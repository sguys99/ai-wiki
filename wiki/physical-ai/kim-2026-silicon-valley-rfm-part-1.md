## 요약

실리콘밸리의 RFM(Robot Foundation Model) 스타트업이 학습 전 과정을 외부에 맡기지 않고 직접 수행하는 이유를 현지 업계 시각에서 정리한 LinkedIn 연재 1편이다. Kyungyul Kim과 Jiyoon Kim이 2026년 4월 22일에 발행했다.

글은 세 가지를 차례로 다룬다. 첫째로 RFM 기업이 PoC를 중심으로 사업을 운영하는 방식, 둘째로 pre-training과 post-training과 데이터 제작과 평가를 전부 내재화하는 배경, 셋째로 하드웨어까지 직접 만드는 Full-stack 전략이 humanoid 분야에서 특히 강한 이유다.

이 저장소의 physical-ai 자료는 대부분 논문과 기술 문서다. 반면 이 글은 같은 VLA 지형을 사업 구조와 투자 생태계 쪽에서 본다. 따라서 논문이 다루지 않는 PoC 관행, 데이터 접근권, 파트너십의 역량 비대칭을 확인할 때 쓸모가 있다.

연재 1편은 기술 개념 설명을 다음 편으로 미루고 산업 구조만 다룬다. VLM과 VLA의 내부 구조 설명은 2편이 이어받는다.

## 배경

글은 모델이 텍스트에서 로봇 동작까지 확장돼 온 흐름을 출발점으로 삼는다. 이 흐름은 네 단계로 나뉘며, 각 단계가 앞 단계를 그대로 물려받아 입력과 출력을 넓히는 구조다.

| 단계 | 처리 대상 | 출력 | 글이 든 사례 |
|---|---|---|---|
| LLM | 텍스트 | 텍스트 | OpenAI GPT, Anthropic Claude, Google Gemini |
| VLM | 텍스트에 이미지와 비디오를 더한 입력 | 텍스트 답변 | 사례를 따로 들지 않는다 |
| VLA | 로봇 카메라 이미지(Vision)와 자연어 명령(Language) | 로봇 동작(Action) | 사례를 따로 들지 않는다 |
| World Action Model | VLA 입력에 world model이 만든 물리 환경을 결합 | 로봇 동작 | 실리콘밸리에서 연구개발이 활발하다고만 서술 |

LLM은 텍스트 중심의 자연어 처리를 주도했고, VLM은 여기에 이미지와 비디오 같은 시각 데이터까지 함께 이해해 답변을 생성하도록 확장한 모델이다. 즉 VLM까지는 출력이 여전히 텍스트다.

VLA는 출력을 텍스트에서 로봇 동작으로 바꾼 단계다. action은 로봇이 실제로 수행하는 동작 명령을 말한다. Physical AI에 대한 주목이 커지면서 로봇이 사람의 의도대로 움직이게 하려는 요구가 늘었고, 그 요구에 맞춰 VLM에 action 출력을 결합한 형태가 VLA다.

world model은 환경의 동역학을 학습해 미래를 예측하는 모델이다. 글은 world model을 다양한 형태의 데이터를 바탕으로 물리 환경을 만들어 내는 모델로 소개하며, VLA와 world model을 통합한 World Action Model 연구가 실리콘밸리에서 활발히 진행되고 있다고 전한다.

## 핵심 개념

이 글은 기술 개념이 아니라 사업 구조를 다루므로, 본문을 읽기 전에 업계 용어 몇 가지를 먼저 풀어 둘 필요가 있다.

RFM은 Robot Foundation Model의 약어다. 글은 VLA 기반의 로봇 지능 모델을 만드는 기업군을 "RFM(VLA) 기업"으로 통칭한다. 따라서 이 페이지에서 RFM은 모델 자체를 가리키기도 하고 그 모델을 만드는 기업군을 가리키기도 한다.

PoC는 Proof of Concept의 약어로, 산업 파트너의 실제 환경에서 모델이 쓸 만한지 검증하는 프로젝트를 말한다. RFM 기업에게 PoC는 검증 절차이면서 동시에 데이터 제작과 레퍼런스 확보의 통로다.

pre-training은 대규모 일반 데이터로 모델의 기반 능력을 먼저 학습하는 단계다. post-training은 그 뒤에 특정 과제와 환경에 맞추는 후속 학습 단계를 가리킨다. 글의 핵심 관찰은 RFM 기업이 이 두 단계를 모두 내부에서 처리한다는 점이다.

"selling the roadmap"과 "fake it till you make it"은 실리콘밸리가 쓰는 마케팅 용어다. 전자는 완성되지 않은 기술 비전을 먼저 판다는 뜻이고, 후자는 일단 해낼 수 있다고 선언한 뒤 뒤따라가며 채워 넣는다는 뜻이다. 글은 두 표현을 같은 패턴을 가리키는 말로 쓴다.

Full-stack 전략은 모델뿐 아니라 로봇 하드웨어, SDK, 학습 파이프라인, 배포 인프라까지 전부 내부화하는 접근을 말한다. humanoid는 사람과 비슷한 형상으로 만든 로봇을 가리키며, 글은 이 분야에서 Full-stack 경향이 특히 강하다고 본다.

## RFM 기업의 작동 방식

### 학습 전 과정의 내재화

실리콘밸리의 RFM 기업은 학습과 관련된 모든 단계를 직접 수행한다. 목적은 모델 성능과 로봇이 수행할 수 있는 action task의 범위를 점진적으로 넓히는 것이다.

| 수행 항목 | 글의 서술 |
|---|---|
| pre-training | 기반 능력을 학습하는 단계를 외부에 맡기지 않고 직접 수행한다 |
| post-training | 특정 과제와 환경에 맞추는 후속 학습도 직접 수행한다 |
| 데이터 제작 | PoC 현장에서 로봇 하드웨어로 직접 취득한다 |
| 평가 | 특정 Task에 맞춘 모델을 자체적으로 검증한다 |

네 항목이 한 기업 안에서 순환하기 때문에, 학습 과정에서 얻은 지식은 그 기업 밖으로 나가지 않는다. 글이 뒤에서 지적하는 역량 비대칭이 여기서 출발한다.

### PoC를 통한 데이터와 레퍼런스 확보

RFM 기업은 학습 내재화와 병행해 다양한 산업 파트너와 PoC를 진행한다. PoC의 형태는 두 가지다. 유상 계약으로 진행하는 경우도 있고, 금전적 대가보다 레퍼런스 확보를 목적으로 진행하는 경우도 있다.

PoC에서 얻은 결과물은 두 방향으로 쓰인다. 하나는 데이터와 실행 경험이고, 다른 하나는 투자 유치용 레퍼런스다. 글은 후자를 투자사로부터 투자금을 유치하기 위한 강력한 증거라고 표현한다.

### 로드맵 선판매 패턴

글은 이런 PoC를 실리콘밸리 특유의 마케팅 패턴과 연결한다. 기업이 먼저 기술 비전을 제시하고, 실제 구현은 그 뒤를 따라가며 간극을 사후적으로 메운다. 현지에서는 이 패턴을 "selling the roadmap" 혹은 "fake it till you make it"이라 부른다.

이 표현은 비난이라기보다 구조 설명에 가깝다. 즉 기술 비전과 실제 구현 사이에 시차가 있다는 사실 자체가 이 시장의 기본 조건이라는 관찰이다.

## 학습 내재화의 세 가지 배경

글은 RFM 기업이 학습을 외부에 열지 않는 이유를 세 가지로 든다.

| 배경 | 내용 | 귀결 |
|---|---|---|
| 노하우 보호 | 로드맵상의 기술 스택과 실제 구현 사이에 격차가 있다. 데이터를 어떤 비율로 섞는지 자체가 노하우다 | 핵심 노하우 유출 우려로 학습 과정을 공개하지 않는다 |
| 오픈소스 기반 개발 | PaliGemma, LLaMA, SigLIP, Qwen, OpenVLA 같은 공개 모델 위에 기술을 쌓는다 | 공개되면 로봇과 자체 제작 데이터만으로 재현될 여지가 있다 |
| 데이터 확보의 구조적 어려움 | RFM 기업은 로봇이 적용될 산업 환경 자체를 보유하지 않는다 | 환경을 제공하는 기업과 PoC를 진행하며 데이터를 직접 만든다 |

### 노하우 보호

첫 번째 배경은 로드맵과 실제 구현 사이의 격차다. 로드맵에 제시된 기술 스택이 곧 현재 구현 상태를 뜻하지는 않는다.

글은 여기에 더해 데이터 배합 비율 자체를 노하우로 지목한다. RFM을 만들고 활용하는 방법, 특히 어떤 데이터를 어떤 비율로 섞어야 하는지가 성능을 가르는 지식이라는 것이다. 따라서 학습 과정을 외부에 열면 이 지식이 함께 나간다.

### 오픈소스 기반 개발

두 번째 배경은 개발 방식이다. 많은 경우 RFM 기업은 공개된 모델 위에 자사 기술을 쌓는 방식으로 개발한다. 글이 직접 거명한 모델은 다음과 같다.

| 모델 | 글에서의 위치 | 저장소 내 대응 자료 |
|---|---|---|
| PaliGemma | RFM 개발의 오픈소스 기반 모델로 거명 | 별도 페이지 없음 |
| LLaMA | 같음 | 별도 페이지 없음 |
| SigLIP | 같음 | 별도 페이지 없음 |
| Qwen | 같음 | 별도 페이지 없음 |
| OpenVLA | 같음 | [[physical-ai/kim-2024-openvla-an-open-source-vision-language-action-model]] |

기반이 공개돼 있다는 사실은 양면적이다. 개발 속도를 높여 주는 동시에, 그 위에 쌓은 부분까지 공개되면 로봇과 로봇으로 직접 제작한 데이터를 갖춘 곳에서 생각보다 쉽게 재현할 수 있는 영역이 된다. 글은 이런 재현 가능성을 비공개의 근거로 본다.

Robot Intelligence 분야는 초기 진입장벽이 높고 학습 데이터와 노하우의 희소성이 크다. 그래서 업계에는 공개 진영과 비공개 진영이 함께 존재하되 다음과 같은 위치 차이가 생긴다.

| 구분 | 특징 | 마케팅 측면의 위치 |
|---|---|---|
| Open 진영 | 모델과 방법을 공개한다 | 희소성을 근거로 삼기 어렵다 |
| Closed 진영 | 학습 과정과 노하우를 공개하지 않는다 | 희소성을 이용한 기술 마케팅에서 유리한 위치를 취할 수 있다 |

### 데이터 확보의 구조적 어려움

세 번째 배경이 글에서 가장 비중이 크다. LLM과 VLA는 데이터를 얻는 경로가 근본적으로 다르다.

| 항목 | LLM | VLA |
|---|---|---|
| 주 데이터 원천 | 웹 서비스 사용자 데이터 | 실제 산업 환경에서 로봇 하드웨어로 취득한 데이터 |
| 수집 방식 | 서비스 운영 과정에서 자연스럽게 축적된다 | 로봇을 실제로 움직여 직접 취득해야 한다 |
| 인터넷 데이터의 역할 | 학습의 주 재료 | 동작 범위의 scale-up까지만 가능하다 |
| 성공과 실패 케이스 | 별도 요건이 아니다 | 의미 있는 로봇 지능이 되려면 반드시 필요하다 |
| 학습 반복 | pre-training과 post-training을 자체적으로 반복할 수 있다 | 환경을 보유한 기업과 PoC를 거쳐야 반복할 수 있다 |

LLM은 웹 서비스를 통해 사용자 데이터를 자연스럽게 모으면서 pre-training과 post-training을 반복할 수 있었다. 반면 VLA는 인터넷의 비디오 데이터로 동작 범위의 scale-up까지는 가능하지만, 실제 산업 환경에서 로봇 하드웨어로 직접 취득한 데이터와 성공 및 실패 케이스가 있어야 비로소 의미 있는 로봇 지능이 된다.

문제는 RFM 기업이 로봇을 적용할 산업 환경을 스스로 갖고 있지 않다는 점이다. 따라서 데이터 확보가 구조적으로 어렵다. 이 제약이 앞서 본 PoC 중심 사업 구조의 직접적인 원인이다.

해법은 환경을 제공할 수 있는 기업과 PoC를 진행하는 것이다. RFM 기업은 그 과정에서 데이터를 직접 제작하고, pre-training과 post-training을 반복해 특정 Task에 맞는 모델을 만들고 검증한다.

### 협업 구조의 역량 비대칭

저자들이 경고하는 지점은 이 협업 구조의 결과다. RFM 기업이 학습 전 과정을 직접 수행하는 형태로 협업이 이루어지면, 학습 노하우는 오직 RFM 기업에만 쌓인다.

| 참여 주체 | 제공하는 것 | 축적되는 것 |
|---|---|---|
| RFM 기업 | 학습 전 과정의 수행 | 학습 노하우, 고도화된 모델, 투자 유치용 레퍼런스 |
| 파트너 기업 | 자사의 데이터와 산업 환경 | 없음. 상대 모델의 고도화에 기여할 뿐 자체 역량은 쌓이지 않는다 |

즉 파트너나 협업 관계의 기업은 자신의 데이터와 환경을 내주면서도 결국 RFM 기업의 모델만 고도화시켜 주는 형태가 되기 쉽다. 글은 이 상태를 파트너 기업의 역량 축적이 불가능한 구조라고 명시한다.

## Full-stack 전략

일부 RFM 기업은 모델에서 멈추지 않고 하드웨어까지 직접 제작한다. 이 경향은 humanoid 분야에서 특히 강하다. 근거는 두 가지이며, 결과적으로 내부화 대상은 하드웨어에서 배포 인프라까지 넓어진다.

| 구성 요소 | 내부화 방식 | 목적 |
|---|---|---|
| 로봇 하드웨어 | 일부 기업이 직접 제작한다 | 검증에 쓸 다양한 로봇을 확보하기 어려운 문제를 해소한다 |
| Controller와 SDK | 자사 모델에 맞춘 전용 Robot H/W SDK를 직접 개발한다 | 로봇마다 다른 Controller 커스터마이징을 표준화할 수 없는 문제에 대응한다 |
| 부품 수급 | 아시아권 조달로 공급망을 다변화하고 모듈 단위로 받아 미국에서 조립한다 | 공급 경로를 다각화한다 |
| 학습 파이프라인과 배포 인프라 | 전부 내부에 둔다 | 연구개발 과정의 예외 변수를 최소화한다 |

### Controller 표준화의 부재

첫 번째 근거는 로봇마다 다른 제어 계층이다. RFM 모델은 다양한 로봇에서 검증돼야 하지만, 다양한 로봇을 확보하는 것부터 쉽지 않다.

확보한 뒤에도 문제가 남는다. 로봇 하드웨어 기업이 제공하는 Controller, 즉 SDK를 RFM 모델에 맞게 커스터마이징해야 하는데, 이 작업을 표준화할 방법이 없다. 따라서 로봇 종류가 늘어날수록 통합 비용이 선형으로 늘어난다.

### 부품 수급과 전용 SDK

두 번째 근거는 공급망이다. RFM 기업은 부품 수급 전략도 다각화한다. 아시아권에서 다수의 부품을 조달하면서 공급망 다변화를 병행하고, 경우에 따라서는 완성도가 높은 모듈 단위 부품을 여러 경로로 받은 뒤 미국에서 조립하는 방식을 택한다.

이렇게 확보한 하드웨어에는 자사 RFM 모델을 최적화할 수 있도록 전용 Robot H/W SDK를 직접 개발해 붙인다. 즉 하드웨어와 모델 사이의 접점을 외부 규격에 맡기지 않고 스스로 정의하는 방식이다.

### 내부화의 목적

Full-stack 접근의 목적은 "RFM 학습에만 집중할 수 있는 환경"을 만드는 것이라고 글은 해석한다. 하드웨어 공급, SDK, 학습 파이프라인, 배포 인프라를 모두 내부화하면 연구개발 과정에서 통제할 수 없는 변수가 줄어든다.

이 전략은 기술적 선택인 동시에 사업적 선택이다. 예외 변수를 줄이는 것이 곧 RFM 중심의 비즈니스 모델을 견고하게 유지하는 수단이기 때문이다.

## 정보 비대칭이라는 결론

글은 RFM 분야를 기술 스택, 학습 노하우, 하드웨어, 데이터, 배포 인프라가 모두 맞물려 움직이는 복합 영역으로 규정한다. 구성 요소가 서로 얽혀 있어서 기술의 실체와 마케팅으로 제시된 비전 사이의 간극을 외부에서 명확히 판별하기 쉽지 않다.

이 어려움은 판단하는 주체마다 다른 형태로 나타난다.

| 주체 | 겪는 어려움 | 글이 제시하는 대응 |
|---|---|---|
| AI 연구개발 실무자 | 각 Physical AI 기업의 기술적 본질과 성숙도를 정확히 가늠하기 어려운 영역이 존재한다 | 기술의 실체를 구조적으로 이해하는 접근 |
| VC 투자 생태계 | 기술과 시장과 사업성을 종합해 판단해야 하므로 정보 비대칭이 상대적으로 크게 작용한다 | 같음 |
| Enterprise | Robot Intelligence 영역에서 R&D와 오퍼링이 가능한지 판단해야 한다 | 다음 연재부터 이어지는 기술 개념 설명 |

따라서 이 분야에 대한 전략적 판단에는 기술의 실체를 구조적으로 이해하려는 접근이 필수적이라는 것이 글의 결론이다. 연재가 2편부터 기술 개념 설명으로 넘어가는 이유도 여기에 있다.

## 한계

이 글을 인용할 때 유의할 점은 다음과 같다.

- 기업 실명과 구체적 사례와 수치가 없다. 관찰의 근거는 저자들의 현지 경험이며, 정량 데이터나 벤치마크는 제시되지 않는다.
- "selling the roadmap" 같은 진단은 업계 전반의 경향을 서술한 것이라 개별 기업 평가에 그대로 옮겨 쓰기 어렵다.
- 연재 1편이라 VLM과 VLA의 기술 개념 설명이 빠져 있다. 이 페이지만으로는 VLA 내부 구조를 알 수 없다.
- 오픈소스 기반 모델 다섯 개를 거명하지만 각각이 어떤 역할로 쓰이는지는 구분하지 않는다.
- 시각 자료가 없는 기사다. 본문 이미지는 "PHYSICAL AI" 문구가 들어간 커버 아트 하나뿐이고 기술 도식이 아니다. 따라서 임베드한 그림이 없다.

## 핵심 용어

| 용어 | 뜻 |
|---|---|
| RFM (Robot Foundation Model) | 로봇 제어를 위한 foundation model. 글은 VLA 기반 로봇 지능 모델을 만드는 기업군을 "RFM(VLA) 기업"으로 통칭한다 |
| World Action Model | VLA와 world model을 통합하는 연구 방향. 글 기준으로 실리콘밸리에서 연구개발이 활발하다 |
| PoC (Proof of Concept) | 산업 파트너 환경에서 진행하는 검증 프로젝트. RFM 기업에게는 데이터 제작과 레퍼런스 확보의 통로다 |
| selling the roadmap | 완성되지 않은 기술 비전을 먼저 판매하고 구현이 뒤따라가는 패턴. "fake it till you make it"과 같은 뜻으로 쓰였다 |
| Full-stack 전략 | 모델뿐 아니라 로봇 하드웨어, SDK, 학습 파이프라인, 배포 인프라까지 내부화하는 접근 |
| Robot H/W SDK | 자사 RFM 모델에 맞춰 직접 개발하는 로봇 하드웨어 제어 계층. 표준화되지 않은 외부 Controller 문제에 대한 대응이다 |
