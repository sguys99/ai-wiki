# 그래프 페이지 화면 구성

작성일 2026-11-17. `docs/graph-design-plan.md` Phase 2 첫 항목 "선택한 방향의 화면 구성 확정" 의 산출물이다. 통합 시안 F `docs/graph-mockups/f-atlas-orbit.html` 을 실제 사이트 `/graph/` 페이지로 옮길 때의 영역, 배치, 상태별 노출, 층, 토큰, 접근성을 정한다. 인터랙션(마우스, 터치, 키보드 세부)은 Phase 2 두 번째 항목, 추가 기능 네 가지의 내용은 여섯 번째 항목이 맡는다. 이 문서는 자리만 정한다.

시각 규칙(색, 스프라이트, 모션)은 `docs/graph-mockups/design-direction.md` 가 정본이다. 이 문서는 그 규칙을 어디에 놓을지만 다룬다.

## 1. 출발점

시안 F와 현재 사이트의 차이 가운데 화면 구성에 영향을 주는 것만 적는다.

| 항목 | 시안 F | 현재 사이트 `/graph/` | 이 문서의 결정 |
|---|---|---|---|
| 상단 | 자체 바 `.mk-bar` 48px (`--bar-h`), 제목과 통계, 테마 버튼 | 공용 헤더 `.site-header` sticky, `--z-header: 100`, 높이 약 `--header-h: 3.6rem` | 자체 바를 없애고 공용 헤더를 쓴다 (2.1절) |
| 무대 | `position: fixed; inset: var(--bar-h) 0 0` | `.graph-canvas-wrap` 높이 `clamp(22rem, 60vh, 40rem)`, 문서 흐름 안 | 뷰포트 전체를 채우고 공용 헤더가 그 위에 유리판으로 겹친다 (2.2절) |
| 텍스트 목록 | 스크립트나 CDN 실패 때만 `.f-fallback` 이 무대를 대신한다 | 캔버스 아래 늘 보이는 카테고리별 목록 | "목록 보기" 판으로 전환한다 (2.3절) |
| 필터 | 범례가 카테고리 필터를 겸한다. 유형, 태그 필터 없음 | 카테고리 칩 줄 `.graph-filter` | 카테고리는 범례, 유형과 태그는 필터 팝오버 (4절) |
| 줌 | 휠과 핀치, 우하단 "화면 맞춤" 버튼 | 없음 | 우하단 도구 묶음에 확대, 축소, 맞춤 (5.6절) |
| 푸터 | 없음 | 공용 `.site-footer` | 지도 판에서는 숨기고 목록 판에서는 보인다 |
| 토큰 | 파일 안 "F 토큰" 블록이 `--bg`, `--text`, `--signal` 등을 전역에서 덮어쓴다 | `@layer tokens` 의 사이트 값 | 기존 이름 덮어쓰기는 `main.graph` 범위로 가둔다 (8절) |

## 2. 페이지 골격

### 2.1 사이트 헤더와의 관계

공용 헤더(`layout()` 의 `header()`)를 그대로 쓴다. 그래프 페이지만의 제목 바는 두지 않는다. 시안 F 바의 세 요소는 이렇게 옮긴다.

| 시안 F 바 요소 | 사이트에서 |
|---|---|
| 제목 "시안 F 성도와 궤도" | `<h1 class="graph-title">그래프</h1>`. 목록 판에서는 보이고 지도 판에서는 시각적으로만 숨긴다 (`.sr-only`, 새로 추가) |
| 통계 "페이지 344개, 연결 2,600개" | 지도 판은 범례 머리 줄, 목록 판은 제목 아래 `.graph-stat` |
| 테마 버튼 | 공용 헤더의 `.theme-toggle` 을 쓴다. 테마가 바뀌면 탐색기가 토큰을 다시 읽는다 (`data-theme` 관찰) |

헤더는 `position: sticky; z-index: var(--z-header)` 그대로다. 무대는 뷰포트 맨 위에서 시작하고, 지도 판에서만 헤더 배경을 그래프 유리(`--graph-glass`, blur 18px)로 바꿔 무대 위에 겹친다. 별먼지가 헤더 뒤로 비친다 (11절 M1 결정).

모바일(≤560px) 햄버거 메뉴 `.site-menu` 는 헤더 안에서 `position: absolute` 로 열린다. 헤더가 `--z-header: 100` 이고 무대는 아래 2.2절대로 `isolation: isolate` 로 쌓임 맥락을 가두므로 메뉴는 늘 무대 위에 뜬다. 검색 모달(`--z-modal: 1000`)도 같다.

### 2.2 무대 높이

`layout()` 은 `<body>` 에 클래스를 붙일 수 없다. 대신 `:has()` 로 지도 판일 때만 body와 헤더를 바꾼다. 무대를 담은 `main` 을 `position: fixed; inset: 0` 으로 뷰포트 전체에 깔고, 헤더는 `z-index` 로 그 위에 둔다 (11절 M1).

```css
body:has(> main.graph[data-view='map']) { overflow: hidden; }   /* 지도 판은 문서 스크롤이 없다 */
body:has(> main.graph[data-view='map']) .site-header {           /* 무대 위 유리판 */
  background: var(--graph-glass);
  -webkit-backdrop-filter: blur(18px);
  backdrop-filter: blur(18px);
}
main.graph[data-view='map'] ~ .site-footer { display: none; }
main.graph[data-view='map'] { position: fixed; inset: 0; }
.graph-stage { position: absolute; inset: 0; overflow: hidden; isolation: isolate; touch-action: none; }
```

- 헤더는 `position: sticky; top: 0; z-index: var(--z-header)` 라 문서 맨 위, 곧 뷰포트 맨 위에 붙고, z-index가 없는 고정 `main` 보다 위에 그려진다. 무대 크기는 헤더 높이와 무관하게 뷰포트와 같다.
- 무대 위쪽 크롬은 헤더 밑에서 시작해야 한다. 탐색기가 `.site-header` 의 `offsetHeight` 를 `ResizeObserver` 로 읽어 `main.graph` 에 런타임 변수 `--graph-header-h` 로 넣는다. 스크립트가 값을 넣기 전의 대체값은 사이트 토큰 `--header-h` (3.6rem) 다. 위 여백 `--graph-top: calc(var(--graph-header-h, var(--header-h)) + var(--graph-inset))` 이 명령 줄과 상세 패널의 `top` 이다 (8.2절).
- 헤더 상자는 크롬 장애물 목록(3절)에도 들어간다. 캔버스 라벨이 헤더 유리 밑에 깔려 읽히지 않는 일을 막는다.
- `.skip-link` 는 `position: absolute` 라 배치에 영향이 없다. 스크립트가 나중에 붙인 `<script>` 는 렌더 상자가 없다.

### 2.3 두 판: 지도와 목록

`main.graph` 는 `data-view` 로 두 판을 오간다.

| 판 | 서버가 내보내는 기본값 | 보이는 것 |
|---|---|---|
| `list` | 기본 (스크립트 없음, `graph.json` 실패, 런타임 라이브러리를 쓴다면 그 로드 실패. `05-libraries.md` 의 빌드 배치안이면 이 경우는 없다) | 제목, 안내문, 통계, 카테고리별 목록 (현재 `.graph-list` 마크업 유지), 푸터 |
| `map` | 탐색기가 데이터와 배치를 마치면 바꾼다 | 무대 전체 |

- 스크립트가 실패하면 아무것도 바꾸지 않으므로 목록 판이 그대로 남는다. 시안 F의 `.f-fallback` 과 `<noscript>` 는 필요 없다. 3절 제약 "스크립트가 실패해도 텍스트 목록으로 모든 페이지에 간다" 를 서버 렌더만으로 지킨다.
- 지도 판에서 목록 판으로: 도구 묶음의 "목록 보기" 버튼. 목록 판에서 지도 판으로: 목록 머리의 "그래프로 보기" 버튼 (서버는 `hidden` 으로 내보내고 탐색기가 보일 때 연다).
- 판 상태는 hash `#list` 에 둔다. 딥링크 `#node=` 와 함께 쓰는 규칙은 인터랙션 명세가 정한다.
- 지도 판에서 목록 판 마크업은 `hidden` 으로 숨긴다. 목록이 무대 아래 스크롤로 이어지는 안은 11절 M2에서 기각 사유와 함께 적는다.

### 2.4 마크업 뼈대

클래스 접두는 시안의 `mk-`, `f-` 대신 `graph-` 로 통일한다. 현재 `.graph-*` 규칙은 Phase 4에서 통째로 다시 쓰므로 이름이 겹쳐도 된다.

```html
<main id="main" class="graph" data-view="list">
  <h1 class="graph-title" id="graph-title">그래프</h1>
  <a class="graph-skip" href="#list">페이지 목록으로 건너뛰기</a>   <!-- 지도 판에서만 보임 -->

  <section class="graph-stage" aria-labelledby="graph-title" hidden>
    <canvas class="graph-canvas" tabindex="0" aria-label="…" aria-describedby="graph-help"></canvas>
    <p class="sr-only" id="graph-help">…조작 설명 (02 9.3절)…</p>
    <p class="sr-only" id="graph-live" aria-live="polite"></p>

    <div class="graph-cmd graph-float is-tl">                       <!-- 명령 줄 -->
      <search class="graph-search">                                  <!-- 검색 -->
        <label class="sr-only" for="graph-q">페이지 검색</label>
        <input id="graph-q" type="search" role="combobox" …>
        <ul class="graph-results" id="graph-results" role="listbox"></ul>
      </search>
      <button class="graph-filter-btn" aria-expanded="false" aria-controls="graph-filters">필터 <span class="graph-badge"></span></button>
      <!-- Phase 5 예약: 학습 경로 버튼 (7절) -->
    </div>
    <div class="graph-row graph-float" id="graph-active-filters" hidden></div>   <!-- 조감: 적용된 필터 칩 -->
    <nav class="graph-row graph-float graph-trail" aria-label="지나온 페이지" hidden>…</nav>  <!-- 궤도: 경로 -->

    <div class="graph-filters" id="graph-filters" role="group" aria-label="유형과 태그 필터" hidden>…</div>

    <aside class="graph-panel" aria-labelledby="graph-p-title" hidden inert>…</aside>

    <div class="graph-dock graph-float is-bl">                        <!-- 범례와 안내 -->
      <div class="graph-legend" role="group" aria-label="카테고리 필터">
        <p class="graph-legend-stat">페이지 344개, 연결 2,600개</p>
        <button class="graph-legend-item" data-cat="physical-ai" aria-pressed="false">…</button> ×8
        <!-- Phase 5 예약: 최근 추가 표식 줄, 약한 연결 링크 (7절) -->
      </div>
      <p class="graph-hint is-atlas">…</p><p class="graph-hint is-orbit">…</p>
    </div>

    <div class="graph-tools graph-float is-br" role="toolbar" aria-label="보기 도구">
      <button aria-label="확대">+</button><button aria-label="축소">−</button>
      <button>화면 맞춤</button><button>목록 보기</button>
    </div>
    <!-- Phase 5 예약: 학습 경로 단계 막대 .graph-pathbar (7절) -->

    <div class="graph-tip" aria-hidden="true" hidden></div>
  </section>

  <section class="graph-list" id="graph-list" aria-labelledby="graph-list-h">
    <header class="graph-list-head">…안내문, 통계, [그래프로 보기]…</header>
    …카테고리 section 들 (현재 마크업)…
    <!-- Phase 5 예약: 약한 연결 리포트 section#weak-links (7절) -->
  </section>
</main>
```

- 범례 항목은 시안 F의 `li[aria-pressed]` 대신 진짜 `<button aria-pressed>` 로 만든다. `li` 에 `role` 없이 `aria-pressed` 를 단 시안 구조는 접근성 트리에서 버튼으로 읽히지 않을 수 있다.
- `<search>` 요소를 지원하지 않는 브라우저에서는 알 수 없는 요소로 남을 뿐이라 `role="search"` 를 함께 단다.
- DOM 순서가 곧 Tab 순서다 (9.2절). 시각 위치는 CSS 로만 정한다.

## 4. 필터 배치

| 축 | 개수 (스냅샷 344노드) | 자리 | 형태 |
|---|---|---|---|
| 카테고리 | 8 | 범례 | 시안 F 그대로. 견본을 누르면 켜고 끈다. 하나라도 켜지면 범례 아래 "필터 해제" |
| 유형 | 6: article 114, paper 110, repo 93, overview 14, video 10, report 3 | 필터 팝오버 첫 절 | 토글 칩 6개, 개수 표시. 두 줄에 들어간다 |
| 태그 | 고유 1,023개, 5회 이상 88개 | 필터 팝오버 둘째 절 | 자동완성 입력 + 자주 쓰는 태그 추천 칩 8개 + 고른 태그는 지울 수 있는 칩 |

- 태그가 1,023개라 칩 목록으로 펼칠 수 없다. 입력으로 찾고, 입력이 비었을 때는 빈도 상위 태그를 추천한다. 카테고리와 같은 값인 태그(`physical-ai` 152회)는 추천에서 뺀다.
- 필터 버튼에는 켜진 유형과 태그 수를 배지로 단다. 카테고리는 범례에 이미 보이므로 배지에 넣지 않는다.
- 조감 상태에서 유형이나 태그가 켜져 있으면 명령 줄 아래 `#graph-active-filters` 에 "유형 paper ×", "태그 vla ×" 칩을 보인다. 궤도 상태에서는 그 줄을 경로 줄이 쓰므로 칩 줄을 숨기고 배지만 남긴다.
- 필터 사이의 결합 규칙(유형 안은 OR, 축 사이는 AND 등)과 걸러진 노드를 흐리게 할지 지울지는 인터랙션 명세가 정한다.
- 팝오버 맨 아래에 "모두 해제" 버튼을 둔다. 범례의 "필터 해제" 는 카테고리만 푼다.

## 5. 브레이크포인트별 배치

### 5.1 구간

| 이름 | 조건 | 근거 |
|---|---|---|
| 데스크톱 | `min-width: 1200px` | 패널이 오른쪽에 있어도 궤도가 가로 700px 이상 남는다 |
| 태블릿 | `641px ~ 1199px` | 시안 F의 640 경계를 그대로 쓴다 (768px 두 테마 검증 통과) |
| 모바일 | `max-width: 640px` | 시안 F `mqMobile` 과 같다. 하단 시트, 견본 한 줄 범례 |
| 휴대폰 가로 | `max-height: 480px` (폭 무관) | 시안 F와 같다. 641px 이상이면 옆 패널을 쓴다 |

시안 F에서 범례를 견본 한 줄로 접고 안내를 숨긴 것은 그대로 둔다. 10절 잔여 사항 두 가지는 다음처럼 푼다.

```
│ [✦ 전체 보기] / ● π0                        │● Physical AI  ×││ 머리 압축
│ ●                                          │π0: A Vision-… ↗││ 제목 2줄 + 열기 아이콘

└──────────────────────────────────────────────────────────────┘
  ↑ 범례를 왼쪽 세로 한 줄로
```

**잔여 1. 범례가 외곽 궤도 아래쪽에 닿는다.** 가로 화면은 세로 여유가 330px 남짓이라 아래쪽 범례 줄(26px + 여백)이 궤도 사용 영역을 깎는다. 범례를 왼쪽 가장자리의 세로 한 줄로 옮긴다.

- `@media (max-height: 480px)`: `.graph-dock` 을 `top: calc(var(--graph-top) + 38 + 8 + 30 + 8); bottom: auto; left: inset` (헤더 44px이면 뷰포트 위에서 144px), 범례 `flex-direction: column`. 견본 8개 × 26px + 간격 2px × 7 + 위아래 여백 12px = 234px. 남은 높이 안에 든다.
- 궤도 카메라 왼쪽 여유를 `inset + 범례 폭(26 + 16) + 8` = 66px로 두고 아래 여유는 20px로 줄인다. 세로로 비는 공간이 늘어 외곽 궤도가 범례에 닿을 일이 없다.
- 누른 견본의 이름 펼침은 세로 줄에서 오른쪽으로 튀어나오는 알약으로 그린다 (`position: absolute; left: 100%`). 줄 폭은 바뀌지 않는다.

**잔여 2. 옆 패널의 이웃 목록 높이가 좁다.** 패널 머리와 바닥이 고정 높이를 먹는다. 가로 화면에서는 이렇게 줄인다.

| 부분 | 시안 F | 가로 화면 |
|---|---|---|
| 머리 여백 | `16px 16px 12px` | `10px 12px 8px` |
| 제목 | 19.2px, 줄 제한 없음 | `--text-base`, 두 줄 말줄임 |
| 메타 줄 (연도, 유형, 연결) | 제목 아래 따로 한 줄 | 카테고리 줄 오른쪽으로 합친다 |
| 태그 | 본문 맨 위 | 본문 맨 아래로 내린다 |
| 바닥 "페이지 열기" | 높이 36px 버튼 줄, 위아래 여백 12px | 바닥 줄을 없애고 머리 오른쪽 위 32px 아이콘 링크(↗, `aria-label="페이지 열기"`)로 옮긴다 |

어림셈으로 머리와 바닥이 차지하던 약 185px가 약 75px로 줄어 이웃 목록이 330px 높이 중 약 250px를 쓴다. 정확한 값은 Phase 6에서 iPhone 13과 Pixel 7 가로 설정으로 잰다.

**사이트 헤더 축소.** 헤더가 무대 위에 겹쳐도 그 아래로는 크롬과 궤도를 둘 수 없으므로, 가로 화면에서는 헤더가 쓸 수 있는 높이의 15%를 먹는다. `@media (max-height: 480px)` 에서 그래프 페이지 헤더만 위아래 여백을 `var(--space-1)` 로 줄여 약 44px로 만든다 (`body:has(> main.graph[data-view='map']) .site-header`, 2.2절 유리판 규칙과 같은 선택자). `--graph-header-h` 는 줄어든 높이를 그대로 읽는다.

### 8.1 z-index 층

무대가 `isolation: isolate` 라 아래 값은 무대 안에서만 비교된다. 사이트의 `--z-header: 100`, `--z-modal: 1000` 과 섞이지 않는다. 무대 바깥에서는 고정 `main.graph` (z-index 없음) 위에 공용 헤더(`--z-header: 100`, 유리판), 그 위에 검색 모달(`--z-modal`)이 놓인다. 헤더 안의 햄버거 메뉴도 헤더 층에 속하므로 무대의 어떤 층보다 위다 (2.1절).

### 9.2 초점 순서

DOM 순서를 아래로 고정한다. 시각 위치가 달라도(범례가 왼쪽 아래) Tab은 이 순서를 따른다.

1. 공용 건너뛰기 링크 "본문으로 건너뛰기"
2. 공용 헤더
3. `.graph-skip` "페이지 목록으로 건너뛰기" (초점을 받을 때만 보인다. 누르면 `#list` 로 판을 바꾸고 목록 첫 링크에 초점)
4. 검색 입력 → 필터 버튼 → (예약) 학습 경로 버튼
5. 필터 팝오버 (열려 있을 때만)
6. 필터 칩 줄 또는 경로 줄 ("전체 보기", 경로 버튼들)
7. 캔버스 (`tabindex="0"`, 방향키 조작)
8. 상세 패널 (궤도에서만): 닫기 → 이웃 목록 (Tab 한 번으로 들어가고 나온다. 안에서는 `↑` `↓`, roving tabindex, 02 6.6절) → "모두 보이기" → 페이지 열기 → 이웃 보기 토글
9. 범례 견본 8개 → 필터 해제
10. 도구 묶음

캔버스 다음에 패널이 오므로 궤도에서 Enter로 중심을 정한 뒤 Tab 한 번에 패널로 들어간다. 시안 F는 패널이 범례와 도구 뒤에 있었다.

헤더가 무대 위에 겹쳐도 DOM에서는 `main` 앞에 있으므로 순서는 위와 같다. 헤더 요소에 초점이 있을 때 초점 테가 별먼지 위 유리판에서도 보이는지 Phase 6에서 확인한다.

### 9.3 숨은 영역 처리

시안 F는 숨긴 패널을 `transform` 으로 밀고 `visibility: hidden` 을 늦게 걸어 Tab에서 뺐다. 사이트에서는 `inert` 를 함께 쓴다.

| 영역 | 숨김 방식 |
|---|---|
| 상세 패널 (조감) | `hidden` + `inert`. CSS는 시안처럼 `[hidden]` 에 `display: flex` 를 다시 주고 `transform` 과 `visibility` 지연으로 닫는 전환을 보인다. `inert` 는 열 때 먼저 지우고 닫을 때 바로 건다 |
| 모바일 시트 접힘의 본문 | `.graph-panel-body` 에 `inert` (시안은 `display: none`). 시트 높이 전환을 남기려는 것이다 |
| 필터 팝오버 닫힘 | `hidden` |
| 모바일 필터 시트 열림 동안 상세 패널 | `inert` |
| 지도 판의 목록 | `hidden` |
| 목록 판의 무대 | `hidden` |
| 궤도의 도구 묶음, 조감의 경로 줄 | `hidden` (시안은 CSS `display: none`. 상태를 속성으로 두어 장애물 목록과 접근성 트리가 같은 값을 본다) |
| 툴팁 | `aria-hidden="true"`. 같은 정보는 라이브 영역과 패널이 준다 |

`inert` 를 지원하지 않는 브라우저(Safari 15.4 이전, Firefox 112 이전)에서는 시안 F의 `visibility: hidden` 규칙이 같은 역할을 하므로 두 규칙을 모두 둔다.

### 9.4 그 밖

- 필터 팝오버는 비모달이다. Esc로 닫고 초점을 필터 버튼으로 돌린다. 모바일 필터 시트도 같다 (캔버스 결과를 보며 고르게 하려는 것이다).
- 모든 조작 요소는 `--signal` 2px 초점 테를 보인다. 캔버스는 시안 F처럼 `outline-offset: -2px`.
- 터치 대상은 최소 26px(범례 견본, 시안 검증값), 그 밖의 버튼은 32px 이상이다.

## 10. 구현 메모

- 탐색기의 크롬 기하 상수(시안 F `orbitCam()` 의 112, 104, 58, 20과 `atlasRect()` 의 60, 56)는 숫자로 박지 말고 매 계산 때 장애물 상자와 토큰에서 구한다. 위쪽 값에는 헤더 높이(`--graph-header-h`)가 더해진다. 7절 예약 자리가 늘어나도 다시 손댈 곳이 생기지 않는다.
- 모바일 판정은 시안의 `W <= 640` 과 `matchMedia('(max-width: 640px)')` 를 하나로 합친다. 휴대폰 가로 판정 `matchMedia('(max-height: 480px)')` 를 새로 둔다.
- 사이트 CSS에서 그래프 절은 지금처럼 `@layer components` 안 한 블록으로 둔다. 시안 F의 `:root:not([data-theme='light'])` 구분은 사이트의 `:root[data-theme='light']` 덮어쓰기 방식으로 뒤집는다 (기본 dark).

## 12. 개선 제안

시안 F보다 더 세련되고 모던하게 보이게 하는 구체 안이다. 모두 이 문서의 영역 구성 안에서 할 수 있고, 하나씩 따로 채택할 수 있다.

이 절은 확정된 설계가 아니다. Phase 4, 5 구현 때 비용이 적은 것부터 골라 넣는다.

| 번호 | 제안 | 무엇이 나아지나 | 비용 |
|---|---|---|---|
| I1 | **명령 줄을 하나의 유리 캡슐로 묶는다.** 검색 입력, 필터 버튼, 학습 경로 버튼을 반경 12px 캡슐 하나 안에 1px 구분선으로 나누어 넣는다. 오른쪽 끝에 `/` 키 표시를 `kbd` 로 둔다 | 지금은 입력과 버튼이 따로 떠 있어 크롬이 흩어져 보인다. 한 덩어리가 되면 화면 위 크롬이 "도구 하나" 로 읽힌다 | CSS만 |
| I2 | **유리판 높이를 두 단계로 정리한다.** 띄운 컨트롤(명령 줄, 범례, 도구)은 그림자 없이 위 가장자리 빛만, 패널과 팝오버만 `--graph-float-shadow` 를 쓴다 | 지금은 범례에도 그림자가 있어 모든 판이 같은 높이로 떠 보인다. 높이 차가 생기면 패널이 주인공이 된다 | CSS만 |
| I3 | **패널 이웃 목록의 묶음 제목을 sticky로 둔다.** `.nb-group` 을 `position: sticky; top: 0` 에 유리 배경으로 | 63이웃, 118이웃 목록을 스크롤해도 지금 어느 카테고리인지 보인다 | CSS만 |
| I4 | **연결 방향 화살표(→ ← ↔)를 작은 방향 막대로 바꾼다.** 패널 메타 줄에 "들어옴 n, 나감 m" 을 두 색 비율 막대 하나로 보이고, 목록의 화살표는 `aria-label` 만 남긴 6px 점 두 개로 줄인다 | 글자 화살표가 목록 왼쪽 열을 어지럽힌다. 숫자 정보는 그대로다 | 마크업 소폭 |
| I5 | **모바일 시트에 끌기 손잡이와 두 멈춤점(접힘, 42vh)을 준다.** 손잡이는 36 × 4px 둥근 막대, 놓으면 가까운 멈춤점으로 `--ease-out` 240ms | "이웃 63개" 버튼만으로 펼치던 동작에 손 제스처가 더해진다. 휴대폰 앱의 지도 시트와 같은 감각 | JS 소량. reduced-motion 에서는 즉시 |
| I6 | **조작 안내를 늘 띄우지 않는다.** 범례 머리에 `?` 버튼을 두고 누르거나 처음 방문했을 때만(브라우저 저장소에 한 번 기록) 안내 카드를 연다 | 데스크톱 좌하단의 11px 안내가 범례 옆에 늘 남아 있던 잡음이 사라진다. 태블릿에서 숨긴 안내도 되찾는다 | JS 소량 |
| I7 | **판 전환에 View Transitions API를 쓴다.** 지도 판과 목록 판 전환 때 `document.startViewTransition` 으로 교차 페이드, 지원하지 않으면 즉시 바꾼다 | 목록 판이 다른 페이지처럼 툭 바뀌지 않는다 | JS 몇 줄. 점진적 향상 |
| I8 | **검색 결과 행을 두 줄로 만든다.** 첫 줄 제목, 둘째 줄 카테고리 견본과 유형, 연도를 `--text-2xs` muted로. 일치 글자는 시안처럼 카테고리 색 | 비슷한 제목(RT-1, RT-2, "모두의 로보틱스" 연재)이 많아 한 줄로는 고르기 어렵다 | 마크업 소폭 |
| I9 | **빈 상태 문구를 행동으로 쓴다.** 검색 결과 없음: "일치하는 제목이 없다. 필터가 켜져 있으면 해제한다" + 해제 버튼. 필터로 노드가 0개: 범례 아래에 같은 형식 | 막다른 화면이 없어진다 | 문구와 버튼 하나 |
| I10 | **헤더 유리 연결 (M1 b안).** 헤더 아래 1px 경계를 없애고 무대 위쪽 24px에 배경색으로 녹는 그라데이션만 둔다 | 페이지 전체가 하나의 성도 화면으로 읽힌다 | CSS만. M1이 (b)로 확정돼 전제가 갖춰졌다 |

넣지 않기를 권하는 것: 미니맵(344노드 화면에서 "화면 맞춤" 과 역할이 겹친다), 상단의 큰 통계 숫자 타일(`design-direction.md` 1절 "피할 것"), 패널 탭 구조(이웃 목록 하나로 충분하다).

## 13. 확인하지 못한 것

- 사이트 헤더의 실제 높이. `--header-h: 3.6rem` 은 주석상 "대략" 값이다. 2.2절은 런타임에 잰 `--graph-header-h` 를 쓰고 이 값은 스크립트 전 대체값으로만 쓰지만, 5.2절과 5.4절의 "헤더 약 58px" 환산과 5.5절 가로 화면 44px 축소는 실측이 필요하다.
- 헤더 유리판(`--graph-glass`, blur 18px) 위 헤더 글자와 초점 테의 대비. 별먼지와 성운 빛이 뒤로 비치는 상태에서 재지 않았다.
- 5.5절 휴대폰 가로 패널의 높이 어림셈(이웃 목록 약 250px). 실제 렌더로 재지 않았다.
- `<search>` 요소, `inert`, `:has()`, `dvh` 의 대상 브라우저 지원은 일반 지식으로 판단했고 이 저장소에서 확인하지 않았다. Phase 6 교차 엔진 검증 항목에 넣는다.
- 덮어쓴 `--cat-*` 값을 wiki 페이지 배경(사이트 `--bg` `#0b0e14`, `#f7f8fa`) 위에서 쓸 때의 대비. 시안 F 대비표는 그래프 배경(`#070b14`, `#f3f4f8`) 기준이다.
