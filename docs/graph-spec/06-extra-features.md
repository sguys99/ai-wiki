# 06. 추가 기능의 화면 위치와 데이터 출처

작성일 2026-11-17. `docs/graph-design-plan.md` Phase 2 여섯째 항목 "추가 기능 네 가지의 화면 위치와 데이터 출처 확정" 의 산출물이다. 대상은 계획서 6절과 Phase 5의 네 기능(최근 추가 강조, 학습 경로 겹쳐 보기, 약한 연결 리포트, 페이지별 미니 그래프)과 7절 Q8의 3D 실험 페이지 `/graph/3d/` 다.

자리 이름과 토큰은 `01-layout.md` 7절 예약 자리와 8절 토큰을 그대로 쓴다. 배치 규칙은 `04-layout-algorithm.md`, 라이브러리는 `05-libraries.md` 를 따른다. `graph.json` 스키마 확정은 03 항목의 몫이고, 이 문서는 9절에 요구 필드만 넘긴다. 인터랙션 세부(키 배정, hash 문법 전체)는 02 항목이 정한다.

측정 스크립트는 스크래치 디렉토리의 `measure06.mjs` 다. 사이트 빌드 모듈(`loadContent`, `addedDates`, `buildGraph`)을 그대로 불러 현재 작업 트리(2026-11-17)로 계산했다. 344노드, 2,600엣지로 계획서 2절 값과 같다.

## 2. 최근 추가 강조

### 2.1 기준

- 최근 = 추가일이 빌드 시각에서 14일 이내 (`RECENT_DAYS`). 홈 카드의 NEW 뱃지와 같은 정의다. 지금 13개.
- 14일 안이 6개(`RECENT_COUNT`) 미만이면 추가일 최신순 6개로 채운다. 1.2절처럼 공백이 12일 이상인 기간이 있어, 바닥이 없으면 스위치를 켜도 아무것도 보이지 않는 날이 생긴다. 채운 경우 범례 설명은 "최근 14일" 대신 "가장 최근 6개" 로 바꾼다.
- 기준 시각은 빌드 시각이다. 홈 NEW 뱃지도 빌드에서 계산하므로 두 화면이 같은 집합을 본다. 배포는 `wiki/**` 등 변경이 있을 때만 돌기 때문에 오래 배포가 없으면 "최근" 이 낡는다. 홈과 같은 한계로 받아들인다.
- 최근 N일 대 최근 N개: 날짜 기준이 홈과 일치하고 "지식이 어디서 자라는지" 라는 기능 목적(시간)에 맞다. 개수 기준은 공백 대비 바닥으로만 쓴다.

### 2.2 화면

| 상태 | 표시 |
|---|---|
| 조감 | 최근 노드마다 구 오른쪽 위 45° 방향 `r + 2.5px` 에 지름 4px 위성 점 하나. dark는 흰색 0.95, light는 `--text`. 위성 점은 overviews 바깥 고리(r + 2.6px 원), etc 유리 고리와 모양이 달라 색 없이도 구분된다. 최근 노드는 라벨 강제 후보(04 5.1절, `+1e4` 단계)에 넣어 줌 배율과 무관하게 제목 후보가 된다. 다른 노드는 흐리게 하지 않는다 (필터와 섞이지 않게 "표시" 만 한다) |
| 궤도 | 궤도 노드 가운데 최근 노드에 같은 위성 점. 상세 패널 메타 줄 끝에 "새로 추가 11월 16일" (`--text-2xs`, `--signal`) |
| 모바일 | 같은 그림. 위성 점은 `r × √k` 가 작아도 4px 고정 (k 0.37 첫 화면에서도 보인다) |
| 범례 | 스위치가 켜져 있을 때만 범례 맨 아래 한 줄 `.graph-legend-recent`: "◦ 최근 14일 추가 13개". 모바일 견본 한 줄 범례에서는 줄을 더하지 않고 필터 버튼 배지가 켜짐을 알린다 |
| 첫 등장 | 스위치를 켤 때 위성 점이 220ms 동안 0에서 커진다 (`--ease-out`). 반복하는 맥박은 두지 않는다 (`design-direction.md` 1절 "숨쉬는 글로우" 금지). reduced-motion은 즉시 |

```
필터 팝오버 (데스크톱 320px)              범례 (켜졌을 때)
┌──────────────────────────────┐         ┌ 페이지 344개, 연결 2,600개 ┐
│ 유형                          │         │ ● Physical AI         149 │
│ [paper 110][article 114] …   │         │ …                         │
│ 태그                          │         │ ● etc                   5 │
│ [⌕ 태그 찾기        ]          │         │ ◦ 최근 14일 추가 13개      │ ← .graph-legend-recent
│ [vla][world-model] …          │         │ 연결이 적은 페이지 36개 →  │ ← 3절
│ 강조                          │         └───────────────────────────┘
│ ( ●) 최근 추가 표시   13       │ ← #graph-recent (role="switch")
│ [ 모두 해제 ]                  │
└──────────────────────────────┘
```

- 스위치는 `<button role="switch" aria-checked>` 로 만든다. 필터가 아니라 표시라서 필터 버튼 배지 수에는 넣지 않는다. 대신 배지 옆에 점 하나를 더해 "강조가 켜져 있음" 을 알린다 (모바일에서 범례 줄이 없으므로 필요하다).
- "모두 해제" 는 필터만 푼다. 강조 스위치는 그대로 둔다.
- 노드 순회 키: 스위치가 켜진 동안 검색 입력이 비어 있을 때 결과 목록 자리에 "최근 추가" 13개를 추가일 내림차순으로 보인다 (`aria-label` "최근 추가된 페이지"). 캔버스를 보지 못하는 사용자도 같은 집합에 닿는다. 키 배정은 02가 정한다.

### 2.3 켜고 끄기와 상태

- 기본은 꺼짐이다. 켜면 344개 중 13개에 점이 생길 뿐이라 기본 켜짐도 시끄럽지는 않지만, 첫 화면의 정보량을 늘리지 않는다 (12절 미결 R1).
- URL hash에 싣지 않는다. 공유할 "장소" 가 아니라 보기 취향이다. 대신 `localStorage` 에 `graph.recent=1` 로 남긴다 (실패하면 무시. 사이트의 테마 저장과 같은 방식).

### 2.4 데이터

- 빌드: `content.mjs` 가 이미 `page.added` (ISO 시각)를 갖는다. `graph.mjs` 가 노드에 `added: page.added.slice(0, 10)` 을 붙인다. 날짜 글자는 작성자 시간대의 날짜다 (`%aI`).
- 빌드는 최근 집합의 경계 날짜 하나를 최상위에 둔다: `recentSince` (14일 기준 또는 6개 바닥을 적용한 뒤의 가장 이른 날짜). 브라우저는 `node.added >= recentSince` 로 판정한다. ISO 날짜 문자열 비교라 계산이 없다. 집합 정의는 빌드 한 곳에만 있다.
- 범례 문구를 고르기 위해 `recentMode: 'days' | 'count'` 와 `recentDays: 14` 를 함께 둔다.
- 크기: `added` 652B gzip, 최상위 세 키는 무시할 만하다.

## 3. 약한 연결 리포트

### 3.1 기준

- **들어옴 0** (overviews 제외): 어느 페이지도 링크하지 않아 위키를 둘러보다가는 닿을 수 없는 페이지. 27개.
- **degree 3 이하**: 연결이 전체 하위 3.5%. 12개.
- 둘의 합집합 36개를 리포트한다 (1.3절). 한 페이지가 두 조건에 다 걸리면 첫 묶음에만 둔다.
- degree 4 이하로 넓히면 49개, 5 이하면 74개다. 보강 작업 목록으로 쓰기에 36개가 한 번에 훑을 수 있는 크기이고, degree 4는 18개가 한꺼번에 들어와 경계가 흐려진다.
- 나감 0 노드는 지금 0개다. 조건으로 두지 않고 자체 점검(9.4절)에서만 센다.
- overviews는 들어옴이 0일 수 있어도(지금은 0개) 허브라 제외한다.


- **경로 선**: 단계 노드 home 좌표를 순서대로 잇는 Catmull-Rom 곡선 (장력 0.5, 노드 원 가장자리에서 끊는다). 굵기 2px, 색은 새 토큰 `--graph-path` (dark 흰색 계열, light 잉크 계열)이고 그 아래 6px 폭 `--graph-path-glow` 를 한 번 더 그린다. dark는 `--graph-filament-blend` 로 더한다. 방향은 선 중간마다 작은 촉(4px)으로 보인다.
- **번호 배지**: 단계 노드 왼쪽 아래 `(-gap × 0.92, +gap × 0.62)` 에 지름 18px 원, 숫자 `--text-2xs` 700. 라벨 자리(오른쪽 위, 04 5.1절)와 반대쪽이라 라벨과 겹치지 않는다. 배지는 노드 라벨 충돌 검사의 장애물에 넣는다.
- **라벨**: 단계 노드는 모두 강제 후보다 (검색 결과와 같은 `+1e5` 단계). 단계가 최대 12개라 라벨 160개 상한에 여유가 있다.
- **나머지 노드**: 알파를 `--graph-dim-alpha` 의 중간값(`(1 + dim) / 2`)으로 낮춘다. 필터 흐림보다 덜 흐리게 해서 "경로가 주인공이지만 지도는 남아 있다" 로 읽힌다. 엣지는 경로 단계끼리의 엣지만 원래 알파, 나머지는 45%.
- **처음 그릴 때**: 선이 단계 1에서 마지막 단계로 900ms 동안 그려진다 (선 길이 비율, `--ease-out`). 배지는 선이 닿을 때 나타난다. 한 번뿐이고 반복하지 않는다. reduced-motion은 즉시.
- **필터와 겹칠 때**: 단계 노드가 필터 밖이면 노드는 필터 규칙대로 흐려지지만 배지와 라벨은 남고, 그 노드로 드나드는 경로 선 구간을 점선(4px 간격)으로 바꾼다. 경로가 끊겨 보이지 않으면서 "필터 밖" 임이 보인다. 단계 노드를 고르면 04 7.3절처럼 필터를 푼다.
- **prereq**: 선으로 그리지 않는다. 72개 중 41개가 바로 앞 단계라 경로 선과 겹치고, 나머지 31개를 호로 그리면 12단계 경로에서 선이 세 배로 는다. 단계 막대의 단계 툴팁과 상세 패널에 "선수 단계 3, 5" 로 적는다 (12절 개선 제안 E5에서 켜는 안).

### 4.4 궤도와의 관계

- 궤도에서는 경로 선을 그리지 않는다. 궤도는 노드를 home이 아닌 자리로 옮기므로 home 기준 선이 의미를 잃는다.
- 궤도 위의 단계 노드(1-hop, 2-hop 어디든)에는 번호 배지를 단다. 중심이 단계 노드면 단계 막대의 그 점이 "현재" 가 된다.
- 단계 막대의 ‹ › 는 이전, 다음 단계로 궤도 중심을 옮긴다 (04 6.2절 "중심 옮기기" 600ms). 이것이 경로를 따라 읽는 주 동작이다. 조감에서 › 를 누르면 단계 1로 궤도에 들어간다.
- 중심이 경로 밖 노드로 옮겨 가도 경로는 꺼지지 않는다. 막대의 "현재" 표시만 사라진다.
- 궤도를 나가 조감으로 돌아오면 경로 선이 다시 그려진다 (첫 그리기 연출 없이 즉시).
- 상세 패널: 중심이 단계 노드면 패널 머리 아래 한 줄 "Physical AI 카테고리 지도와 학습 경로의 4단계" 와 note, 선수 단계 번호를 보인다.

### 4.5 hash

`#path=overviews/physical-ai-overview`. `#node=` 와 함께 쓸 수 있다 (정규 순서 `#node=…&path=…`). 구분자와 순서, 둘 중 하나가 해석되지 않을 때의 처리는 02 8.4 ~ 8.6절이 정한다. 해석되지 않는 경로 id는 무시하고 콘솔 경고 한 줄을 남긴다.

wiki 쪽 진입점: overview 페이지의 학습 경로 컴포넌트(`studyPathSection()`) 머리에 "그래프에서 이 경로 보기" 링크(`/graph/#path=<overview id>`)를 단다. 이 링크는 서버 렌더라 스크립트 없이도 있다. `#path=` 를 받은 그래프 페이지가 스크립트 실패로 목록 판에 남으면 hash는 무시된다.

### 4.6 데이터

- 출처: `content.mjs` 의 `resolveStudyPaths()` 결과(`page.studyPath`). 이미 빌드가 해석하고 미해석을 `[study]` 로 리포트한다. 새 해석 코드가 필요 없다.
- 산출: 새 파일 `dist/graph/paths.json`. 경로 버튼을 처음 열 때, 또는 시작 hash에 `path=` 가 있을 때 받는다.

  ```json
    "paths": [
      {
        "id": "overviews/physical-ai-overview",
        "title": "Physical AI 카테고리 지도와 학습 경로",
  ```

- 빌드 로그: 기존 `[study]` 줄에 `paths.json NNNB` 를 덧붙인다.

## 5. 페이지별 미니 그래프

### 5.1 그리는 방식

| 안 | 장점 | 단점 | 결정 |

| 빌드 타임 정적 SVG | 스크립트 없이 보인다. 빌드 비용 거의 0. 페이지마다 fetch 없음. 지금 구조 그대로 | 페이지 HTML이 SVG만큼 커진다 | **채택** |

`relatedSection(page, neighbors)` 의 자리(`wikiFoot` 첫 절), 제목 "관련 페이지 n", SVG 상자(viewBox 480 × 240, `max-width: 34rem`), `reader.js` 툴팁 계약(`a[data-neigh][data-title]` 와 `li[data-neigh]` 짝), 목록 마크업을 유지한다. 바꾸는 것은 SVG 안의 배치와 선별, 색, 링크 방향이다.

### 5.2 선별과 배치

1. 이웃 전체를 정렬한다: 서로 링크(mutual) 먼저, 그다음 degree 내림차순, 같으면 제목.
2. 앞에서 24개를 고른다. 이웃 카테고리 가운데 24개 안에 하나도 없는 카테고리가 있으면, 그 카테고리 최상위 노드로 24개 중 가장 뒤 노드를 바꾼다 (최대 허브가 8색을 다 보이게 하려는 것).
3. 고른 노드를 04 4.2절 2번 순서(카테고리 범례 순서, 하위 태그 묶음, degree)로 다시 정렬하고, `placeRing` 과 같은 규칙으로 각도를 준다. 카테고리 사이 틈 `min(0.09, 0.7 / g)` rad, 꼭대기 시작, 시계 방향. 24개 이하라 겹은 하나다.
4. 각도를 지금처럼 타원(중심 240, 120, 반지름 200 × 92) 위 점으로 바꾼다. 원이 아닌 타원은 읽기 칼럼의 가로 폭을 쓰기 위해서다.
5. 숨긴 이웃이 있으면 꼭대기에 `reserve = 0.5` rad를 비우고 거기에 `+k` 글자를 둔다 (04 4.3절 6번과 같은 생각). `+k` 는 `/graph/#node=<이 페이지 id>` 로 가는 링크다.
6. 노드 반지름은 지금 식 `4 + 5 × (degree / 고른 노드 최대 degree)` 를 쓴다. 중심은 7.

### 5.3 그리는 것

| 요소 | 모양 | 클래스 |
|---|---|---|
| 바큇살 | 중심에서 이웃까지 직선. 서로 링크는 실선 1.2px, 이 페이지가 거는 링크만 있으면 실선 1px, 들어오기만 하는 링크(백링크)는 점선 `3 3` | `.neigh-spoke.is-mutual`, `.is-out`, `.is-in` |
| 현 | 고른 이웃끼리의 엣지. 두 점의 중점을 중심 쪽으로 30% 당긴 2차 곡선 (04 4.4절). 상한 40개, 서로 링크 쌍 먼저, 다음은 두 끝 degree 합 | `.neigh-chord` (알파 0.35) |
| 이웃 노드 | 원, 채움 `var(--cat-<category>)` | `.neigh-node.c-<category>` |
| 중심 | 원 r 7, 채움 자기 카테고리 색, 바깥 1px 고리 | `.neigh-center` |
| `+k` | 꼭대기 글자 `--text-xs` mono muted | `.neigh-more` |

- 색은 01 8.3절대로 `:root` 에 둘 `--cat-*` 를 쓴다. wiki 배경(`--bg` `#0b0e14`, `#f7f8fa`) 위 대비는 01 13절에 미확인으로 남아 있고, 미니 그래프가 그 첫 소비자다.
- SVG는 `aria-hidden="true"` 로 장식 처리하고 안의 링크는 `tabindex="-1"` 이다. 지금은 `role="img"` 안에 링크가 있어 접근성 트리에서 이름 붙은 그림과 링크 118개가 섞인다. 스크린 리더와 키보드는 바로 아래 목록을 쓴다. 마우스 사용자는 지금처럼 노드를 눌러 이동한다.
- `aria-label` 과 `data-title` 이 같은 제목을 두 번 싣던 것을 `data-title` 하나로 줄인다 (`reader.js` 는 `data-title` 을 먼저 읽는다).
- 텍스트 없이 그린다. 제목은 툴팁과 목록이 맡는다. 480 × 240 상자를 휴대폰 폭(약 343px)으로 줄이면 글자가 7px 안팎이 되기 때문이다.

## 9. 03 스키마에 넘길 요구사항

### 9.1 `graph.json` (홈 히어로와 함께 쓰는 파일)

| 위치 | 필드 | 형태 | 예 | 크기 (344노드) | 쓰는 곳 |
|---|---|---|---|---|---|
| 노드 | `added` | `"YYYY-MM-DD"` 문자열, 필수 | `"2026-11-16"` | 7.2KB, gzip 0.65KB | 최근 강조, 상세 패널 |
| 최상위 | `recentSince` | `"YYYY-MM-DD"` | `"2026-11-03"` | 무시할 만함 | 최근 판정 (`added >= recentSince`) |
| 최상위 | `recentMode` | `"days"` 또는 `"count"` | `"days"` | | 범례 문구 |
| 최상위 | `recentDays` | 정수 | `14` | | 범례 문구 |

- 가드: 최근 집합이 노드의 50%를 넘으면 git 이력이 없는 빌드로 보고 `recentSince` 를 `null` 로 둔다. 탐색기는 `null` 이면 스위치를 숨긴다. 빌드 로그 `[graph] WARN recent: N/344 (git 이력 없음?)`.
- 약한 연결과 미니 그래프는 `graph.json` 에 아무것도 요구하지 않는다. 약한 연결을 지도에 표시하는 E3를 채택해도 탐색기가 `edges` 로 들어옴 수를 셀 수 있다.
- 학습 경로는 `graph.json` 에 넣지 않는다 (9.2절).

### 9.2 새 파일 `dist/graph/paths.json`

| 필드 | 형태 |
|---|---|
| `version` | 정수 `1` (03 6.1절에서 더함) |
| `paths[]` | 카탈로그 순서의 overview 경로 |
| `paths[].id` | overview 노드 id (`graph.json` 노드 id와 같은 공간) |
| `paths[].title` | 카탈로그 표시 이름 |
| `paths[].steps[]` | 단계. 미해석 단계는 빠진다 |
| `steps[].n` | 원래 단계 번호 (1부터, 빠진 번호 가능) |
| `steps[].id` | 단계 노드 id |
| `steps[].note` | 문자열, 비어 있을 수 있다 |
| `steps[].prereq` | 같은 경로의 단계 번호 배열, 비어 있을 수 있다 |

크기 약 15KB, gzip 약 7KB. 경로 버튼을 처음 열거나 시작 hash에 `path=` 가 있을 때만 받는다.

### 9.3 `dist/graph/3d/layout.json`

05 6절이 정한 `xyz` 배열을 그대로 쓴다. 이 문서는 추가 요구가 없다. 노드 순서는 03 6.2절이 `graph.json` 의 `nodes` 배열 순서로 정했다 (id 정렬 순서가 아니다. 04 2.1절은 배치 계산에만 정렬 사본을 쓴다).

### 9.4 자체 점검 (Phase 3 `graph.mjs` 점검 스크립트에 합친다)

- 모든 노드에 `added` 가 있고 `YYYY-MM-DD` 형태다.
- `recentSince` 가 `null` 이 아니면 최근 노드 수가 1 이상, 노드 수의 50% 이하.
- `paths.json` 의 모든 단계 id와 경로 id가 `graph.json` 노드에 있다. prereq 번호가 그 경로의 앞 단계를 가리킨다.
- 약한 연결 수와 나감 0 노드 수를 로그로 남긴다 (실패 조건은 아니다).

## 10. 다른 설계 문서와 어긋나는 점

작성 때는 고치지 않고 적었다. 2026-11-17 03 작업에서 정본 원칙(화면 구성 01, 인터랙션 02, 스키마 03, 배치 04, 라이브러리 05, 추가 기능 06)으로 판정하고 항목마다 "해결" 을 덧붙였다.

1. **01 7절, 모바일 궤도의 단계 막대 자리.** 01은 모바일 단계 막대를 "필터 칩 줄 자리" 로 정했는데, 궤도에서는 그 자리를 경로 줄(`.graph-trail`)이 쓴다 (01 6절). 이 문서는 모바일 궤도에서 단계 막대를 경로 줄 끝 알약으로 접는다 (4.3절). 01 6절 표에 이 행이 필요하다. **해결:** 01 6절 표에 단계 막대 행을, 01 7절 학습 경로 행에 모바일 궤도와 휴대폰 가로의 알약을 더했다.
2. **01 5.6절 도구 묶음 표.** 3D 진입 링크 "3D" 가 데스크톱 조감에 하나 늘어난다 (6절). 01 표에 없다. **해결:** 01 5.6절 표에 "3D" 행을 더했다.
3. **01 7절, 최근 추가 범례 줄의 모바일 처리.** 01은 범례 맨 아래 한 줄만 정했다. 모바일 견본 한 줄 범례에는 줄을 더할 자리가 없어 필터 버튼 배지 점으로 대신한다 (2.2절). **해결:** 01 7절 최근 추가 행에 모바일 배지 점을 적었다.
4. **05 6절 "본 페이지 상단에 '3D로 보기 (실험)' 링크 하나".** 01이 그래프 페이지 자체 상단 바를 없앴으므로 "상단" 이 없다. 이 문서는 목록 판 머리와 데스크톱 도구 묶음 두 곳에 둔다. **해결:** 05 6절 경로 행을 이 문서의 두 진입점으로 고쳤다.
5. **04 11절 "미니 이웃 그래프는 4.2절 1-hop 궤도 배치를 그대로".** 이 문서는 4.2절의 정렬과 각도 규칙만 쓰고, 원 대신 타원에, 겹 대신 24개 상한과 "+k" 로 그린다 (5.2절). 4.2절대로 3겹을 쓰면 최대 허브에서 480 × 240 상자에 118개가 다시 들어간다. **해결:** 04 11절 제안을 "정렬과 각도 규칙만 쓰고 세부는 06 5.2절" 로 고쳤다.
6. **01 7절 미니 그래프 행 "이미 480 × 240 SVG 미니 성도와 이웃 목록이 있으므로 그 자리를 바꾼다".** 같은 뜻이다. 다만 `--cat-*` 가 wiki 페이지에서 읽혀야 한다는 조건 때문에 미니 그래프의 색 입히기는 Phase 4 CSS 토큰 작업 뒤로 묶인다 (7절 순서 2의 의존). **해결:** 어긋남이 아니다. 01 7절이 이미 `--cat-*` 를 `:root` 에 둔다고 적었고 의존은 이 문서 7절에 있다. 고친 문서 없음.
7. **계획서 Phase 5 미니 그래프 항목의 "342개 페이지".** 현재 페이지는 344개다 (계획서 2절도 344). **해결:** 계획서(`docs/graph-design-plan.md`)는 이번 작업의 수정 범위 밖이라 고치지 않았다. 계획서를 갱신할 때 함께 고친다.
8. **05 4절 A 5번 "`.graph-explorer` 는 `hidden` 으로 시작"** 은 현재 마크업 기준이고 01 2.3절은 `data-view="list"` 방식으로 바꿨다. 이 문서의 `#weak-links` 처리(3.2절)는 01 방식을 전제한다. **해결:** 05 4절 A-5를 01 방식으로 고쳤다. `#weak-links` 를 목록 판으로 보내는 규칙은 02 8.5절에 더했고, 01 7절 링크도 `href="#weak-links"` 로 맞췄다.

## 11. 확인하지 못한 것

- 미니 그래프 변경 후의 실제 HTML 바이트와 gzip. 5.5절 값은 근사 문자열로 잰 추정이다.
- `--cat-*` 8색의 wiki 배경 위 대비 (01 13절과 같은 항목).
- 위성 점(4px)이 k 0.37 휴대폰 첫 화면과 light 테마에서 눈에 띄는지. 렌더하지 않았다.
- 경로 선 Catmull-Rom 곡선이 단계 노드가 아닌 다른 노드 위를 지나갈 때 읽히는지. 12단계 경로 두 개(`vla-evolution…`, `prompt-to-loop…`)는 이웃 단계 사이 엣지가 적어 선이 성운을 가로지를 수 있다. 화면으로 확인하지 않았다.
- 단계 막대(최대 12단계, 단계 점 22px + 간격)의 데스크톱 폭이 범례 독과 도구 묶음 사이에 들어가는지. 어림셈으로 12 × 26 + 이름 140 + 버튼 3개 약 100 = 약 550px이고, 1440px 화면의 범례(200) 안내 문구와 도구 묶음 사이는 계산하지 않았다. 01 I6(안내를 늘 띄우지 않음)을 채택하면 여유가 커진다.
- `paths.json` 의 실제 크기. 1.6절 값은 같은 내용을 `JSON.stringify` 한 값이다.
- 3D 페이지의 light 테마 표현. 계획서 4절은 "라이트 테마에서는 깊이감이 사라진다" 고만 관찰했다.

| R1 | 최근 추가 강조의 기본값 | (a) 꺼짐 (b) 켜짐 | **(a)**. 첫 화면 정보량을 늘리지 않는다. 다만 켜도 13개 점이라 (b)도 무리가 없다 |

### 12.2 개선 제안

사용자가 세련되고 모던한 화면을 가장 먼저 원하므로 그 쪽으로 고른 안이다. 하나씩 따로 채택할 수 있다.

| 번호 | 제안 | 무엇이 나아지나 | 비용 |
|---|---|---|---|
| E1 | **신선도 그라데이션.** 최근 위성 점 하나 대신, 스위치를 켜면 추가일이 가까울수록 빛번짐 알파를 높인다 (90일 안에서 선형, 그 밖은 기본값). 지도 위로 "자라는 가장자리" 가 은은하게 보인다 | 이분법 표식보다 지식 성장의 방향이 지형으로 읽힌다 | 탐색기 수십 줄. `added` 가 이미 있으므로 데이터 추가 없음 |
| E2 | **경로 재생.** 단계 막대에 ▶ 버튼. 누르면 3초 간격으로 다음 단계로 궤도 중심을 옮긴다. 아무 입력이나 들어오면 멈춘다 | 학습 경로가 "둘러보기 투어" 가 된다. 발표나 공유에 좋다 | 탐색기 30줄. reduced-motion에서는 버튼을 숨긴다 |
| E3 | **약한 연결 렌즈.** "강조" 절에 두 번째 스위치 "연결이 적은 페이지". 켜면 36개 노드에 점선 바깥 고리를 그린다 | 보강 대상이 지도 어디에 몰렸는지(physical-ai와 agents 가장자리) 보인다 | 탐색기 20줄, 데이터 추가 없음 |
| E4 | **연결 후보 제안.** 약한 연결 행마다 "링크할 만한 페이지" 를 태그가 가장 많이 겹치는 페이지 3개로 빌드에서 계산해 작게 보인다 | 리포트가 목록에서 할 일 목록이 된다 | 빌드 30줄. 태그 겹침 계산 344 × 344 |
| E5 | **선수 관계 보기.** 단계 막대의 작은 토글로 prereq 31개(바로 앞 단계 아닌 것)를 경로 선 아래 가는 호로 그린다 | 갈래가 있는 경로(`prompt-to-loop…`)의 구조가 보인다 | 탐색기 40줄 |
| E6 | **미니 그래프 가장자리 빛.** 미니 SVG의 이웃 원에 `--cat-*` 색 1px 테와 아주 옅은 방사형 그라데이션(`<radialGradient>` 카테고리별 8개, 페이지당 한 번 정의)을 준다 | 그래프 페이지의 구슬 노드와 같은 질감이 문서 하단에도 이어진다 | 페이지당 약 600B |
| E7 | **목록과 그림의 양방향 연동.** 관련 페이지 목록 행을 가리키면 미니 그래프의 그 노드와 바큇살이 밝아진다 (지금은 노드에서 목록 방향만) | 목록을 읽으며 위치를 함께 본다 | `reader.js` 20줄 |
| E8 | **경로 진입 연출.** 경로를 고를 때 카메라 비행이 끝난 뒤 선을 그리기 시작하고(4.2절의 900ms), 선 끝이 지나가는 노드마다 배지가 120ms 커지며 나타난다 | 경로가 "그려지는" 장면 하나로 기억된다 | 4.2절 연출에 포함 가능, 추가 20줄 |
| E9 | **overview 페이지의 미리보기.** 학습 경로 컴포넌트 옆에 그 경로만 그린 작은 정적 SVG(단계 노드를 home 좌표 비율로 놓고 곡선으로 잇기)를 빌드에서 만든다. 누르면 `/graph/#path=` | wiki 문서에서 그래프로 넘어가는 동기가 생긴다 | 빌드 60줄. 좌표는 04 배치 결과를 재사용 |

넣지 않기를 권하는 것: 최근 노드의 맥박 애니메이션(`design-direction.md` 1절 "숨쉬는 글로우" 금지), 약한 연결을 빨간색 경고로 칠하기(보강 대상이지 오류가 아니다), 미니 그래프 런타임 확대와 팬(문서 하단 그림에 조작을 붙이면 스크롤과 다툰다).
