# 04. 배치 알고리즘

작성일 2026-11-17. `docs/graph-design-plan.md` Phase 2의 "배치 알고리즘 결정 (허브 뭉침 완화 방법 포함)" 산출물이다. 정본 시안은 `docs/graph-mockups/f-atlas-orbit.html` (이하 시안 F)이고, 이 문서의 행 번호는 그 파일 기준이다. 라이브러리는 d3-force를 쓴다는 전제만 둔다 (선정은 05가 맡는다). `graph.json` 필드 이름은 03(스키마)과 맞춘다.

## 0. 결정 요약

| 번호 | 항목 | 결정 |
|---|---|---|
| L1 | 조감 force 구성 | 시안 F 그대로: 카테고리 앵커 forceX/Y, degree 비례 charge, degree와 카테고리로 감쇠한 link, collide. 바꾸는 값은 collide 반지름 하나 (`r + 3.5` 에서 `1.4r + 3.5`) |
| L2 | 계산 시점 | **빌드 타임에 좌표를 구워 `graph.json` 에 싣는다.** 브라우저는 force 계산을 하지 않는다 |
| L3 | 결정성 | 빌드 스크립트가 노드를 `id` 순으로 정렬한 사본에 시드 7 LCG 초기 위치를 주고 360 tick을 돈다. 같은 입력이면 같은 좌표 (측정 차이 0) |
| L4 | 세로 화면 | 가로 배치 한 벌만 굽고, 세로 화면에서는 런타임에 x와 y를 맞바꾼다 (시안 F의 세로 앵커 전치와 같은 반사) |
| L5 | 궤도 배치 | 시안 F `layout()` 그대로. 1-hop 궤도는 이웃 40개 넘으면 2겹, 90개 넘으면 3겹. 2-hop은 공유 이웃 수 순 상위 28개, 나머지는 "+k" |
| L6 | 전환 | 시안 F 그대로 (640ms easeInOutCubic, 지연 최대 360ms, 카메라 720ms). 전환 중 선택은 현재 위치에서 다시 출발한다. 나가는 중에 다시 들어갈 때 복귀 카메라를 덮어쓰는 시안 결함을 고친다 (6.4절) |
| L7 | 필터 | 배치를 다시 계산하지 않는다. 걸러진 노드는 흐리게 남기고 "화면 맞춤"만 걸러진 노드에 맞춘다 |
| L8 | 히트 테스트 | 선형 탐색 유지. quadtree는 쓰지 않는다 (344노드 1회 1.6µs) |
| L9 | 성능 | 프레임당 DOM 읽기(`getBoundingClientRect`)와 성운 이름 자리 찾기를 캐시한다 |

## 1. 측정

스크립트는 저장소 밖 스크래치 디렉토리에서 돌렸다 (`bench.mjs`, `visual.mjs`, `micro.mjs`). 시안 F의 배치 코드(478 ~ 494행)와 `layout()`(766 ~ 812행)을 node로 옮겨 실제 스냅샷 `shared/graph-data.js`(344노드, 2,600엣지, 최대 degree 118)에 돌렸다.

환경: Apple M5, Node v24.18.0, d3-force 3.0.0. 시간은 JIT 예열 1회 뒤 7회 중앙값이다. 휴대폰 CPU에서의 시간은 미측정이다.

### 1.1 조감 배치 시간과 확장성

| 입력 | 360 tick 시간 | tick당 |
|---|---|---|
| 실제 344노드, 2,600엣지 (가로) | 268ms (최소 266, 최대 299) | 0.75ms |
| 실제 344노드 (세로 앵커) | 275ms | 0.76ms |
| 복제 1,032노드, 7,800엣지 | 1,101ms | 3.06ms |
| 복제 2,064노드, 15,600엣지 | 3,023ms | 8.40ms |

복제 그래프는 스냅샷을 3벌, 6벌 겹치고 엣지 10%를 다른 벌로 다시 이었다. 1,000노드를 넘으면 런타임 계산이 메인 스레드를 1초 넘게 막는다. 시안 F는 이 계산을 동기로 돌린다 (494행).

### 1.2 결정성과 안정성

| 검사 | 결과 |
|---|---|
| 같은 입력 두 번 | 좌표 차이 최대 0 |
| 노드 배열 순서만 뒤집음 | 평균 50.6 world 이동 (초기 위치 시드가 배열 순서를 따라간다) |
| 노드 1개 추가 (최대 허브와 잎 3개에 연결) | 평균 14.5, 최대 112 world 이동 |

d3-force 3.0.0의 jiggle 난수는 고정 시드 LCG(`src/lcg.js`)라 실행마다 같다. 다만 시안 F의 초기 위치는 `Math.cos`, `Math.sin` 을 쓰는데, 이 함수의 마지막 자릿수는 엔진마다 다를 수 있고 360 tick이 그 차이를 키울 수 있다. 브라우저 사이 결정성은 미측정이다. 빌드 타임 계산(L2)은 Node 한 곳에서만 계산하므로 이 문제가 생기지 않는다.

### 1.3 수렴

600 tick 결과까지의 평균 거리 (world 단위):

| tick | 150 | 200 | 250 | 300 | 360 | 450 |
|---|---|---|---|---|---|---|
| 평균 거리 | 1.57 | 0.52 | 0.16 | 0.05 | 0.01 | 0.00 |

d3 기본 `alphaDecay` 로 alpha는 약 300 tick에 `alphaMin` 아래로 떨어진다. 300 tick이면 충분하지만 빌드 시간에서 아낄 것이 50ms뿐이라 시안과 같은 360을 둔다.

### 1.4 허브 뭉침 완화 수단의 효과

지표: 겹친 쌍(world에서 두 원이 겹침), 상위 5 허브 둘레 80 world 안의 노드 수, 자기 카테고리 중앙값 중심이 가장 가까운 노드 비율(overviews 제외, 클수록 성운이 잘 갈림).

| 변형 | 겹친 쌍 | 허브 둘레 80 안 노드 수 (상위 1 ~ 5) | 자기 성운 비율 | 외곽 크기 |
|---|---|---|---|---|
| 시안 F | 0 | 0, 14, 18, 15, 16 | 95.8% | 1341 × 843 |
| 감쇠 없음 (charge -40 고정, link 거리 30, 강도 `1/lo`) | 0 | 27, 35, 37, 31, 35 | 90.9% | 1067 × 676 |
| 허브 charge만 끔 (-40 고정) | 0 | 0, 20, 25, 24, 22 | 97.6% | 1250 × 794 |
| 카테고리 넘는 link 감쇠만 끔 | 0 | 1, 10, 18, 15, 17 | 91.5% | 1314 × 802 |
| 시안 F + collide `1.4r + 3.5` | 0 | 0, 10, 15, 23, 18 | 96.7% | 1353 × 847 |

감쇠를 모두 빼면 허브 둘레 노드가 약 두 배가 된다. 허브 charge는 뭉침을, 카테고리 넘는 link 감쇠는 성운 분리를 맡는다. 최대 허브(`overviews/physical-ai-overview`)는 앵커가 없고 이웃이 모두 다른 카테고리라 감쇠가 있으면 둘레가 비어 있다.

### 1.5 화면에서의 겹침

노드는 `r × √k` 로 그리고 거리는 `× k` 로 줄어든다. 그래서 world에서 겹치지 않아도 줌을 줄이면 화면에서 겹친다. 화면 원이 겹치는 쌍:

| collide 반지름 | k 0.37 | k 0.6 | k 0.9 | k 1.5 |
|---|---|---|---|---|
| `r + 3.5` (시안 F) | 93 | 0 | 0 | 0 |
| `1.4r + 3.5` | 0 | 0 | 0 | 0 |

k 0.37은 375 × 812 세로 화면의 처음 맞춤 배율(계산값)이다. 1440 × 900 가로 화면은 약 0.90이다. 브라우저 화면에서 이 겹침을 눈으로 확인하지는 않았다.

### 1.6 그 밖

| 항목 | 결과 |
|---|---|
| 궤도 배치 344개 전부 계산 | 11.1ms (노드당 0.032ms) |
| 2-hop 후보가 28개를 넘는 노드 | 310 / 344. 후보 수 중앙값 75, 최대 182 |
| degree 분포 | 중앙값 9, 90분위 23. 50 이상 5개, 25 이상 30개, 10 이상 163개 |
| 좌표를 정수로 굽는 비용 (스냅샷 기준) | 442,034 B에서 447,726 B, gzip 49,563 B에서 52,184 B (+2.6KB) |
| 정수 반올림 뒤 겹친 쌍 | 0 (실수 좌표도 0) |
| 히트 테스트 선형 탐색 | 344노드 1.6µs, 1,032노드 5.9µs, 2,064노드 12.0µs |
| 성운 이름 자리 찾기 최악 (모든 후보가 막혀 491자리 × 노드 전수 검사) | 344노드 0.80ms, 1,032노드 5.48ms, 2,064노드 9.63ms (프레임당) |

스냅샷 크기는 `year`, `type`, `tags` 가 붙은 시안용 데이터 기준이다. 사이트 `graph.json` 의 실제 크기는 Phase 3에서 잰다.

## 2. 조감(성도) 배치

### 2.1 입력

- 노드: `graph.json` 노드 전부. degree는 무방향 고유 이웃 수(`graph.mjs` 의 `degree` 와 같다).
- 엣지: 방향 엣지 2,600개를 그대로 link로 쓴다. 서로 링크한 쌍은 link가 두 개다 (시안과 같다).
- 계산 전에 노드를 `id` 오름차순으로 정렬한 사본을 만든다. `graph.json` 노드 순서는 건드리지 않는다 (홈 히어로 `constellation.js` 가 배열 순서로 자리를 정한다). 1.2절대로 순서가 바뀌면 배치가 바뀐다.
- 반지름 `r = min(20, 2 + 1.6√degree)` (431행). 그리기와 collide가 같은 값을 쓴다.

### 2.2 카테고리 중심 좌표

중심은 손으로 정한 표다 (444 ~ 452행). 카테고리 간 링크 양(overviews와 physical-ai 230, agents와 overviews 102, agents와 physical-ai 5)을 보고, 많이 잇는 쌍은 가깝게, 거의 잇지 않는 쌍은 멀게 놓았다. overviews는 앵커가 없어 link 힘으로 그 사이에 자리 잡는다.

| 카테고리 | 앵커 (x, y) |
|---|---|
| physical-ai | (-330, 10) + 하위 오프셋 |
| llms | (-40, -300) |
| agents | (300, -90) |
| evaluations | (430, -330) |
| applications | (210, 270) |
| database | (470, 200) |
| etc | (-30, 360) |
| overviews | 없음 (x, y 앵커 힘 0) |

physical-ai는 149개라 하나의 덩어리로 두지 않고 첫 태그(`physical-ai` 제외)로 하위 오프셋을 더한다.

| 첫 태그 | 오프셋 | 노드 수 (스냅샷) |
|---|---|---|
| vla | (0, 0) | 91 |
| world-model | (-150, -150) | 14 |
| manipulation, robot-learning, imitation-learning | (-30, 175) | 13 |
| humanoid | (130, 150) | 6 |
| slam, mobile-robot | (-200, 120) | 10 |
| simulator | (-175, -10) | 6 |
| benchmark, robot-dataset | (120, -170) | 7 |
| 그 밖 (hardware, safety) | (0, 0) | 2 |

규칙:

- 표에 없는 새 카테고리는 앵커 없음으로 둔다 (overviews와 같은 처리). 빌드 자체 점검이 경고를 내고, 사람이 표에 앵커를 추가한다. 카테고리는 CLAUDE.md 통제 목록이라 드물게 바뀐다.
- 표에 없는 하위 태그는 (0, 0), 즉 vla 자리로 간다.
- 첫 태그는 frontmatter `tags` 배열 순서를 따른다. 태그 순서를 바꾸면 노드 자리가 바뀐다.

### 2.3 초기 위치

Park-Miller LCG, 시드 7 (465 ~ 466행). 정렬한 노드 순서대로 난수를 두 개씩 뽑는다.

- 앵커가 있으면 앵커, 없으면 이웃들의 앵커 평균 (이웃에 앵커가 없으면 원점)을 중심으로 한다.
- 중심에서 각도 `rnd × 2π`, 거리 `20 + rnd × 90` 에 둔다.

### 2.4 force 구성

| force | 시안 F 값 (행) | 결정 | 근거 |
|---|---|---|---|
| charge (`forceManyBody`) | 강도 `-26 - 3.2 × degree`, `distanceMax 520`, `theta 0.85` (479) | 유지 | 허브일수록 세게 밀어 둘레를 비운다. 끄면 허브 둘레 노드가 14 ~ 18에서 20 ~ 25로 는다 (1.4절) |
| link 거리 | `26 + 5.5 × √max(deg_s, deg_t)` (481) | 유지 | 허브에 붙은 link를 길게 해 잎을 허브에서 떼어 놓는다. 최대 허브는 약 86 |
| link 강도 | `0.7 / min(deg)`, 큰 쪽 degree가 30 이상이면 `× 0.3`, 카테고리를 넘으면 `× 0.35` (482 ~ 488) | 유지 | 허브 감쇠가 다발이 허브로 빨려 드는 것을 막고, 카테고리 넘는 감쇠가 성운을 가른다. 끄면 자기 성운 비율이 95.8%에서 91.5%로 떨어진다 |
| x, y (`forceX`, `forceY`) | 앵커로, 강도 0.11. 앵커 없으면 0 (489 ~ 490) | 유지 | 성운 자리를 고정한다 |
| collide | 반지름 `r + 3.5`, 강도 0.9, 반복 2 (491) | **반지름을 `1.4r + 3.5` 로 바꾼다** | 세로 휴대폰 처음 배율 k 0.37에서 화면 겹침 93쌍이 0쌍이 된다. 외곽은 1% 커지고 다른 지표는 같거나 낫다 (1.4절, 1.5절). 시안 F 스크린샷과 미세하게 달라지므로 Phase 4 스크린샷으로 확인한다 (10절 결정 2, 2026-11-17 승인) |
| center | 쓰지 않는다 | 유지 | 앵커가 전체 위치를 잡는다 |
| 반복 | `sim.stop()` 뒤 `tick()` 360회 (494) | 유지 | 1.3절 |

계산이 끝나면 좌표를 정수로 반올림한다 (겹침 변화 없음, 1.6절).

### 2.5 허브 뭉침 완화 정리

허브 뭉침은 force 네 가지가 함께 푼다. 하나만 빼도 지표가 나빠진다 (1.4절).

1. 허브 charge: degree에 비례해 밀어낸다.
2. 허브 link 감쇠: 큰 쪽 degree 30 이상이면 강도 30%, 거리는 √degree로 늘인다.
3. 카테고리 넘는 link 감쇠: 강도 35%. overviews 허브가 여러 성운을 한가운데로 끌어오지 않게 한다.
4. collide: 원끼리 겹치지 않게 하고 2.4절 값으로 줌 아웃 화면까지 지킨다.

그래도 남는 빽빽함(허브를 고르면 방사 다발이 보이는 문제)은 배치로 풀지 않고 궤도 화면(4절)이 맡는다. 계획서 4절의 "A의 약점을 B가 메운다" 결정이다.

| 세로 화면 | 화면 비율로 앵커를 바꿔 다시 계산 | 한 벌을 전치 (3.4절) |
| 배치 실험 | 브라우저에서 바로 | 빌드를 다시 돌린다 |

### 3.2 결정

빌드 타임에 굽는다. 차단 시간, 엔진 사이 결정성, 1,000노드 확장성, 런타임 의존 제거 모두 이쪽이 낫고, 대가는 2.6KB와 빌드 0.3초다.

부수 효과로 브라우저에 d3-force를 싣지 않아도 된다. d3-force는 빌드 스크립트의 의존이 된다. 자리는 05 4절대로 `devDependencies` 다. 배포 CI(`.github/workflows/deploy.yml`)는 `NODE_ENV` 없이 `npm ci` 를 돌려 `devDependencies` 도 설치하고, 같은 자리의 `pagefind` 를 `build:deploy` 가 이미 쓴다.

### 3.3 빌드 구현

- 새 모듈(예: `site/lib/graph-layout.mjs`)이 `buildGraph` 결과를 받아 노드마다 정수 좌표(가로 배치, world 단위)를 만든다. `site/build.mjs` 3절의 `buildGraph` 직후에 부른다. `graph.json` 필드는 `xy: [x, y]` 다 (03 3.2절. 런타임 현재 위치 `n.x`, `n.y` 와 이름을 나눈다).
- 홈 히어로 `constellation.js` 는 노드의 `id`, `degree`, `domain` 과 배열 순서만 읽고 자기 자리를 따로 계산한다 (확인함). 새 필드는 무시된다.
- 자체 점검 (`STRICT` 에서 실패):
  - 모든 노드의 `xy` 가 유한한 정수 두 개다 (03 7절 V10, V11에 합쳤다).
  - world 겹친 쌍 0.
  - 외곽이 가로 600 ~ 3,000 world 안에 있다 (배치가 터지거나 한 점으로 무너진 것을 잡는다).
  - 앵커 표에 없는 카테고리가 있으면 경고.
- 페이지가 하나 늘면 다른 노드도 평균 15 world 남짓 움직인다 (1.2절). 매 빌드 그림이 조금씩 바뀌는 것은 받아들인다 (10절 결정 1, 2026-11-17 승인).

### 3.4 세로 화면

- `portrait = W < H × 0.8` (시안 454행과 같은 기준).
- 세로면 home 좌표를 `(hx, hy) = (y, x)` 로 쓴다. 시안 F의 세로 앵커도 `(ax, ay) → (ay × 1.15, ax × 0.85)` 로 같은 대각선 반사이므로 성운 방향이 같다 (physical-ai가 위). 전치는 거리를 보존하므로 1.4절, 1.5절 지표가 그대로 성립한다. 시안 F 세로 배치와는 비율이 조금 다르고 별개 계산이라 노드 자리가 같지 않다. 375px 성운 이름 배치는 Phase 6에서 다시 확인한다.
- 시안은 회전해도 다시 계산하지 않았다 (453행 shortcut). 굽기 방식은 바꾸기가 싸므로 리사이즈에서 기준을 넘으면 바꾼다.
  - 성도 화면: home을 바꾸고 노드를 640ms 전환으로 새 자리에 옮긴 뒤 `fitTarget` 으로 카메라를 맞춘다. reduced-motion은 한 프레임에 바꾼다.
  - 궤도 화면: 바꾸기를 미루고 궤도를 나갈 때 적용한다. 나가는 전환의 목표가 새 home이 되고, 복귀 카메라는 `atlasCam` 대신 `fitTarget(nodes)` 다.
  - 성운 안개(`buildHaze`)와 `CAT_INFO` 는 home이 바뀔 때 다시 만든다.

### 3.5 reduced-motion

굽기 방식에서는 계산 단계가 없으므로 정지 배치가 따로 필요 없다. 첫 프레임이 최종 배치다. 첫 등장 연출(600ms)과 전환은 시안처럼 즉시 바꾼다.

## 4. 궤도(초점) 배치

궤도 배치는 런타임에 고를 때마다 계산한다 (노드당 0.032ms, 1.6절). 캐시하지 않는다.

### 4.1 상수

| 이름 | 값 | 뜻 |
|---|---|---|
| `CAP2` | 28 | 2-hop 바깥 궤도 상한 |
| `TRACK` | 24 | 여러 겹 궤도의 겹 간격 (world) |
| `LABEL_ROOM` | 150 | 안쪽 바깥 궤도 사이 라벨 자리 (world) |
| `START` | `-π/2` | 각도 시작 (꼭대기), 시계 방향 |

### 4.2 1-hop 안쪽 궤도

1. 이웃 목록 `r1` = 중심의 무방향 이웃 전부.
2. 정렬: 카테고리 범례 순서(physical-ai, agents, applications, database, llms, overviews, evaluations, etc), 같은 카테고리 안에서는 `카테고리|첫 하위 태그` 묶음의 크기 내림차순, 묶음 키 사전순, degree 내림차순 (758 ~ 765행). 같은 묶음이 호 하나로 모인다.
3. 겹 수: 이웃 40개 이하 1겹, 90개 이하 2겹, 그 위 3겹.
4. 반지름 `R1 = max(130, (n1 / 겹수) × 21 / 2π)`. 겹마다 노드 사이 호 길이가 약 21 world가 된다. 바깥 겹 `R1o = R1 + (겹수 - 1) × 24`.
5. 각도 배정 `placeRing` (742 ~ 757행):
   - 카테고리 묶음 수 g가 2 이상이면 묶음 사이 틈 `gap = min(0.09, 0.7 / g)` rad.
   - 한 칸 `step = (2π - reserve - g × gap) / n`. 1-hop은 `reserve = 0`.
   - `START + gap/2` 에서 시작해 칸 가운데에 놓고, 카테고리가 바뀌면 `gap` 을 더한다.
   - 여러 겹이면 i번째 노드를 `i mod 겹수` 번째 겹에 둔다 (지그재그).
6. 노드 크기 상한 `cap = 0.4 × 칸 호 길이` (world). 그릴 때 반지름은 `max(2.5, min(r√k, cap × k))`, 중심은 1.25배 (1010 ~ 1015행).
7. 카테고리 호는 반지름 `R1 - 16` 에 그리고 노드가 하나뿐인 묶음은 호를 생략한다.

### 4.3 2-hop 바깥 궤도

1. 후보: 1-hop 이웃의 이웃 중 중심과 1-hop을 뺀 노드. 각 후보에 닿는 1-hop 부모 목록을 모은다.
2. 선별 기준: 부모 수 내림차순, 같으면 degree 내림차순. 상위 28개를 남긴다 (`모두 보이기` 면 전부).
3. 남긴 노드의 정렬: 카테고리 순, 같은 카테고리 안에서 부모들 각도의 원형 평균 순. 부모 가까이에 놓여 바큇살이 덜 꼬인다.
4. 겹 수 `min(3, max(1, ceil(n2 / 72)))`. 28개면 1겹, 모두 보이기에서 최대 182개면 3겹.
5. 반지름 `R2 = max(R1o + 150, (n2 / 겹수) × 16 / 2π)`, `R2o = R2 + (겹수 - 1) × 24`.
6. 숨긴 후보가 있으면 꼭대기에 `reserve = min(0.5, 70 / R2)` rad를 비워 "+k" 자리를 만든다.
7. 크기 상한은 `0.4 × (2π R2 - 70) / (n2 / 겹수)`. 카테고리 호 반지름은 `R2 - 26`.
8. 바깥 궤도 노드 알파는 0.62.

### 4.4 궤도 엣지

세 종류만 그린다: 중심에서 1-hop으로 가는 바큇살, 1-hop끼리의 곡선 현(제어점은 두 노드 중점을 중심 쪽으로 30%), 1-hop 부모에서 2-hop으로 가는 선. 2-hop끼리, 2-hop과 배경 노드 사이 엣지는 그리지 않는다.

### 4.5 큰 허브 (degree 118)

측정값 (1.6절): 1-hop 118개가 3겹, `R1` 131.5, `R1o` 179.5, 칸 호 길이 21 world, 크기 상한 8.4 world. 2-hop 후보 63개 중 28개를 두고 35개는 "+k". `R2` 329.5, 화면 맞춤 범위 `R2o + 130 = 459.5`.

- 라벨은 약 40개만 붙는다 (시안 F 검증값). 1-hop이 40개를 넘으면 패널 이웃 목록 첫머리에 "이웃이 많아 궤도에는 라벨을 일부만 적는다. 전체는 이 목록에 있다" 를 적는다.
- 3겹 지그재그로 노드가 서로 겹치지 않는다. 더 큰 허브(이웃 135개 이상)가 생기면 3겹에서도 칸이 21 world를 넘도록 `R1` 이 커진다 (4.2절 4번 식이 자동으로 처리한다).

### 4.6 "+k"

- 2-hop 후보가 28개를 넘는 노드가 310 / 344라 거의 모든 선택에서 나타난다.
- 자리: 중심 바로 위 `(C.x, C.y - R2)`. 4.3절 6번의 빈 틈이다.
- 알약 상자(글자 폭 + 14px, 높이 20px)가 궤도 노드 원(`nodeR × 1.08 + 4px`, 중심은 `+ 12px`)에 닿으면 그리지 않고 누를 수도 없다. 줌을 많이 줄이면 이렇게 된다.
- 충돌 검사를 건너뛰는 호버 라벨이 알약에 닿으면 알약을 내린다.
- 숫자와 "모두 보이기" 는 패널 본문에 늘 있다. 펼치면 알약 글자는 "접기" 다.

### 4.7 궤도 라벨

모두 가로로 쓴다 (1409 ~ 1510행).

| 자리 | 배치 | 최대 폭 |
|---|---|---|
| 옆 호 (`|cos θ| ≥ 0.4`), 1-hop | 바깥 겹 밖 `max(노드 거리 + r + 5, R1o × k + 8)` 에서 바깥쪽으로 | `(R2 - R1o) × k / max(0.6, |cos θ|) - 22`, 40 ~ 170px |
| 옆 호, 2-hop | 노드 밖 `r + 5` 에서 바깥쪽으로 | 150px |
| 위아래 호, 1-hop | 노드 위나 아래 가운데, `r + 글자/2 + 5` | 120px |
| 위아래 호, 2-hop | 그리지 않는다 (패널이 맡는다) | |
| 호버 노드 | 위 규칙의 자리, 충돌 검사 건너뜀 | 최소 200px |

- 우선순위: 호버 노드, 호버 노드의 이웃, 1-hop, degree.
- 탐욕적으로 하나씩 놓고 크롬, 이미 놓은 라벨, 다른 궤도 노드 원, 알약과 겹치면 뺀다. 1-hop 최대 64개, 2-hop 최대 18개.
- 노드 전환이 85% 넘게 진행된 뒤에 나타난다 (`lt > 0.85`).
- 글자가 넘치면 `…` 로 줄이고, 8자보다 짧아지면 라벨을 뺀다. 결과는 `(글꼴, 폭/8, 문자열)` 키로 캐시한다.
- 중심 라벨은 노드 아래 15px 굵게. 줄 폭을 안쪽 궤도 안쪽 원의 현 길이로 막는다 (안쪽 원 반지름 `min(R1 × k - 최대 노드 반지름 - 6, (R1 - 16) × k - 5)`). 전체 제목이 두 줄에 들어가면 두 줄, 아니면 짧은 이름 한 줄, 그 현도 16px보다 좁으면 생략한다.

## 5. 라벨 표시 규칙 (성도)

### 5.1 노드 라벨

| 줌 배율 k | degree 하한 | 해당 노드 수 (스냅샷) |
|---|---|---|
| 0.8 미만 | 50 | 5 |
| 0.8 ~ 1.4 | 25 | 30 |
| 1.4 ~ 2.2 | 10 | 163 |
| 2.2 이상 | 0 | 344 |

- 하한을 무시하고 늘 후보가 되는 노드: 호버 노드, 검색 결과 상위 40개, 호버 노드의 이웃 중 degree 10 이상.
- 필터에 걸러진 노드와 흐림(`emph < 0.9`) 노드는 빠진다 (강제 후보 제외).
- 화면 밖 20px 넘는 노드는 뺀다.
- 우선순위 `호버 1e6 + 검색 1e5 + 강제 1e4 + degree` 순으로 탐욕 배치, 크롬과 성운 이름과 앞 라벨에 겹치면 뺀다 (호버는 겹쳐도 그린다). 최대 160개.
- 자리: 노드 중심에서 `(gap × 0.92, -gap × 0.62)`, `gap = 화면 반지름 + 고리 여유(overviews 6, 나머지 4) + 3`. 오른쪽 끝을 넘으면 왼쪽으로 뒤집는다.
- 글꼴: degree 50 이상과 호버 13px 700, 15 ~ 49 12px, 14 이하 11px muted.
- 첫 등장 600ms 동안은 라벨을 그리지 않는다.

처음 맞춤 배율은 1440 × 900에서 약 0.90(하한 25, 후보 30개), 375 × 812 세로에서 약 0.37(하한 50, 후보 5개)이다 (계산값).

### 5.2 성운 이름

1. 카테고리마다 home 좌표의 x, y 중앙값을 중심으로, 최소 최대를 외곽 상자로 둔다 (`CAT_INFO`, 498 ~ 503행). overviews와 노드 5개 미만 카테고리는 이름이 없다.
2. 글꼴: 노드 60개 넘는 성운 15px, 나머지 13px (모바일 13px, 11px). 자간 0.16em (모바일 0.1em).
3. 후보 11자리를 순서대로 본다: 외곽 위 18px, 아래 18px, 위 40px, 아래 40px, 위 왼쪽, 위 오른쪽, 왼쪽 옆, 오른쪽 옆, 아래 왼쪽, 아래 오른쪽, 성운 중앙.
4. 자리가 비었다는 조건: 화면 안 4px, 모든 노드 원(`r√k + 4`)과 크롬과 이미 놓은 이름에 닿지 않는다.
5. 11자리가 모두 막히면 외곽 타원을 8px씩 최대 160px까지 넓히며 24방향을 본다. 찾으면 0.8px 지시선을 이름 상자에서 가장 가까운 제 성운 노드까지 긋는다.
6. 그래도 없으면 그리지 않는다.
7. 알파: `clamp((1.7 - k) / 0.5)` 로 k 1.2 이하에서 완전히, 1.7 이상에서 사라진다. 궤도 전환이 1/3 진행되면 사라진다.

성능 변경 (L9): 시안은 이 탐색을 매 프레임 돌린다. 최악 344노드 0.8ms, 1,032노드 5.5ms다 (1.6절). 실제 구현은 카메라(`x, y, k`), 화면 크기, 필터, 크롬 상자가 같으면 지난 결과를 다시 쓴다. 카메라가 움직이는 프레임(팬, 줌, 비행 중)에는 지난 자리를 유지하고, 움직임이 멈춘 프레임에 다시 찾는다.

## 6. 조감과 궤도 전환

### 6.1 대상 좌표

- 궤도 중심 `C` 는 고른 노드의 home 좌표다. 중심 노드는 움직이지 않는다.
- 궤도 노드의 목표: `C + (cos θ, sin θ) × rad`. 나머지 노드의 목표는 home, 알파는 `--f-backdrop-alpha` (dark 0.16, light 0.2).
- 성도로 나갈 때 모든 노드의 목표는 home, 알파 1.

### 6.2 보간

| 종류 | 위치 보간 | 시간 | 이징 | 노드별 지연 |
|---|---|---|---|---|
| 들어가기 | 직선 | 640ms | easeInOutCubic | 1-hop `40 + 160 × frac(θ)`, 2-hop `200 + 160 × frac(θ)` ms. `frac` 은 꼭대기에서 시계 방향 비율 |
| 나가기 | 직선 | 640ms | easeInOutCubic | 2-hop 0, 1-hop `60 + 120 × frac`, 그 밖 140ms |
| 중심 옮기기, 모두 보이기 | 이전과 새 위치가 모두 궤도 위이고 중심에서 24 world 넘게 떨어졌으면 극좌표(반지름 선형, 각도 최단 방향), 아니면 직선 | 600ms | 4차 ease-out | 없음 |

- 궤도 층(렌즈, 안내선, 호, 엣지)의 섞임 `orbitMix` 는 들어가기 760ms, 나가기 640ms, 옮기기 600ms에 easeInOutCubic.
- 중심을 옮길 때는 이전 궤도 층과 새 층을 600ms 교차 페이드한다.
- 안내선과 카테고리 호는 꼭대기에서 시작해 80ms 지연 뒤 760ms에 원을 그리며 나타난다.

### 6.3 카메라

- 비행은 화면 중앙 기준 세계 좌표를 선형, 배율을 `log k` 로 보간하고 4차 ease-out을 쓴다. 기본 480ms, 들어가기 720ms, 나가기 640ms, 옮기기 600ms, 시트 접기 펼치기 360ms.
- 들어가기 직전 카메라를 `atlasCam` 에 저장하고 나갈 때 그리로 돌아간다. 저장된 것이 없으면(딥링크로 시작) `fitTarget(nodes)` 로 간다.
- 궤도 카메라 (`orbitCam`, 711 ~ 718행):
  - 데스크톱: 위 112px, 아래 20px, 왼쪽 16px, 오른쪽 패널 자리 392px를 뺀 영역에 `extent = R2o + 130` (2-hop이 없으면 `R1o + 130`) 반지름이 들어가게 한다.
  - 모바일: 위 104px, 아래 시트 높이 + 58px (시트를 펼치면 범례가 숨어 + 20px), `extent = R2o + 36`.
  - 배율은 0.2 ~ 1.6으로 막는다.
  - 위 값들은 시안 F 기준이다. 사이트에서는 무대가 공용 헤더 뒤까지 깔리므로(01 11절 M1 결정) 위쪽 여유에 헤더 높이를 더하고, 숫자 대신 크롬 장애물 상자에서 구한다 (01 2.2절, 5.2절, 5.4절, 10절).

### 6.4 전환 중 입력

- 새 전환은 언제나 각 노드의 **현재** 위치와 알파에서 출발한다 (`setTargets` 가 `n.x, n.y, n.p` 를 출발점으로 잡는다). 그래서 들어가는 중에 다른 노드를 고르거나, 옮기는 중에 또 옮겨도 튀지 않는다.
- 카메라 비행도 현재 카메라에서 다시 출발한다.
- 전환 중에는 마우스 호버 판정을 끈다. 클릭과 탭은 받고, 그 시점의 화면 위치로 판정한다.
- 팬, 핀치, 휠이 시작되면 진행 중인 카메라 비행을 멈춘다. 노드 전환은 계속된다.
- **시안 결함 수정**: 나가는 전환(카메라가 `atlasCam` 으로 비행 중)에 노드를 누르면 시안은 비행 중간 카메라를 `atlasCam` 으로 덮어쓴다. 다음에 나갈 때 원래 개요 화면으로 돌아오지 않는다. 구현은 나가기 비행이 진행 중이면 그 목표 카메라를 `atlasCam` 으로 저장한다.
- 딥링크 시작은 전환 없이 궤도를 한 프레임에 연다 (`instant`).
- reduced-motion은 모든 전환과 비행을 한 프레임에 끝낸다.

## 7. 뷰포트

### 7.1 화면 맞춤

`fitTarget(list)`: 대상 노드의 home 좌표와 `r` 로 외곽을 잡고, 여백 `min(w, h) × 0.06` 을 둔 영역에 맞춘다. 배율은 0.2 ~ 2.4. 모바일은 위 60px(사이트에서는 헤더 높이를 더한다, 01 5.4절), 아래 56px를 뺀 영역이다. 처음 화면(전체), "화면 맞춤" 버튼과 성도 화면 더블클릭(둘 다 필터가 있으면 걸러진 노드만, 02 3.4절)이 쓴다. 궤도 화면 더블클릭은 `orbitCam` 으로 간다.

줌 범위는 0.2 ~ 6이다.

### 7.2 리사이즈

- 캔버스 크기와 dpr(최대 2)을 다시 잡고 배경을 다시 그린다.
- 궤도 화면: `orbitCam` 을 즉시 다시 계산한다 (비행 없이).
- 성도 화면: 카메라 중심을 크기 변화의 절반만큼 옮겨 같은 곳을 화면 가운데에 둔다. 사용자가 확대하거나 옮겼으면 다시 맞추지 않고, 마지막 화면 맞춤 그대로면 새 크기에 다시 맞춘다 (2026-11-25, 노드가 크롬 밑에 깔리지 않게). 세로 기준을 넘으면 3.4절.
- 크롬 상자 캐시(9절)를 비운다.

### 7.3 필터

배치를 다시 계산하지 않는다 (L7). 근거는 두 가지다. 노드가 자리를 옮기면 사용자가 익힌 지도가 깨지고, 굽기 방식에서는 브라우저에 force 엔진이 없다.

- 성도: 걸러진 카테고리 밖 노드는 알파 `--graph-dim-alpha`. 엣지는 두 번 그린다 (양 끝이 모두 필터 안이면 알파 × 1.5, 아니면 × 0.22). 성운 안개는 55%, 걸러진 성운 이름은 25%.
- 궤도: 궤도 구성은 그대로 두고 필터 밖 궤도 노드를 흐리게, 그 엣지를 25%로, 호를 `dim-alpha` 로 낮춘다.
- 검색으로 필터 밖 노드를 고르면 그 노드를 막던 축만 푼다 (02 7.5절).

## 8. 히트 테스트

선형 탐색을 쓴다 (L8). 모든 노드에 대해 `화면 거리 - 화면 반지름` 이 여유(마우스 4px, 터치 12px)보다 작은 것 중 가장 가까운 것을 고른다. 궤도 화면에서는 배경 노드(`role < 0`)와 알파 0.3 미만 노드를 건너뛴다.

344노드 1.6µs, 2,064노드 12µs라 pointermove마다 돌려도 된다. 노드가 5,000개를 넘거나 한 번에 0.1ms를 넘으면 quadtree로 바꾼다.

## 9. 성능 예산

목표는 60Hz 화면에서 프레임 간격 16.7ms 유지, 그리기 자체는 데스크톱 8ms 이하다. 그리기 시간은 이 작업에서 재지 않았다 (미측정). 근거로 쓸 수 있는 실측은 시안 F 검증의 프레임 간격(실제 GPU M5에서 전환, 줌, 팬 p50 16.7ms, p95 17.7ms 이하, CPU 4배 감속에서 프레임 누락 0)뿐이다. Phase 4에서 `drawTimes` 같은 계측을 남겨 p95를 잰다.

프레임당 비용 상한 (344노드 기준):

| 항목 | 상한 |
|---|---|
| 배경 | `drawImage` 1번, 별먼지 패턴 `fillRect` 1번 |
| 성운 안개 | `drawImage` 1번 (저해상도 오프스크린, 배율 0.25) |
| 엣지 | 묶음 9개 `stroke` 9번. 필터 중에는 최대 18번 |
| 강조 엣지 | 선형 그라데이션 최대 118개 (호버한 허브) |
| 노드 | 노드마다 `drawImage` 2 ~ 4번 (빛번짐, 구, 허브 반짝임). 화면 밖 60px 넘으면 건너뜀 |
| 라벨 | 성도 최대 160개, 궤도 최대 64 + 18 + 중심 2줄. `measureText` 는 캐시 |
| 성운 이름 | 카메라가 멈췄을 때만 다시 찾는다 (5.2절) |
| 궤도 반짝임 | 1-hop 수만큼 그라데이션, 선택 뒤 7초만 |

시안에서 고칠 것:

- `chromeRects()` 는 `getBoundingClientRect` 를 요소 5 ~ 6개에 부르며 매 프레임 두세 번 불린다 (성운 이름, 성도 라벨, 궤도 라벨). 리사이즈, 패널 열기 닫기, 시트 토글, 검색 결과 변화 때만 다시 읽고 캐시한다.
- rAF는 전환, 비행, 흐림 보간, 호버 들림, 맥박, 반짝임 중 하나라도 진행 중일 때만 돈다 (시안 그대로).

## 11. 개선 제안

이 절은 확정된 설계가 아니다. Phase 4, 5 구현 때 비용이 적은 것부터 골라 넣는다.

- **들어가기 이동 거리 줄이기.** 1-hop 궤도의 시작 각도를 고정 꼭대기 대신, 각 노드의 home 방향과 궤도 각도 차이 합이 가장 작은 회전으로 고른다 (36가지 회전을 시험, 노드당 수십 µs). 노드가 성운 쪽에서 가까운 궤도 자리로 날아와 전환이 덜 엉킨다. 다만 "+k" 자리가 꼭대기를 전제하므로 2-hop은 지금처럼 둔다. 효과는 미측정.
- **앵커 배율.** 노드가 1,000개 근처로 늘면 앵커 표를 `√(N / 344)` 배로 넓힌다. 같은 앵커로 1,032노드를 돌린 품질 지표는 재지 않았다.
- **빌드 점검에 화면 겹침 추가.** 3.3절 자체 점검에 "k 0.37에서 화면 겹친 쌍 0" 을 넣으면 앵커나 반지름을 고칠 때 휴대폰 겹침 회귀를 빌드가 잡는다 (1.5절 계산이 그대로 쓰인다).
- **미니 이웃 그래프 (Phase 5).** 4.2절의 정렬과 각도 규칙을 쓰면 force 없이 결정적인 1-hop 그림을 빌드 타임 SVG로 만들 수 있다. 344페이지 × 0.03ms라 빌드 비용이 거의 없다. 겹 대신 24개 상한과 "+k", 원 대신 타원에 그리는 세부는 06 5.2절이 정본이다.
