# 02. 인터랙션 명세

작성일 2026-11-17. `docs/graph-design-plan.md` Phase 2의 "인터랙션 명세 (마우스, 터치, 키보드 각각)" 산출물이다. 정본 시안은 `docs/graph-mockups/f-atlas-orbit.html` (이하 시안 F)이고 이 문서의 행 번호는 그 파일 기준이다. 영역 이름과 상태 이름은 `01-layout.md`, 전환 시간과 배치 상수는 `04-layout-algorithm.md` 를 따른다. 시각 규칙(색, 스프라이트)은 다루지 않는다.

구현자는 1 ~ 11절로 이벤트 처리를 짜고, 검증자는 13절 체크리스트로 테스트 항목을 뽑는다. "시안" 이라고 적은 값은 시안 F 코드에서 읽은 값이고, "새로" 라고 적은 값은 이 문서가 정한 값이다.

## 1. 용어

| 용어 | 뜻 |
|---|---|
| 조감 | `data-mode='atlas'`. 성도 배치 전체 화면 |
| 궤도 | `data-mode='orbit'`. 고른 노드(중심)를 가운데 두고 1-hop, 2-hop을 동심원에 놓은 화면 |
| 커서 | 궤도에서 키보드로 가리키는 노드. 시안 변수 `focused`. DOM 초점과 다르다 |
| 호버 | 마우스가 올라간 노드. 시안 변수 `hovered` |
| 비행 | 카메라 보간 (`flyTo`). 노드 위치 보간(전환, 시안 `morph`)과 따로 돈다 |

## 2. 상태 기계

### 2.1 상태 영역

상태는 서로 독립인 영역 여섯 개로 나눈다. 한 영역의 전이가 다른 영역을 바꿀 때는 전이 표의 "동작" 열에 적는다.

| 영역 | 상태 | 저장 위치 |
|---|---|---|
| A. 판 | `list`, `map` | `main.graph[data-view]` |
| B. 지도 모드 | `atlas`, `entering`, `orbit`, `recentering`, `exiting` | `.graph-stage[data-mode]` 는 `atlas` 또는 `orbit` 만 쓴다. 전환 중 여부는 내부 변수 (`morph.kind`) |
| C. 지시 | `none`, `hover(node)`, `hover(plus)`, `hover(legend:cat)`, `hover(list:node)`, `cursor(node)` | 내부 변수 |
| D. 덮개 | `none`, `search`, `filter` | 검색 결과 목록 열림, 필터 팝오버 `hidden` |
| E. 시트 (모바일 궤도만) | `hidden`, `peek`, `full`, `dragging` | `.graph-panel.is-peek`, `.graph-stage.is-sheet-full` |
| F. 제스처 | `idle`, `pressed`, `panning`, `pinching` | 내부 변수 (`pointers`, `gesture`) |

`entering`, `recentering`, `exiting` 은 "선택 전환 중" 과 "복귀 전환 중" 이다. 노드 전환(640ms 안팎, 지연 포함 최대 약 1,000ms)이 끝나면 각각 `orbit`, `orbit`, `atlas` 로 바뀐다. 카메라 비행은 노드 전환과 따로 끝난다.

### 2.3 궤도 나가기 `exitOrbit`

1. 지금 history 항목이 이 탐색기가 `pushState` 한 궤도 항목(`state.graph === 'orbit'`)이면 `history.back()` 만 부르고 끝낸다. `popstate` 가 다시 `exitOrbit({ fromHistory: true })` 를 부른다 (시안 932행).
2. 그렇지 않으면(딥링크로 들어온 첫 항목 등) `replaceState` 로 hash에서 `node` 만 지운다. 필터 키는 남긴다.
3. 패널을 닫고 경로 줄을 숨기고 필터 칩 줄을 다시 보인다 (01 6절).
4. 노드 전환 `exit` 640ms, 비행 640ms로 `atlasCam` 에. 없으면 `fitTarget(필터 안 노드)`.
5. 커서와 호버를 지우고 툴팁을 숨긴다. 알림 "전체 보기".
6. DOM 초점이 패널 안에 있었으면 캔버스로 옮긴다 (시안 1602, 1603행).

### 2.4 전환 중 입력

04 6.4절을 그대로 따르고 아래를 더한다.

| 입력 | 전환 중 처리 |
|---|---|
| 탭, 클릭 | 받는다. 그 프레임의 화면 위치로 히트 테스트한다. 새 전환은 각 노드의 현재 위치에서 출발한다 |
| 마우스 호버 | 끈다 (시안 1683행 `morph ? null`). 커서 모양은 `grab` |
| 키보드 커서 이동 | 받는다. 새 배치(`view`) 기준이라 노드가 아직 날아가는 중이어도 대상은 맞다 |
| 팬, 핀치, 휠 | 카메라 비행만 멈춘다. 노드 전환은 계속한다 |
| Esc, 뒤로 가기 | 받는다. `exit` 전환이 현재 위치에서 출발한다 |
| 검색 입력, 필터 변경 | 받는다. 흐림 보간(약 160ms)이 따로 돈다 |

### 2.5 복귀 카메라 규칙 (시안 결함 수정)

시안 897행은 조감에서 들어갈 때마다 그 순간의 카메라를 `atlasCam` 으로 저장한다. 나가는 비행 중에 노드를 누르면 비행 중간 카메라가 저장되어, 다음에 나갈 때 원래 화면으로 돌아오지 않는다.

들어갈 때 `atlasCam` 을 아래 순서로 정한다.

1. 나가는 비행이 아직 진행 중이면 그 비행의 목표 카메라.
2. 나가는 비행이 사용자 팬, 핀치, 휠로 멈췄으면 현재 카메라 (사용자가 일부러 옮긴 자리다).
3. 그 밖에는 현재 카메라.

구현은 `flight` 객체에 `kind: 'exit'` 와 목표 `to` 를 두고, 사용자 입력이 비행을 멈출 때 `flight = null` 로 지우는 것으로 충분하다. 1번은 `flight && flight.kind === 'exit'` 이다.

### 2.6 D 영역 (덮개)

| 현재 | 사건 | 동작 | 다음 |
|---|---|---|---|
| `none` | 검색 입력에 초점 + 글자 있음 | 결과 목록 열기 | `search` |
| `search` | 입력이 비거나 초점이 입력과 목록 밖으로 | 결과 목록 닫기 (글자는 남긴다) | `none` |

## 3. 카메라

### 3.1 상수

| 이름 | 값 | 출처 |
|---|---|---|
| `K_MIN`, `K_MAX` | 0.20, 6.00 | 시안 519행 |
| 맞춤 배율 범위 | 0.20 ~ 2.40 | 시안 707행 |
| 궤도 배율 범위 | 0.20 ~ 1.60 | 시안 716행 |
| 휠 계수 | 0.0018, `ctrlKey` 0.01 | 시안 1713행 |
| 버튼과 키 줌 배율 | 1.5 | 01 5.6절 |
| 비행 이징 | 4차 ease-out `1 - (1 - t)^4` | 시안 734행 |
| 비행 시간 | 기본 480 (`--dur-camera`), 들어가기 720, 나가기 640, 옮기기 600, 시트 360 | 04 6.3절 |

### 3.2 줌 기준점

| 입력 | 기준점 |
|---|---|
| 휠 | 커서 위치. 그 아래 world 점이 화면에서 움직이지 않는다 (`camFor`) |
| 핀치 | 두 손가락 중점. 중점이 움직이면 함께 팬한다 (시안 1672행) |
| 버튼, `+` `-` 키 | 사용 영역 중앙. 조감은 `atlasRect` 중앙, 궤도는 `orbitCam` 사용 영역 중앙 |

버튼과 키 줌은 비행(480ms)이다. 비행 중에 또 누르면 현재 비행의 목표 배율에 1.5배를 곱한다. 세 번 빠르게 누르면 3.375배가 된다. `K_MIN` 이나 `K_MAX` 에 닿으면 해당 버튼에 `aria-disabled="true"` 를 걸고 누르면 아무것도 하지 않는다.

### 3.3 휠 정규화 (새로)

시안은 `deltaMode` 를 보지 않는다. 줄 단위(`deltaMode === 1`, Firefox의 일부 마우스)면 `deltaY × 16`, 쪽 단위(`2`)면 `deltaY × 캔버스 높이` 로 픽셀로 바꾼 뒤 계수를 곱한다. 한 이벤트의 배율 변화는 0.5 ~ 2.0배로 자른다. 휠은 비행을 멈춘다 (시안 1711행).

### 3.4 맞춤

| 상황 | 대상 |
|---|---|
| 조감 "화면 맞춤" 버튼, `0` 키, 빈 곳 두 번 누르기 | `fitTarget(필터 안 노드)`. 필터 안 노드가 0개면 전체 |
| 궤도 `0` 키, 빈 곳 두 번 누르기 | `orbitCam(view)` |
| 처음 화면 | `fitTarget(전체)`. 필터 hash로 시작해도 전체를 보여 준다 (지형을 먼저 보인다) |

시안의 더블클릭(1720행)은 전체 노드에 맞추고 맞춤 버튼(1819행)은 필터 안 노드에 맞춰 서로 달랐다. 둘 다 필터 안 노드로 통일한다.

## 4. 마우스

### 4.1 공통 규칙

- `pointerdown` 에서 `button !== 0` 이면 무시한다 (새로). 시안은 버튼을 보지 않아 오른쪽 버튼으로도 팬과 선택이 되었다. 오른쪽 클릭은 브라우저 기본 메뉴를 그대로 둔다. 가운데 버튼도 무시한다.
- `pointerdown` 에서 `setPointerCapture` (시안 1653행). 캔버스 밖으로 끌어도 팬이 이어진다.
- 시안 1656행은 `pointerdown` 에서 비행을 멈춘다. 그러면 비행 중 탭 한 번에 카메라가 어중간한 자리에 멈춘다. 비행은 이동이 탭 경계를 넘어 팬이 될 때 멈춘다 (새로, 04 6.4절 "팬이 시작되면" 과 같다).
- `lostpointercapture` 와 `pointercancel` 은 제스처를 탭 판정 없이 끝낸다.

### 4.2 동작 표

| 입력 | 조감 | 궤도 | 비고 |
|---|---|---|---|
| 노드 위로 이동 | 호버: 노드와 이웃 엣지 강조, 라벨 강제, 툴팁 (6.2절), 커서 `pointer` | 같다. 툴팁에 관계("중심", "이웃", "두 다리 건너") 추가 (시안 1727행) | 전환 중에는 판정하지 않는다. 히트 여유 4px |

### 4.3 두 번 누르기 판정 (새로)

`dblclick` 대신 `pointerup` 에서 직접 판정한다. 마우스, 터치, 펜에 같은 규칙을 쓰기 위해서다.

- 앞선 탭과 시간 간격 300ms 이하, 거리 24px 이하, 같은 `pointerType`.
- 두 탭 모두 빈 곳이어야 맞춤을 한다. 하나라도 노드에 맞았으면 각 탭을 단일 탭으로만 처리한다.
- 단일 탭 동작을 300ms 늦추지 않는다. 빈 곳 단일 탭은 커서 지우기뿐이라 겹쳐도 해가 없다.

## 5. 터치

### 5.1 `touch-action` 과 스크롤 충돌

| 요소 | 값 | 이유 |
|---|---|---|
| `.graph-stage` | `touch-action: none` (01 2.2절, 시안 `mock-base.css` 234행) | 팬과 핀치를 스크립트가 받는다. 지도 판은 문서 스크롤이 없다 (`overflow: hidden`) |
| `.graph-panel-body`, `.graph-results`, `.graph-filters` 본문 | `touch-action: pan-y; overscroll-behavior: contain` (새로) | 무대 안에서도 목록은 세로로 스크롤해야 한다. 끝에 닿은 스크롤이 무대로 새지 않게 한다 |
| 시트 손잡이 `.graph-sheet-grip` | `touch-action: none` | 끌기를 스크립트가 받는다 |
| 경로 줄 `.graph-trail` | `touch-action: pan-x` | 가로로 넘치는 경로를 밀어 본다 |
| 무대 전체 | `-webkit-touch-callout: none; user-select: none` (캔버스와 범례) | 길게 누를 때 확대경과 선택 메뉴가 뜨지 않게 한다 |
| 목록 판 | 기본값 | 보통 문서처럼 스크롤 |

iOS Safari의 페이지 확대(두 손가락)가 `touch-action: none` 으로 막히는지는 미확인이다. 막히지 않으면 무대에서 `gesturestart` 의 기본 동작을 막는다. Phase 6 실기기 항목이다.

| 범례 견본 탭 | 카테고리 토글. 모바일에서 누른 견본은 이름을 펼친다 (01 5.4절) | 같다 | 미리 강조는 없다 |

### 5.3 시트 끌기 (새로)

01 12절 I5의 손잡이를 기본 동작으로 넣는다. 사용자가 손 제스처를 기대하는 자리이고 코드가 작다.

- 손잡이는 시트 머리 맨 위 36 × 4px 막대, 누를 수 있는 영역은 높이 24px 전체 폭이다. 시트 머리의 제목 줄도 끌기 영역에 넣는다. 본문 목록은 넣지 않는다 (목록 스크롤과 다투지 않게).
- 끄는 동안 시트 높이를 손가락에 그대로 따르게 하고 `--graph-sheet` 를 매 프레임 갱신한다. 궤도 카메라는 끄는 동안 다시 맞추지 않는다.
- 놓을 때: 마지막 100ms 속도가 0.5px/ms 넘게 위면 `full`, 아래면 `peek`. 그보다 느리면 두 멈춤점 중 가까운 쪽. 이어서 높이 전환 240ms `--ease-out` 과 궤도 비행 360ms.
- 손잡이 탭(이동 8px 이하)은 토글이다. 키보드와 스크린 리더는 "이웃 N개" 버튼을 쓴다.

## 6. 키보드

### 6.1 Tab 순서

01 9.2절을 그대로 쓴다. 공용 건너뛰기 링크, 공용 헤더, `.graph-skip`, 검색 입력, 필터 버튼, (열린) 필터 팝오버, 필터 칩 줄 또는 경로 줄, 캔버스, (궤도) 상세 패널, 범례 견본 8개와 필터 해제, 도구 묶음 순이다. 숨긴 영역은 `hidden` 이나 `inert` 라 순서에 들지 않는다 (01 9.3절).

### 6.2 전역 키

문서 `keydown` 하나에서 받는다. 아래 경우에는 처리하지 않는다.

- `e.isComposing` 이 참이거나 `keyCode === 229` (한글 조합 중).
- `ctrlKey`, `metaKey`, `altKey` 중 하나라도 눌림 (6.5절 예외 제외). 브라우저 단축키를 가로채지 않는다.
- 초점이 텍스트 입력(`input`, `textarea`, `[contenteditable]`)에 있을 때. 그 입력이 자기 키를 처리한다 (시안 1756행).

| 키 | 초점 조건 | 동작 |
|---|---|---|
| `/` | 텍스트 입력 밖 어디든 | 검색 입력에 초점, 기존 글자 전체 선택 (시안 1757행에 선택 추가) |
| `Esc` | 텍스트 입력 밖 어디든 | 6.4절 단계 |
| 그 밖 6.3절 키 | 캔버스 또는 `body` | 6.3절 |

### 6.3 캔버스 키

| 키 | 조감 | 궤도 |
|---|---|---|
| `←` `→` `↑` `↓` | 필터 안 최대 허브로 궤도를 연다 (2.2절). 시안 1766행은 필터를 보지 않고 `rank[0]` 이었다 | 6.4절 이웃 이동 |
| `Shift` + 방향키 | 사용 영역 폭의 10%만큼 팬 (새로). 비행 없이 즉시 | 같다 |
| `Enter` | 방향키와 같다 | 커서가 있고 중심이 아니면 중심 옮기기. 커서가 없거나 중심이면 그 페이지를 연다 (같은 탭, 시안 1786행) |
| `Ctrl` / `Cmd` + `Enter` | 해당 없음 | 커서 노드(없으면 중심)의 페이지를 새 탭에서 연다 (새로) |
| `Space` | 묶지 않는다 | 커서가 있으면 중심 옮기기 (페이지는 열지 않는다). 없으면 무동작 |
| `Backspace` | 무동작 | 경로를 한 칸 되돌린다. 경로가 1개면 궤도를 나간다 (시안 944행) |
| `+`, `=` | 1.5배 확대 비행 | 같다 |
| `-`, `_` | 1.5배 축소 비행 | 같다 |
| `0` | 필터 안 노드 맞춤 | `orbitCam` |
| `Home` / `End` | 무동작 | 커서를 안쪽 궤도 첫 노드 / 끝 노드로 (새로) |

방향키, `Enter`, `Space`, `Backspace`, `+`, `-`, `0` 은 처리할 때 `preventDefault` 한다.

### 6.4 궤도 방향키 규칙

시안 1770 ~ 1787행을 그대로 쓴다. "목록 순서" 는 궤도 배치 정렬 순서(04 4.2, 4.3절)이고 꼭대기에서 시계 방향 각도 순과 같다. 여러 겹 궤도에서도 목록 순서가 각도 순이라 지그재그 겹을 따라 이웃한 각도로 움직인다.

| 커서 위치 | `→` | `←` | `↓` | `↑` |
|---|---|---|---|---|
| 없음 (중심) | 안쪽 궤도 첫 노드 (꼭대기 바로 오른쪽) | 안쪽 궤도 끝 노드 (꼭대기 바로 왼쪽) | 안쪽 궤도에서 각도 π/2(맨 아래)에 가장 가까운 노드 | 무동작 |
| 안쪽 궤도 | 목록 다음 (시계 방향), 끝에서 처음으로 돈다 | 목록 이전, 처음에서 끝으로 | 바깥 궤도에서 각도가 가장 가까운 노드. 바깥 궤도가 비었으면 무동작 | 커서를 지운다 (중심으로) |
| 바깥 궤도 | 바깥 목록 다음 | 바깥 목록 이전 | 무동작 | 안쪽 궤도에서 각도가 가장 가까운 노드 |

- 각도 거리는 원형 최소 차 `|((a - b) mod 2π + 3π) mod 2π - π|` 이다 (시안 1744행). 같으면 목록 앞쪽.
- 커서를 옮기면 호버를 지우고, 툴팁을 커서 노드에 붙이고, 알린다 (9.2절).
- 커서 노드가 필터 밖이어도 건너뛰지 않는다. 흐린 노드도 궤도 구성원이다.
- 펼침을 토글하거나 중심을 옮기면 커서를 지운다 (시안 920행).
- 커서 노드가 화면 밖이면 그 노드가 사용 영역 안에 들어오도록 최소 거리 비행(240ms)을 한다 (새로). 줌을 크게 키운 상태에서 키보드 사용자가 길을 잃지 않게 한다.

### 6.5 Esc 단계

한 번 누를 때 아래에서 처음 해당하는 하나만 한다.

| 순서 | 조건 | 동작 | 초점 |
|---|---|---|---|
| 1 | 검색 입력에 초점 | 글자를 지우고 결과를 닫는다 (시안 1863행) | 캔버스로 |
| 2 | 태그 자동완성 입력에 초점, 제안 목록 열림 | 제안 목록만 닫는다 | 그대로 |
| 3 | 필터 팝오버 열림 | 닫는다 | 필터 버튼으로 |
| 4 | 모바일 시트 `full` | `peek` 로 접는다. 초점이 시트 본문에 있으면 펼침 버튼으로 옮긴다 (2026-11-25) | 초점 이동 추가 |
| 5 | 궤도, 커서 있음 | 커서를 지운다 (시안 1760행) | 그대로 |
| 6 | 궤도 | 궤도를 나간다 | 패널 안이었으면 캔버스로 |
| 7 | 조감, 카테고리 필터 켜짐 | 카테고리 필터만 푼다 (시안 1761행, 범례 "필터 해제" 와 같은 범위) | 그대로 |
| 8 | 그 밖 | 무동작 | |

유형과 태그 필터는 Esc로 풀지 않는다. 입력해서 고른 태그를 키 하나로 잃지 않게 한다.

### 6.6 패널, 범례, 경로 줄의 키

| 요소 | 키 | 동작 |
|---|---|---|
| 이웃 목록 행 (`button`) | `Enter`, `Space` | 그 노드로 중심 옮기기, 초점을 캔버스로 (시안 1610행) |
| 이웃 목록 행 | `↑` `↓` | 이전, 다음 행으로 초점 (새로). Tab은 목록을 한 번에 건너뛰도록 목록 첫 행만 `tabindex="0"`, 나머지는 `-1` (roving tabindex) |

| 경로 버튼 | `Enter` | 그 노드로 되돌아가기 |
| 필터 팝오버 칩 | `Enter`, `Space` | 토글 |

## 7. 검색

### 7.1 입력 처리

- 디바운스 없음. `input` 이벤트마다 바로 계산한다 (시안 1856행). 344노드 선형 탐색이라 1ms 미만이다 (미측정, 04 1.6절 히트 테스트 규모로 추정). 노드가 2,000개를 넘거나 한 번에 4ms를 넘으면 80ms 디바운스를 건다.
- 한글 조합 중에도 계산한다. 조합 중인 음절도 `input.value` 에 들어 있어 "로봇" 을 치는 동안 "로" 까지의 결과가 먼저 보인다.
- 조합 중 `keydown` (`isComposing` 또는 `keyCode 229`) 의 Enter, 방향키는 무시한다. macOS 한글 입력기에서 조합을 끝내는 Enter가 결과 선택으로 번지는 것을 막는다.

### 7.2 매칭 규칙

질의와 대상을 아래처럼 정규화한 뒤 부분 문자열로 찾는다.

1. `normalize('NFC')`, `toLowerCase()`, 앞뒤 공백 제거, 연속 공백을 하나로 (시안은 `trim` 과 `toLowerCase` 만).
2. 제목: 정규화한 제목에 질의가 들어 있는가.
3. stem: 질의의 공백을 `-` 로 바꾼 문자열이 stem에 들어 있는가. "diffusion policy" 가 `chi-2023-diffusion-policy-...` 에 맞는다.
4. 태그는 검색하지 않는다 (7절 Q2 결정, 태그는 필터만). `vla` 하나가 91개 노드에 걸려 결과를 덮기 때문이다.
5. 카테고리 이름도 검색하지 않는다. 범례가 맡는다.

### 7.3 점수와 정렬

| 조건 | 점수 (시안 1832행) |
|---|---|
| 제목이 질의로 시작 | 1000 + degree |
| 제목 중간에 포함 | 500 + degree |
| stem에만 포함 | 0 + degree |

같은 점수면 제목 `localeCompare(…, 'ko')` 순 (새로, 시안은 배열 순서). 결과 목록에는 위 8개를 보이고, 캔버스는 위 40개를 강조한다 (조감 라벨 강제 후보, 04 5.1절). 필터 밖 노드도 결과에 넣고 행을 흐리게 하며 "필터 밖" 표시를 단다.

### 7.4 결과 목록 키보드 (combobox)

| 키 | 동작 |
|---|---|
| `↓` `↑` | 활성 행을 8개 안에서 돈다. `aria-activedescendant` 갱신 (시안 1858행) |
| `Enter` | 활성 행 고르기. 새 결과가 나오면 활성 행은 첫 행 |
| `Esc` | 6.5절 1단계 |
| `Tab` | 목록을 닫고 다음 요소(필터 버튼)로. 고르지 않는다 |

행 누르기는 `mousedown` 기본 동작을 막아 (`pointerdown` 을 막으면 에뮬레이션 WebKit 터치에서 `click` 이 오지 않는다, 2026-11-25) 입력 초점을 유지한 뒤 `click` 에서 고른다 (시안 1865행).

### 7.5 고른 뒤

1. 입력을 비우고 결과를 닫는다. 초점을 캔버스로 (시안 1853행).
2. 노드가 켜진 필터 축 중 어느 것에 걸리면 그 축만 푼다 (카테고리가 다르면 카테고리 필터를, 유형이 다르면 유형 필터를). 시안은 카테고리만 풀었다 (1852행). 풀었으면 알림 끝에 "필터 일부를 해제했다" 를 붙인다.
3. 조감이면 궤도 진입(비행 720ms), 궤도면 중심 옮기기(비행 600ms). 이미 중심이면 무동작.

## 8. 필터와 URL

### 8.1 필터 결합

| 축 | 자리 | 축 안 결합 | 기본 |
|---|---|---|---|
| 카테고리 | 범례 버튼 8개 | OR (하나라도 맞으면) | 아무것도 켜지 않음 = 모두 |
| 유형 | 팝오버 칩 6개 | OR | 같다 |
| 태그 | 팝오버 자동완성 + 추천 칩 | OR (11절 N2) | 같다 |

축 사이는 AND다. 예: 카테고리 physical-ai, 유형 paper 와 repo, 태그 vla 면 "physical-ai 이면서 paper나 repo 이면서 vla 태그" 인 노드가 필터 안이다.

- 변경은 즉시 반영한다. 적용 버튼은 없다.
- 걸러진 노드는 흐리게 남고 히트 테스트에 그대로 걸린다. 흐린 노드도 눌러 궤도를 열 수 있다 (04 L7).
- 범례 미리 강조(마우스 호버)는 필터가 하나도 없을 때만 한다 (시안 1813행).
- 필터를 바꿔도 카메라는 움직이지 않는다. "화면 맞춤" 이 필터 안 노드에 맞춘다.

### 8.2 선택 노드가 필터 밖일 때

- 궤도 중심은 흐리지 않는다 (새로. 시안 835행은 중심도 흐렸다). 패널 메타 줄에 "필터 밖" 표시를 단다.
- 궤도 구성원은 바꾸지 않고 필터 밖 노드만 흐린다 (04 7.3절).
- 필터를 바꿔도 궤도를 나가지 않는다.
- 조감에서 방향키로 여는 시작 노드는 필터 안에서 고른다 (6.3절).

### 8.3 0개 결과와 초기화

- 필터 안 노드가 0개면 모든 노드가 흐려진다. 범례 아래(조감) 또는 팝오버 맨 위에 "조건에 맞는 페이지가 없다" 와 "모두 해제" 버튼을 보이고, 라이브 영역에 같은 문구를 알린다.
- 해제 수단: 범례 "필터 해제" (카테고리만), 팝오버 "모두 해제" (세 축), 필터 칩 줄의 × (하나씩), 조감 Esc (카테고리만, 6.5절).
- 필터 버튼 배지는 켜진 유형과 태그 수다. 카테고리는 넣지 않는다 (01 4절).

### 8.4 hash 문법

```
hash   = "#" [ part *( "&" part ) ]
part   = "list" / "node=" id / "path=" id / "cat=" list / "type=" list / "tag=" list
list   = value *( "," value )
```

- `path` 는 Phase 5 학습 경로(06 4.5절)다. 값은 overview 노드 id 하나다. `paths.json` 을 받은 뒤 해석하고, 경로 목록에 없는 id는 그 part만 버리고 콘솔 경고 한 줄을 남긴다.
- `id` 는 `category/stem` 이다. 스냅샷의 모든 id가 `[a-z0-9/-]` 라 그대로 쓰고, 그 밖 글자가 생기면 `/` 를 뺀 나머지를 `encodeURIComponent` 한다.
- 값은 각각 `encodeURIComponent` 한다 (`,` 와 `&` 는 `%2C`, `%26`).
- 정규 순서: `list`, `node`, `path`, `cat`, `type`, `tag`. 값 정렬: `cat` 은 범례 순서, `type` 은 article, paper, repo, overview, video, report (01 4절 개수 순), `tag` 는 사전순. 같은 상태는 늘 같은 문자열이 된다.
- 빈 축은 키째 뺀다. 상태가 모두 기본이면 hash 없이 `location.pathname + location.search` 로 둔다 (시안 939행).
- 예: `#node=physical-ai/black-2024-pi0&cat=physical-ai&type=paper,repo&tag=vla`.

`#list` 는 목록 판 플래그다. 다른 키와 함께 쓰지 않는다. 목록 판으로 바꾸면 `pushState(#list)` 하고, 지도 판의 상태(궤도, 필터)는 메모리에 그대로 둔다. 뒤로 가기는 바로 앞 hash로 돌아와 지도 판을 되살린다. `#list` 로 바로 들어오면 탐색기는 지도를 준비하되 목록 판을 유지한다.

### 8.5 hash를 읽는 규칙

`popstate` 와 `hashchange` 를 모두 듣고 같은 처리 함수 하나로 보낸다 (시안 962, 963행). 처리 함수는 멱등이다 (같은 상태면 아무것도 하지 않는다). 두 이벤트가 같이 와도 한 번만 바뀐다.

| hash | 처리 |
|---|---|
| 비어 있음 | 조감, 필터 없음, 지도 판 |
| `#list` | 목록 판 |
| `node=`, `path=`, `cat=`, `type=`, `tag=` 로 시작하는 part가 하나라도 있음 | 각 part 적용 |
| `#physical-ai` 처럼 카테고리 slug 하나 | 현재 사이트의 옛 형식 (`graph-explorer.js` 423행). `cat=` 로 해석하고 정규 형식으로 `replaceState` |
| 목록 판 안 요소의 id (`#weak-links`, 카테고리 절 id, `#graph-list`) | 목록 판으로 바꾸고 그 요소로 스크롤한다. hash는 고쳐 쓰지 않는다 (앵커 이동이 이미 history 항목을 만들었다). 지도 판 상태는 `#list` 와 같이 메모리에 둔다. 06 3.2절의 범례 링크 "연결이 적은 페이지" 가 이 경로다 |
| 그 밖 (`#main` 등 목록 판 밖 앵커) | **무시한다.** 상태를 바꾸지 않는다 |

마지막 줄은 시안 결함 수정이다. 시안 `syncFromHash` 는 `node` 가 없는 hash를 모두 "궤도 나가기" 로 읽었다. 사이트에서는 공용 건너뛰기 링크(`href="#main"`, `templates.mjs` 97행)를 누르면 궤도가 닫힌다. `.graph-skip` 은 `href="#list"` 로 둔다.

잘못된 값:

| 경우 | 처리 |
|---|---|
| `node` 의 id가 그래프에 없음 | 조감으로 시작, `node` 를 뺀 정규 hash로 `replaceState`, 알림 "요청한 페이지를 그래프에서 찾지 못했다" |
| 모르는 카테고리, 유형, 태그 값 | 그 값만 버리고 정규화 |
| 모르는 키 | 버린다 |
| `decodeURIComponent` 예외 | 그 part를 버린다 |
| 같은 키 두 번 | 마지막 것을 쓴다 |

### 8.6 history

| 동작 | 방식 | 이유 |
|---|---|---|
| 조감에서 궤도 진입 | `pushState({ graph: 'orbit' })` | 뒤로 가기가 궤도를 닫게 한다 (시안 954행) |
| 궤도 안 중심 옮기기, 펼침 | `replaceState` | 이웃을 스무 번 옮겨도 history가 쌓이지 않는다. 그래프 안 되돌리기는 경로 줄과 Backspace가 맡는다 (시안 955행) |
| 궤도 나가기 | push한 항목이면 `history.back()`, 아니면 `replaceState` (2.3절) | |
| 필터 변경 | `replaceState` | 칩을 누를 때마다 history가 쌓이지 않는다 |
| 학습 경로 켜기, 끄기, 바꾸기 (Phase 5) | `replaceState` | 필터와 같은 보기 상태다. 경로 단계 이동은 중심 옮기기와 같다 |
| 지도 판에서 목록 판 | `pushState('#list')` | 뒤로 가기로 지도에 돌아온다 |
| 목록 판에서 지도 판 ("그래프로 보기") | `#list` 가 push한 항목이면 `history.back()`, 아니면 `replaceState` | |
| 딥링크로 시작 | 첫 항목을 `node` 없는 hash로 `replaceState` 한 뒤 궤도 진입이 push 한다 (시안 1881행) | 뒤로 가기가 페이지를 떠나지 않고 이 그래프의 조감으로 온다. `atlasCam` 은 `fitTarget(전체)` |

`replaceState` 가 예외를 던지는 환경(`file://` 등)은 `try` 로 감싸고 무시한다 (현재 사이트 `graph-explorer.js` 와 같다).

### 9.3 캔버스의 역할과 이름

| 속성 | 값 |
|---|---|
| `role` | `application` (새로). 방향키를 직접 쓰는 위젯이라 스크린 리더 탐색 모드가 키를 가로채지 않게 한다 |
| `aria-roledescription` | "관계 그래프" |

| `aria-describedby` | `graph-help`: 숨은 문단 "방향키로 이웃을 고르고 Enter로 중심을 옮긴다. 중심에서 Enter는 페이지를 연다. Esc는 전체 보기. 슬래시로 검색" |

### 9.4 키보드만으로 모든 노드에 닿는 길

1. 검색: `/` 로 초점, 제목 일부, Enter. 344개 모두 제목이나 stem으로 닿는다.
2. 궤도 따라가기: 캔버스에서 방향키로 커서, Enter로 중심 옮기기. 그래프가 연결되어 있으면 (고립 노드 0개, 계획 2절) 어느 노드에서든 닿는다.
3. 패널 이웃 목록: Tab으로 들어가 `↑` `↓` 와 Enter.
4. 목록 판: `.graph-skip` 또는 "목록 보기" 버튼으로 모든 페이지 링크 목록.

## 13. 검증 체크리스트

Phase 6에서 Chrome, Firefox, WebKit 데스크톱과 휴대폰 설정(375 × 812, 844 × 390), 실기기로 돌린다. "실기기" 표시 항목은 에뮬레이션으로 대신하지 않는다.

**상태와 전환**

1. 조감에서 노드를 클릭하면 640ms 전환 뒤 궤도가 되고 hash가 `#node=…` 가 된다. history 길이가 1 늘어난다.
2. 궤도에서 다른 노드를 누르면 중심이 옮겨지고 history 길이는 그대로다.
3. 뒤로 가기 한 번이면 조감으로 돌아오고 카메라가 진입 전 값과 같다 (x, y, k 차이 0.5 이하).

7. 전환 중 마우스를 노드 위에 두어도 툴팁이 나오지 않는다.
8. 궤도 빈 곳 클릭은 궤도를 닫지 않는다.

**마우스**

9. 오른쪽 버튼으로 끌어도 카메라가 움직이지 않고 오른쪽 클릭으로 노드가 선택되지 않는다. 기본 메뉴가 뜬다.

51. 딥링크로 열고 뒤로 가기 한 번이면 같은 페이지의 조감이다. 두 번이면 이전 페이지다.
52. "목록 보기" 뒤 뒤로 가기는 지도 판과 그 전의 궤도, 필터를 되살린다.
53. `#list` 로 들어오면 목록 판이고 "그래프로 보기" 가 보인다.

**패널과 접근성 (일부 실기기)**

54. 이웃 목록 행에 키보드 초점이 가면 캔버스의 그 노드가 강조된다.
55. "모두 보이기" 를 누른 뒤 초점이 새 "28개로 줄이기" 버튼에 있다.
56. 라이브 영역 문구가 9.2절 표와 같다. 같은 노드로 두 번 들어가도 두 번 알린다.
57. 캔버스가 `role="application"`, `aria-roledescription`, 모드별 `aria-label`, `aria-describedby="graph-help"` 를 갖는다.
58. VoiceOver(macOS, iOS)와 NVDA에서 캔버스 초점 시 이름과 설명을 읽고 방향키가 탐색 모드에 먹히지 않는다 (실기기).
59. 키보드만으로 9.4절 네 경로 모두 임의 노드 하나에 닿는다.

**모션과 가장자리**

60. reduced-motion에서 첫 등장, 전환, 비행, 맥박, 반짝임, 패널, 시트가 모두 한 프레임에 끝난다. 휠과 핀치는 그대로다.
61. 툴팁이 처음 120ms 뒤 나오고 이웃 노드로 옮기면 바로 바뀐다.
62. 궤도 상태에서 창을 1440에서 768, 375로 줄였다 늘려도 중심, 경로, 커서, 필터, 검색 글자가 남는다.
63. 휴대폰 세로에서 가로로 돌려도 궤도가 유지되고 나갈 때 새 배치로 돌아온다.
64. `graph.json` 을 막으면 목록 판과 실패 안내 한 줄이 보이고 콘솔 오류는 경고 한 줄뿐이다.
65. 163자 제목이 툴팁, 패널, 검색 결과, 경로에서 무대 밖으로 넘치지 않는다.

## 14. 개선 제안

세련되고 모던한 사용감을 위한 미세 인터랙션이다. 하나씩 따로 넣을 수 있고, 모두 reduced-motion에서 즉시 바꾸기로 대체한다.

이 절은 확정된 설계가 아니다. Phase 4, 5 구현 때 비용이 적은 것부터 골라 넣는다.

| 번호 | 제안 | 효과 | 비용 |
|---|---|---|---|
| J1 | **관성 팬.** 손을 뗄 때 마지막 80ms 속도로 약 400ms 감속 이동한다 (마찰 계수 0.92/프레임). 마우스 끌기에도 적용 | 휴대폰 지도 앱과 같은 손맛. 끊기는 느낌이 사라진다 | JS 20줄 |
| J2 | **줌 끝 고무줄.** 핀치가 `K_MAX` 를 넘으면 최대 10%까지 저항하며 따라가다 놓으면 240ms에 되돌아온다 | 한계에 부딪힌 것이 딱딱하게 멈추지 않고 손에 전해진다 | JS 소량 |
| J3 | **커서 노드에 궤도 고리.** 키보드 커서 노드에 `--graph-ring` 2px 고리를 120ms에 그려 넣고, 다음 노드로 옮기면 고리가 호를 따라 미끄러진다 | 툴팁만으로는 커서가 약하다. 키보드 사용이 눈에 보이는 조작이 된다 | 그리기 소량 |
| J4 | **호버 시 이웃 라벨 순차 등장.** 허브에 호버하면 이웃 라벨을 degree 순으로 20ms 간격으로 띄운다 | 118개 라벨이 한꺼번에 튀지 않고 퍼져 나간다 | 그리기 소량 |
| J5 | **검색 결과 미리보기 비행.** 결과 목록에서 활성 행이 바뀔 때 카메라를 그 노드 쪽으로 30%만 기울이고 노드에 맥박을 준다. 고르기 전에 위치를 보여 준다 | 결과를 고르기 전에 지도 위 자리를 안다 | JS 소량. 키 반복이 빠르면 비행을 건너뛴다 |
| J6 | **명령 팔레트 키 표시.** 검색 캡슐 오른쪽 `kbd` `/` 가 입력에 초점이 가면 `Esc` 로 바뀐다 | 지금 누를 키를 늘 보여 준다 | CSS와 문구 |
| J7 | **필터 변경 시 수 카운터 굴리기.** 범례 머리 "페이지 344개" 가 필터 결과 수로 바뀔 때 숫자를 240ms 굴린다 (`font-variant-numeric: tabular-nums`) | 필터 효과가 숫자로 즉시 읽힌다 | JS 소량 |
| J8 | **경로 줄 되돌리기 미리보기.** 경로 버튼에 호버하면 그 노드를 캔버스에서 강조하고 툴팁처럼 "여기로 되돌아가기" 를 띄운다 | 어디로 돌아가는지 누르기 전에 안다 | 소량 |
| J9 | **햅틱.** 모바일에서 시트가 멈춤점에 닿을 때와 궤도 중심이 옮겨질 때 `navigator.vibrate(8)` (지원 기기만) | 터치 조작에 촉감 마침표가 생긴다 | 한 줄. iOS Safari는 지원하지 않는다 (일반 지식, 미확인) |
| J10 | **View Transitions로 패널 제목 교체.** 중심을 옮길 때 패널 제목과 메타를 `document.startViewTransition` 으로 교차 페이드 (01 I7과 같은 수단) | 패널 내용이 툭 바뀌지 않는다 | 몇 줄, 점진적 향상 |

넣지 않기를 권하는 것: 노드 끌어 옮기기(배치가 빌드에서 고정이고 다음 방문에 되돌아간다), 길게 누르기 메뉴(터치에서만 있는 숨은 기능이 된다), 휠 줌 관성(트랙패드가 이미 관성 이벤트를 보낸다).

## 15. 확인하지 못한 것

- 실제 휴대폰에서의 탭 흔들림 폭, 두 번 탭 간격, 시트 튕김 속도 경계. 값(8px, 300ms, 24px, 0.5px/ms)은 일반적인 값으로 정했고 시안에서 재지 않았다. Phase 6 실기기 항목이다.
- iOS Safari가 `touch-action: none` 으로 페이지 핀치 확대를 막는지, `gesturestart` 처리가 필요한지.
- `role="application"` 캔버스를 VoiceOver, NVDA가 어떻게 읽는지. 시안 F 접근성 55항목은 접근성 트리 검사였고 스크린 리더 청취는 아니다 (계획 10절).
- 검색 계산 시간. 344노드에서 1ms 미만은 추정이다.
- Firefox `deltaMode === 1` 마우스에서 시안 계수로 줌이 느린지는 코드로 추론했고 실측하지 않았다.
- 한글 입력기별(macOS 기본, 구름, Windows MS IME, Android Gboard) 조합 중 `keydown` 의 `isComposing` 동작 차이.
- 현재 사이트에 옛 형식 `/graph/#category` 로 들어오는 링크가 있는지. 사이트 코드(`site/lib/*.mjs`, `site/assets/js/*.js`)에서 `graph/#` 를 찾았을 때 0건이었다. 외부 링크는 알 수 없다.
