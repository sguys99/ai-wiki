# 그래프 페이지 재설계 계획

작성일 2026-11-16. 대상은 사이트의 `/graph/` 페이지다.

## 1. 배경과 목표

사이트에는 이미 `/graph/` 페이지가 있다 (Phase 5, 커밋 `760abdbb`). 캔버스 force 배치, 호버 이웃 강조, 카테고리 칩, 카테고리별 텍스트 목록을 갖췄다. 다만 121노드 시절에 만든 화면이라 지금 규모에서는 관계를 읽기 어렵다. 이번 작업은 **기존 `/graph/` 를 전면 재설계**한다 (2026-11-16 사용자 결정).

목표는 세 가지다.

- wiki 전체의 관계 구조가 한눈에 읽힌다 (어디가 뭉쳐 있고 무엇이 허브인지).
- 한 페이지에서 출발해 이웃을 따라가며 탐색할 수 있다.
- 사이트의 Constellation 디자인 언어 안에서 세련되게 보인다.

## 2. 현재 상태 (2026-11-16 실측)

| 항목 | 값 |
|---|---|
| 노드 | 342개 (physical-ai 149, agents 84, applications 39, database 28, llms 19, overviews 14, evaluations 6, etc 5) |
| 엣지 | 2,593개 (방향성, 중복 제거) |
| 고립 노드 | 0개 |
| 최대 degree | 118 (`overviews/physical-ai-overview`), 다음은 63, 58, 58, 57 |
| 노드 필드 | `id`, `stem`, `title`, `category`, `domain`, `degree` |
| 색 구분 | 도메인 2색 (core 아쿠아, physical 앰버) |

관련 파일은 아래와 같다.

| 파일 | 역할 | 이번 작업에서 |
|---|---|---|
| `site/lib/graph.mjs` | wikilink 파싱, `graph.json` 생성 | 노드 필드 확장 |
| `site/build.mjs` (6.7절) | `/graph/` 렌더, 카테고리 그룹 구성 | 소폭 수정 |
| `site/lib/templates.mjs` `graphPage` | 페이지 마크업 | 재작성 |
| `site/assets/js/graph-explorer.js` | 배치, 그리기, 호버, 필터 (456줄) | 재작성 |
| `site/assets/js/graph-core.js` | 홈 히어로와 공유하는 팔레트, fetch | 유지 (홈이 함께 쓴다) |
| `site/assets/css/styles.css` 1691행 이하 | 그래프 페이지 스타일 | 재작성 |

현재 화면의 한계는 다음과 같다.

- 줌과 팬이 없다. 342개 노드가 고정 크기 캔버스 하나에 들어간다.
- 허브 하나가 엣지 118개를 가져 전체가 한 덩어리로 뭉친다.
- 색이 도메인 2가지뿐이라 카테고리 8개가 구분되지 않는다.
- 노드를 찾는 검색이 없다. 호버 외에는 제목을 볼 방법이 없다.
- 노드를 누르면 바로 페이지로 이동해, 그래프 안에서 이웃을 따라가는 탐색이 끊긴다.
- 특정 노드를 가리키는 공유 URL이 없다.

## 3. 유지할 제약

- 번들러 없음. 브라우저 스크립트는 `<script defer>` 로 싣는 vanilla JS다.
- 색은 CSS 토큰을 런타임에 읽는다. 라이트와 다크 테마 토글이 그대로 따라와야 한다.
- 스크립트가 실패해도 카테고리별 텍스트 목록으로 모든 페이지에 갈 수 있다 (접근성 판본).
- 홈 히어로 `constellation.js` 가 `graph-core.js` 와 `graph.json` 을 함께 쓴다. 깨뜨리지 않는다.
- `BASE=/ai-wiki` 배포 경로에서 동작한다. `npm run build:strict` 가 통과한다.
- 모바일 폭에서 가로 스크롤이 없고 터치로 조작된다.
- `prefers-reduced-motion` 에서는 애니메이션 없이 정지 배치를 보여 준다.

## 4. 디자인 시안 후보

시안은 실제 `graph.json` 을 읽는 단독 HTML로 만든다. 그림이 아니라 동작하는 화면으로 비교한다. 각 시안은 라이트와 다크 두 테마를 모두 보여 준다.

| 시안 | 한 줄 설명 | 강점 | 약점 |
|---|---|---|---|
| A. 성도 (Atlas) | 화면 가득한 force 그래프에 줌과 팬, 카테고리별 성운 클러스터, 우측 상세 패널 | 전체 구조가 한눈에 보인다. 현재 디자인 언어와 가장 잘 맞는다 | 허브 때문에 뭉침을 풀려면 배치 튜닝이 필요하다 |
| B. 궤도 (Orbit) | 선택한 노드를 중심에 두고 1-hop, 2-hop 이웃을 동심원에 배치 | 어떤 노드든 읽기 쉽다. 탐색 흐름이 자연스럽다 | 전체 조감이 약하다 |
| C. 군도 (Archipelago) | 카테고리를 섬으로 나누고 섬 안은 조밀하게, 섬 사이 연결은 묶어서 표현 | 카테고리 간 교류량이 드러난다. 뭉침이 구조적으로 없다 | 배치 계산과 엣지 묶음 구현이 가장 크다 |
| D. 지층 (Strata) | 가로축 연도, 세로축 카테고리. 엣지는 호로 그린다 | 연구 계보와 시간 흐름이 보인다 | 관계보다 시간이 주인공이 된다. 같은 연도에 노드가 몰린다 |

추천은 **A를 기본 화면으로 하고 B를 노드 선택 시의 초점 모드로 합치는 방향**이다. 조감과 탐색을 한 페이지에서 얻는다. 최종 선택은 시안을 본 뒤 사용자가 한다.

## 5. 함께 반영할 것 (요청에 없었지만 필요한 항목)

- `graph.json` 노드에 `year`, `type`, `tags` 추가. 필터, 시안 D, 상세 패널이 이 값을 쓴다.
- 노드 검색. 제목을 입력하면 해당 노드로 화면이 이동한다.
- 딥링크. `#node=category/stem` 으로 특정 노드를 선택한 상태를 공유한다.
- 클릭 동작 변경. 클릭은 선택과 패널 열기, 패널의 버튼이 페이지 이동을 맡는다.
- 카테고리 8색 구분. 도메인 2색 안에서 명도와 채도로 나누거나 범례를 둔다 (시안에서 결정).
- 키보드 조작. 방향키로 이웃 이동, Enter로 열기, Esc로 선택 해제.
- 제목 라벨 표시 규칙. 줌 수준과 degree에 따라 라벨을 드러낸다.

## 6. 더 나은 아이디어 (선택 사항, 사용자 승인 후 진행)

- **wiki 페이지마다 미니 이웃 그래프**: 각 문서 하단에 그 페이지의 1-hop 그래프를 넣는다. `graph.mjs` 주석에 이미 계획으로 적혀 있다.
- **학습 경로 겹쳐 보기**: overview의 `study_path` 를 그래프 위에 번호 붙은 경로로 표시한다.
- **고아와 약한 연결 리포트**: degree가 낮은 페이지 목록을 보여 wiki 보강 대상을 찾는다.
- **최근 추가 강조**: 최근 ingest한 노드를 표시해 지식이 어디서 자라는지 보여 준다.

## 8. 필요한 도구

추가 설치는 필요 없다. 아래는 이미 있는 것이다.

- 디자인 스킬: `frontend-design`, `design-taste-frontend` (설치됨).
- 화면 검증: `playwright` (시스템 Chrome 구동, `pyproject.toml` 에 있음).

브라우저에서 직접 조작해 확인하려면 Claude in Chrome 확장 권한이 있으면 편하다. 없으면 playwright 스크린샷으로 대신한다.
