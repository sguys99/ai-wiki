# AKB 제품 소개 — 에이전트를 위한 올인원 지식베이스 (v4)

## 한 줄 요약 (One-line Summary)

Dnotitia가 사내 1차 검증을 마친 **AKB(Agent Knowledge Base) + Collector + Gardener** 3종 제품 라인을 23장 슬라이드로 정리한 한국어 제품 소개 deck. 기존 GitHub 레포 페이지([[applications/dnotitia-akb]])가 다루지 않은 **외부 소스 자동 수집(Collector)**, **HITL 큐레이션(Gardener: Propose/Approve/Execute)**, **21일 무인 자동 운영 실측($10·2,500+msg·100% 분류·redaction 누락 0)**, **9-도메인 Vault 운영 패턴**, **XDR 보안 지식 허브 포지셔닝**을 처음 공식 문서로 정리한 자료다.

## 2. 주요 기여 (Key Contributions)

이 deck이 **기존 wiki/applications/dnotitia-akb.md(GitHub 레포)에는 없던** 7가지를 처음으로 공식화한다.

1. **AKB Collector (신규 제품)** — Confluence/Jira/Slack/GitHub/Notion/Google Drive 6개 외부 소스를 AKB로 자동 동기화하는 컴포넌트. 3원칙: ① **자동 동기화** (내용 hash 비교 → 변경분만 가져옴) ② **원천 보존** (원본 URL을 메타로 함께 보관 → 역추적 가능) ③ **보안 우선** (유입 단계에서 민감정보 redaction + 권한 규칙 안에서 처리). 결과물은 "원석(Bronze)" 상태 — Gardener가 다듬는 입력이다.

2. **AKB Gardener (신규 제품)** — Bronze→Gold 정제 + HITL 안전장치. 4가지 작업: **다듬기**(구조화), **솎아내기**(중복·낡은 정보 제거), **눈높이 요약**(팀원/팀장/그룹장/임원 4단계 audience-specific), **출처 달기**(모든 문장에 cite). **Propose / Approve / Execute** 워크플로 — Gardener는 제안만 작성하고, 파괴적 작업은 사람 승인 뒤에만 Gardener가 실행한다. **사용자 금고는 read-only로만 본다** — Gardener가 임의로 사용자 vault에 쓰지 않는다.

3. **21일 무인 자동 운영 실측** (2026-05-15 ~ 06-05, Dnotitia 사내 온프렘) — **6개 Slack 채널**, **2,500+ 누적 메시지** 정제, **분류 정확도 100%**(수동 검증 22건), **민감정보 redaction 누락 0건**, **3주 전체 운영 비용 약 $10**. "이론이 아니라 우리가 직접 돌려봤다"는 자체 PROOF 슬라이드.

4. **5갈래 탐색 통합 프레임** — 단일 검색 방식 의존 ❌. (a) **트리 탐색** L0→L1→L2 (`akb_list_vaults` / `akb_browse` / `akb_drill_down`) (b) **하이브리드 검색** (의미+키워드+재순위) (c) **정확 검색 grep** (정규식 기반, 코드·URL·버전번호용) (d) **그래프 탐색** (인용·의존). 모두 `akb://` 한 주소 아래에 모인다. **한국어 검색에 형태소 분석기 Kiwi** 명시 — 기존 페이지가 다루지 않던 한국어 NLP 디테일이다.

5. **9-도메인 Vault 운영 패턴** — HR(인사) · Sales(영업) · Patent(특허/IP) · Product(제품) · Development(개발) · Research(연구) · 경쟁사 분석 · 협력사 · 경쟁제품 벤치마크. 각 도메인 = 독립 Vault. **사내 온프렘(자체 서버)에서 운영하고, 한 바이트도 외부 반출이 없다**고 명시. WHO-KNOWS-WHAT 패턴: 생산자(도메인팀·에이전트·Collector) ↔ 공유 KB ↔ 소비자(제안서·분석·온보딩) — **같은 사람이 생산자이자 소비자** (1차 검증 기준 12명 · 9 Vault).

6. **크로스-Vault 시나리오 3종** — ① 고객 제안서/RFP 응답 초안 (Sales + Product + Research + Patent) ② 경쟁 비교 리포트 (경쟁사 + 벤치마크 + Product) ③ 신규 입사자 온보딩 (HR + Development + Product). 권한이 허용된 vault만 안전하게 조합한다.

7. **XDR(eXtended Detection / Investigation / Response) 보안 지식 허브 포지셔닝** — FW/Server/DDoS/IDS·IPS/NAC/VPN/AV/WAF + EDR·NDR·CTI·Playbook 모든 보안 로그를 AKB에 축적해 **AI Agent가 실시간 탐지·조사·대응**에 활용한다. "의심스러운 VPN 로그인 실패 분석" → "EDR/VPN/NAC 상관 분석 → 계정 탈취 가능성" 대화 예시. AKB의 **신규 vertical**이다.

deck 전반의 **수사적 프레이밍**도 짚어둘 만하다:
- **WHY NOW**: Gartner "AI-Ready Data 60% 폐기 예측"을 인용 — 모델이 아니라 데이터·지식의 품질이 발목을 잡는다는 메시지.
- **THE GAP**: 벡터 검색의 2가지 약점(문맥 잘림 + 임베딩 의존) 명시 → 5갈래 탐색의 정당화.
- **THE BIG PICTURE**: 유입(Collector) → 정제(Gardener) → 활용(AKB) → 폐기(HITL archive)로 이어지는 **지식 생애주기** 전체.

## 3. 방법론 및 아키텍처 (Methodology and Architecture)

### 5갈래 탐색 (THE AKB WAY)

```
          ┌── 트리 탐색 L0→L1→L2 (요약만 보고 좁혀 들어감)
          │
에이전트 ─┼── 하이브리드 검색 (임베딩 + BM25 + 재순위)
          │
          ├── 정확 검색 grep (정규식, 코드/URL/버전)
          │
          └── 그래프 탐색 (인용·의존·관계)
                      │
                      ▼
              akb:// 한 주소 (URI corpus)
              문서·표·파일 모두 헤딩 단위로 완결
```

에이전트가 **필요한 길을 직접 고른다** — single best searcher 가정이 없다. 한국어 검색은 형태소 분석기 **Kiwi**로 정확도를 보정한다.

### 트리 탐색 3단계

| 레벨 | 도구 | 비유 | 무엇을 본다 |
|---|---|---|---|
| L0 | `akb_list_vaults` | 도서관 서가 | 주제별 금고 목록 |
| L1 | `akb_browse` | 책장의 책 목록 | 컬렉션·문서 frontmatter (요약만) |
| L2 | `akb_drill_down` | 책의 목차·페이지 | 문서 헤딩(섹션) 단위 |

**책장을 통째로 복사하지 않고 필요한 페이지만 펼친다** — context budget을 아낀다. 기존 wiki 페이지의 hybrid retrieval 98.4% R@5와는 별개로, **컨텍스트 효율**을 강조하는 새 축이다.

### 콘텐츠 모달리티 (ALL-IN-ONE)

```
문서 (헤딩 단위 markdown + Git 버전)  ─┐
파일 (S3 PDF·이미지, 에이전트 직접)   ─┼─ akb:// 한 주소
테이블 + SQL (구조화 표 + 통계·집계)  ─┘
```

cross-modal 워크플로 예: **"이 PDF 받아와서, 표로 정리하고, 합계를 내줘"** → 파일 → 테이블 → SQL → 근거 있는 답 (한 에이전트, 한 자리).

### Trust & Safety 5축

- **버전 이력 (Git)** — 과거 어느 시점이든 복원
- **문서 ↔ 인덱스 동기화** — 낡은 색인이 옛 답을 주지 않음
- **Vault 권한 (RBAC)** — 금고 단위 read/write/admin
- **DB-네이티브 격리** — 우회 SQL로도 권한 밖 vault 안 보임 (PG-native RBAC)
- **전수 감사 로그** — 누가 언제 무엇을 봤는지 전부 기록

### AKB Collector — Bronze 단계

```
Confluence ─┐
Jira       ─┤
Slack      ─┤
GitHub     ─┼──→ AKB Collector ──→ AKB (Bronze)
Notion     ─┤   (hash diff,
GDrive     ─┘    원본 URL,
                 redaction)
```

## 5. 한계와 향후 과제 (Limitations and Future Work)

### 자료의 한계 (deck 자체)

- **마케팅 deck** 성격 — 1차 자체 검증(self-reported) 외 외부 비교·벤치마크가 없다. 기존 wiki/applications/dnotitia-akb.md의 LongMemEval-S R@5 98.40% 같은 외부 데이터셋 결과와는 별개 차원이다.

- **redaction 0건의 정의 모호** — recall 측정(놓친 PII가 있는지)인지, precision 측정(잡힌 것 중 오탐)인지 deck에서 구분이 없다.

### 제품/포지셔닝의 미해결 영역

- **Collector·Gardener 세부 아키텍처** 미공개 — 6개 소스 connector 구현 깊이, Gardener의 LLM/룰 비율, redaction 엔진 종류, 4단계 audience 요약의 prompt/모델이 공개되어 있지 않다.

## 7. 용어집 (Glossary)

- **AKB** — Agent Knowledge Base. Dnotitia의 에이전트용 조직 메모리 시스템.
- **AKB Collector** — 외부 소스(Confluence/Jira/Slack/GitHub/Notion/GDrive) → AKB 자동 동기화 컴포넌트. hash diff + 출처 보존 + redaction.
- **AKB Gardener** — Bronze→Gold 정제 + HITL 큐레이션 컴포넌트. 다듬기/솎아내기/출처 달기/눈높이 요약 + Propose/Approve/Execute.
- **Bronze / Gold** — data lakehouse medallion 메타포를 차용한 정제 단계 (Bronze=Collector 직후 원석, Gold=Gardener 정제 후 정책 문서).
- **HITL** — Human In The Loop. Gardener의 파괴적 작업은 사람 승인 필수.
- **Propose / Approve / Execute** — Gardener의 3단계 워크플로. Gardener가 제안, 사람이 승인, Gardener가 승인분만 실행.
- **Vault** — 권한·물리 격리 단위 (기존 wiki에서 Git bare repo + PG ACL로 구현된 그것). deck에서는 "금고"로 번역.
- **5갈래 탐색** — 트리(L0→L1→L2) + 하이브리드(임베딩+BM25+재순위) + grep(정규식) + 그래프(인용·의존). akb:// 한 주소 위에서 에이전트가 선택.
- **L0 / L1 / L2** — 트리 탐색 깊이. L0=vault 목록, L1=collection/document frontmatter, L2=document 헤딩.
- **akb_list_vaults / akb_browse / akb_drill_down** — L0/L1/L2 각 단계의 MCP tool 이름.
- **Kiwi** — 한국어 형태소 분석기 (오픈소스, github.com/bab2min/Kiwi). AKB의 Korean BM25에 사용.
- **akb://** URI — vault/collection/document/table/file 통합 주소 체계 (기존 wiki에 상세).
- **XDR** — eXtended Detection Investigation Response. 다양한 보안 로그를 통합 수집·탐지·조사·대응하는 보안 운영 모델. AKB의 신규 vertical.
- **redaction** — 민감정보 가림 처리. Collector 유입 단계에서 적용.
- **온프렘 (on-prem)** — Dnotitia 사내 자체 서버 환경. deck 전반에서 "한 바이트도 외부 반출 없음" 강조.
