# AKB 제품 소개, 에이전트를 위한 올인원 지식베이스

## 한 줄 요약 (One-line Summary)

Dnotitia가 사내 1차 검증을 마친 AKB(Agent Knowledge Base)와 AKB Collector, AKB Gardener 3종 제품을 23장 슬라이드로 정리한 한국어 제품 소개 자료다. 같은 제품의 GitHub 저장소 페이지([[applications/dnotitia-akb]])가 다루지 않은 외부 소스 자동 수집, HITL 큐레이션, 21일 무인 운영 실측, 9개 도메인 vault 운영 패턴, XDR 보안 지식 허브 포지셔닝을 처음 한 문서에 모았다.

## 1. 자료 정보 (Document Information)

- 제목: 에이전트를 위한 올인원 지식베이스. 부제는 "검색을 넘어 에이전트가 스스로 찾고 쌓고 가꾸는 조직의 기억"이다
- 발행: Dnotitia (디노티시아)
- 파일: PDF 1.7, 23장, 약 1.4 MB, 파일 생성 시각 2026-06-09
- 슬라이드 규격: 959.76 x 540 pt (16:9)
- 분류: applications (제품 소개 슬라이드)
- 언어: 한국어. 영문 기술 용어를 인라인으로 섞어 쓴다
- 연관 페이지: [[applications/dnotitia-akb]] (GitHub 저장소 기준 기술 페이지)
- 제품 라인업: AKB, AKB Collector, AKB Gardener 3종

목차 슬라이드(2쪽)가 밝히는 장 구성은 다음과 같다. 괄호 안은 시작 페이지다.

## 2. 주요 기여 (Key Contributions)

이 자료는 같은 제품의 저장소 페이지에 없던 항목을 처음으로 공식화한다. 아래 7가지다.

### 2.1 AKB Collector

회사 곳곳에 흩어진 정보를 AKB로 자동 수집하는 컴포넌트다. 슬라이드 도식에 Confluence, Jira, Slack, GitHub, Notion, Google Drive 6개 소스가 화살표로 모인다. 3원칙은 다음과 같다.

| 원칙 | 슬라이드 표기 | 내용 |
|---|---|---|
| 자동 동기화 | 바뀐 것만 | 내용 지문(hash)을 비교해 변경분만 가져오니 빠르고 낭비가 없다 |
| 원천 보존 | 출처를 남긴 채 | 어디서 왔는지(원본 링크)를 함께 보관해 추적이 가능하다 |
| 보안 우선 | 경계 안에서 | 유입 단계부터 민감정보 가림과 권한 규칙 안에서 처리된다 |

수집 결과물은 아직 "원석(Bronze)"에 가깝다고 명시하고, 이 원석을 다음 주자인 Gardener가 다듬는다고 이어 붙인다.

### 2.2 AKB Gardener

Bronze 상태의 수집물을 Gold로 정제하는 컴포넌트다. 슬라이드 부제는 "지식의 정원사"이고, 인용문 "사용자는 토양을 심는다. 가드너는 정원을 가꾼다"를 표제 아래에 둔다. 작업은 4가지이고 도식의 화살표 순서는 다듬기, 솎아내기, 출처 달기, 눈높이 요약이다.

| 작업 | 내용 |
|---|---|
| 다듬기 | 수집된 원천 정보(원석 Bronze)를 구조화해 핵심(보석 Gold)만 추려 검색 가능한 정책 문서로 만든다 |
| 솎아내기 | 낡고 중복된 정보를 정원에 잡초를 뽑듯이 걷어내고 필요한 지식만 남긴다 |
| 출처 달기 | 가드너가 쓴 모든 문장에 출처(cite)가 붙어 "왜 이렇게 썼나"를 추적해 신뢰도를 확인할 수 있다 |
| 눈높이 요약 | 같은 내용을 팀원, 팀장, 그룹장, 임원 등 역할별로 필요한 수준에 맞춰 4단계로 다르게 요약한다 |

오른쪽 절반은 안전장치 영역이다. 표제는 "최종 결정은 사람이 합니다"이고 Propose, Approve, Execute 3단계를 가로로 배치한다.

| 단계 | 주체 | 슬라이드 설명 |
|---|---|---|
| Propose | 가드너 | 정리 후 보류, 제안서로 작성 |
| Approve | 사람 | 파괴적 작업은 반드시 검토 |
| Execute | 가드너 | 승인분만 실제 반영 |

하단에 "사용자 금고는 읽기 전용으로만 봅니다. 멋대로 고치지 않습니다"라는 단서가 붙는다.

### 2.3 21일 무인 자동 운영 실측

13쪽 PROOF 슬라이드가 사내 Slack을 Gardener가 정제해 검색 가능한 영구 정책 문서로 바꾼 결과를 지표 4개로 제시한다. 표제는 "이론이 아닙니다! 우리가 직접 돌려봤습니다"이고, 각주에 "Dnotitia 사내 온프렘 환경 자체 1차 검증 결과 기준 (2026.05.15 ~ 06.05)"이 달려 있다. 수치는 4절에 정리한다.

### 2.4 다중 경로 탐색

단일 검색 방식에 의존하지 않는다는 명제다. 6쪽 도식은 왼쪽에 에이전트, 오른쪽에 URI 코퍼스를 두고 그 사이에 탐색 경로를 세로로 나열한다. 나열된 경로는 트리 탐색, 하이브리드 검색, 정확 검색 grep, 그래프 탐색 4가지다. 하단 띠에 "에이전트는 SOTA 방식으로 여러 탐색 경로를 조합해 지식에 접근합니다. 국문 검색은 형태소 분석기 Kiwi를 활용해 정확도를 높입니다"가 붙고, 오른쪽 아래에 "SOTA: 현재 시점의 최적 탐색 접근"이라는 주석이 있다.

3장 제목과 22쪽 요약은 이 구성을 다섯 가지로 표기하지만, 6쪽 도식이 실제로 나열하는 경로는 네 가지다. 자료 내부에서 숫자가 어긋난다.

### 2.5 9개 도메인 vault 운영 패턴

15쪽이 회사의 모든 도메인을 하나의 코퍼스로 묶은 구성을 3행 3열 격자로 보여준다. 슬라이드는 vault를 "금고"로 옮겨 부른다. 각 도메인은 독립된 vault로 분리해 관리하고, 자기 권한을 지키면서도 필요한 업무에서 함께 검색하고 연결한다. 하단 띠에 "사내 온프렘(자체 서버) 환경에서 데이터가 처리되며, 한 바이트도 외부 반출 없이 안전하게 운영됩니다"가 명시된다.

16쪽은 이 코퍼스를 생산과 소비 양쪽에서 다시 그린다. 생산자는 도메인 팀, 에이전트, Collector 3종이고 소비자는 제안서 작성, 분석 에이전트, 신규 입사자 3종이다. 가운데 공유 지식베이스 상자에 "9개 도메인 금고, 권한 경계"가 적혀 있다. 도식 아래 문구는 "같은 사람이 생산자이자 소비자입니다"이고, "Gardener는 누가 어떤 지식을 만들고 활용하는지 연결합니다"가 따라온다. 규모는 "1차 검증 기준: 12명, 9개 Vault"로 각주에 적혀 있다.

### 2.6 크로스 vault 시나리오 3종

17쪽이 한 에이전트가 여러 vault를 넘나들며 일하는 시나리오 3개를 카드로 제시한다. 세부는 3절 표에 정리한다. 하단 문구는 "제안서 작성부터 기술지원 답변까지, 권한이 허용된 금고(지식)만 안전하게 연결해 활용합니다"다.

### 2.7 XDR 보안 지식 허브

20쪽과 21쪽이 보안 로그 영역을 AKB의 적용 대상으로 제시한다. 20쪽은 로그를 모으는 허브 구성이고, 21쪽은 그 위에서 탐지, 조사, 대응이 이어지는 XDR 4단계다. 저장소 페이지에 없던 신규 적용 영역이다.

### 2.8 자료의 서술 구조

7개 장이 문제 제기에서 해결책, 실증, 활용, 전체 그림 순으로 이어진다.

- 1장은 Gartner의 "AI에 맞게 준비되지 않은 데이터" 인용으로 시작해, 발목을 잡는 것이 모델이 아니라 데이터와 지식의 품질이라고 규정한다
- 2장은 벡터 검색의 약점 2가지를 짚어 다중 경로 탐색의 근거를 만든다
- 7장은 유입, 정제, 활용, 폐기로 이어지는 지식 생애주기 전체를 한 장에 요약한다

## 3. 방법론 및 아키텍처 (Methodology and Architecture)

### 3.1 문제 정의

1장은 세 가지 명제를 불릿으로 제시한다.

| 명제 | 슬라이드 설명 |
|---|---|
| 읽고 쓰는 주체가 바뀌었다 | 위키는 사람이 읽으라고 만든 것이다. 이제는 AI 에이전트가 직접 찾아 읽고, 결과를 다시 쌓는다 |
| 에이전트는 기억이 짧다 | 한 번에 볼 수 있는 양(컨텍스트)이 정해져 있어, 매번 필요한 것만 정확히 꺼내 와야 한다 |
| 환각의 진짜 원인은 모델이 아니라 지식이다 | 낡고 흩어진 자료를 주면, 아무리 좋은 모델도 틀린 답을 만든다 |

오른쪽 박스는 시장 지표다. Gartner가 "AI에 맞게 준비되지 않은 데이터" 위에 세운 AI 프로젝트의 60%가 2026년까지 폐기될 것으로 전망한다는 내용이고, 출처는 Gartner "Lack of AI-Ready Data Puts AI Projects at Risk" (2025)와 GenAI PoC 30% 포기 예측 (Gartner, 2024) 두 건으로 적혀 있다.

2장은 벡터 검색의 약점 2가지를 나란히 놓는다. 표제는 "벡터 검색은 강력한 도구지, 유일한 도구가 아닙니다"이고, 도입 문장은 "벡터 검색은 비슷한 느낌으로 찾습니다. 훌륭하지만, 그게 전부면 두 가지가 깨집니다"다.

| 문제 | 슬라이드 설명 | 도식 |
|---|---|---|
| 문맥이 잘린다 | 긴 글을 토막 내면, 그 토막의 앞뒤 맥락이 사라져 엉뚱하게 해석된다 | 긴 문서에서 한 조각을 떼어내며 앞뒤 맥락이 사라지는 그림 |
| 임베딩에 의존한다 | 임베딩이 비슷하다고 안 보면, 글자가 정확히 맞아도 검색에서 빠진다 | 검색어 주변 임베딩 군집 밖에 놓인 정확 일치 항목 그림 |

결론 띠는 "그래서 AKB는 회사의 지식을 단 하나의 검색 방식에 의존하지 않습니다"다.

### 3.2 다중 경로 탐색

| 경로 | 슬라이드 설명 |
|---|---|
| 트리 탐색 L0에서 L2까지 | 요약만 보고 필요한 곳만 펼치기 |
| 하이브리드 검색 | 의미(임베딩)와 키워드(BM25)를 합치고 reranking으로 다시 정렬 |
| 정확 검색 grep | 코드, URL, 버전번호처럼 글자 그대로 (정규식) |
| 그래프 탐색 | 문서 간 관계, 인용, 의존 따라가기 |

왼쪽 에이전트 상자의 부제는 "필요한 길을 직접 고른다"이고, 오른쪽 코퍼스 상자의 부제는 "문서, 표, 파일을 헤딩 단위로 완결"이다. 상자 안에 `akb://` 한 주소가 배지로 붙어 있다. 국문 검색에 형태소 분석기 Kiwi를 쓴다는 문장은 이 슬라이드에만 나오고, Kiwi를 어느 단계에 붙였는지는 밝히지 않는다.

### 3.3 트리 탐색 3단계

7쪽 표제는 "전부 읽지 않습니다. 요약을 따라 좁혀 들어갑니다"다. 단계마다 MCP tool 이름과 도서관 비유가 오른쪽에 짝지어져 있다.

| 레벨 | 슬라이드 제목 | tool | 비유 | 무엇을 보는가 |
|---|---|---|---|---|
| L0 | Vault, 어떤 금고가 있나 | `akb_list_vaults` | 서가 | 제품, 사업, 운영 등 주제별 vault 목록을 훑어 어디로 갈지 정한다 |
| L1 | Browse, 그 안에 무엇이 있나 | `akb_browse` | 책장의 책 목록 | 컬렉션과 문서의 요약(frontmatter)만 펼쳐, 본문을 열기 전에 후보를 추린다 |
| L2 | Drill-down, 문서의 어느 대목인가 | `akb_drill_down` | 목차와 페이지 | 문서의 헤딩(섹션) 단위로 필요한 부분만 정확히 펼친다 |

하단 요약 띠는 "도서관에 비유하면 서가(L0), 책장의 책 목록(L1), 책의 목차와 페이지(L2). 책장을 통째로 복사하지 않고, 필요한 페이지만 펼치니 빠르고 정확합니다"다.

### 3.4 콘텐츠 모달리티

8쪽 표제는 "찾기를 넘어 일하기까지"이고, 도입 문장은 "같은 검색 한 번이 문서, 표, 파일을 모두 커버합니다. 통일된 주소 아래 묶여 있기 때문입니다"다.

| 모달리티 | 카드 제목 | 슬라이드 설명 |
|---|---|---|
| 문서 | 지식 본문 | 헤딩 단위 마크다운. 버전과 이력까지 보존되는 회사의 글 |
| 파일 (S3) | 에이전트가 직접 주고받는 파일 | PDF, 이미지 같은 원본 파일을 에이전트가 직접 받아오고 저장한다 |
| 테이블 + SQL | 숫자로 분석 | 구조화된 표에 SQL로 통계와 집계까지. 권한 안에서만 안전하게 |

하단 예시는 한 에이전트가 한 자리에서 "이 PDF 받아와서, 표로 정리하고, 합계를 내줘"를 처리하는 흐름이다. 파일(PDF 받기), 테이블(표로 정리), SQL(합계와 집계), 결과(근거 있는 답) 4단계 상자가 화살표로 이어진다.

### 3.5 이력과 보안

9쪽은 두 개의 카드와 그 아래 요소 배지로 구성된다. 표제는 "믿고 맡기려면, 이력과 보안이 함께 가야 합니다"다.

| 카드 | 제목 | 내용 |
|---|---|---|
| 이력 추적 | 모든 변경이 기록됩니다 | 문서는 Git에 커밋되어 과거 어느 시점이든 되돌려 볼 수 있다. 문서가 바뀌면 검색 인덱스도 같이 갱신돼 낡은 색인이 옛 답을 주는 일이 없다 |
| 권한, 격리, 감사 | 볼 수 있는 사람만 봅니다 | vault마다 권한을 부여한다. 데이터베이스 자체에서 격리되어 권한 없는 vault는 우회 질의(SQL)로도 보이지 않는다. 모든 접근은 감사 로그에 남는다 |

카드 아래 배지 5개는 버전 이력 (Git), 문서와 인덱스 동기화, Vault 권한 (RBAC), DB 네이티브 격리, 전수 감사 로그다.

### 3.8 실시간 지식 흐름

19쪽은 업무 시스템에서 활용처까지의 경로를 한 장에 그린다. 도입 문장은 "사내에 매일 쌓이는 대화, 이슈, 변경 이력, 고객 반응, 운영 로그는 단순 기록이 아니라 AI 에이전트가 다시 활용해야 할 업무 자산입니다"다.

왼쪽 유입 소스는 Slack, Jira, Confluence, GitHub, CRM/VOC, Product Log 6개이고, 그 아래에 "대화, 이슈, 문서, 코드 변경, 고객 문의, 사용 기록"이 캡션으로 붙는다. 가운데 지식화 엔진 상자에는 Collector와 Gardener가 부제로, 수집 / 권한과 출처 / 시간과 맥락 / 정제와 구조화 4개 배지가 본문으로 들어간다. 상자 설명은 "에이전트가 이해하고 활용할 수 있는 지식 단위로 정리"다.

| 활용처 | 슬라이드 설명 |
|---|---|
| 고객 문의 대응 | 관련 이력과 규정 기반 응답 지원 |
| 장애 원인 탐색 | 변경 이력과 운영 로그 교차 확인 |
| RFP, 정책, 업무 자동화 | 검색, 판단, 실행을 연결하는 업무 지원 |

도식 아래 결론 문장은 "AKB는 로그를 저장하는 곳이 아니라, 에이전트가 적재적소에 꺼내 쓰는 실시간 업무 지식 기반입니다"다.

### 3.9 보안 지식 허브

20쪽 표제는 "모든 보안 정보를 AI 활용 가능한 지식으로 전환합니다"다. 가운데 원이 AKB 보안 지식 허브이고, 원 둘레에 로그 소스 8종이 배치된다. FW, Server, DDoS, IDS/IPS, NAC, VPN, AV, WAF다.

허브가 수행하는 기능은 좌우 두 상자에 14개가 나뉘어 있다.

| 왼쪽 상자 | 오른쪽 상자 |
|---|---|
| Log Collection | Real-time Alerting |
| Log Analysis | User Activity Monitoring |
| Event Correlation | Dashboards |
| Log Forensics | Reporting |
| IT Compliance | File Integrity Monitoring |
| Application Log Monitoring | System & Device Log Monitoring |
| Object Access Auditing | Log Retention |

하단 띠는 "다양한 보안시스템과 내부 자산들의 모든 로그를 수집하고 분석하여 위협상황의 실시간 식별 및 사후 분석을 위한 보안 관리 향상"이고, 그 아래 화살표 4개가 기대 효과를 나열한다. 실시간 위협 가시성, 원인 분석 및 조사, 대응 자동화 지원, 감사와 컴플라이언스 강화다.

### 3.10 XDR 4단계

21쪽 표제는 "로그 수집을 넘어, 탐지와 조사, 대응까지 AI가 연결합니다"다. 4개 카드가 가로로 놓이고 각 카드에 영문 이름과 한글 이름이 함께 적혀 있다.

| 단계 | 한글 이름 | 세부 항목 |
|---|---|---|
| eXtended | 확장 수집 | EDR, NDR 등 다양한 이벤트와 로그 수집 / 침입탐지와 방지 이벤트, 내부정보 유출 이벤트, 애플리케이션 로그, 서버 로그 등 / 네트워크 패킷, 엔드포인트 정보 / 클라우드 기반 수집 정보 / IoT, OT 수집 정보 |
| Detection | 위험 탐지 | 다양한 분석 기법 적용 / 단일 분석과 상관 분석, 계정 및 정책 위반 등 다양한 분석 기법 / 공격자 중심과 결과 중심 분석 |
| Investigation | 원인 조사 | 위협 분류별, CTI 등 지표 기반 조사 / 주요 자산 기준 공격자 상위 위험 조사 / 지표, 위험 가설, 사용자 정의 기반 위협 헌팅 / 위협 헌팅 기반 패턴 인지 기술 적용 |
| Response | 대응 실행 | Playbook 자동 실행, 다양한 보안 대응 절차 지원 / 다양한 제품과 데이터 연동, 글로벌 위협 정보 연동 / 공격위협의 자동, 수동 분석 및 대응 / 위험 중심의 분석 및 대응 프로세스 가시화 |

4개 카드 아래에 "확장형 탐지 조사 대응"이라는 띠가 가로지르고, 그 밑에 "플랫폼 및 UI 통합을 통해, 포괄적 관점에서 보안 운영 편의성 향상"이 붙는다.

슬라이드 맨 아래에 사용자와 AI Agent의 대화 예시가 말풍선으로 들어간다.

- 사용자: "의심스러운 VPN 로그인 실패를 분석해줘."
- AI Agent: "최근 24시간 동안 반복된 로그인 실패와 비정상 접근 패턴이 탐지되었습니다. EDR, VPN, NAC 로그를 상관 분석한 결과 계정 탈취 가능성이 있습니다."

### 3.11 지식 생애주기

22쪽이 자료 전체를 한 장으로 요약한다. 표제는 "정보가 들어오고, 정제되고, 쓰이고, 폐기되는 지식의 생애주기 전체"다.

| 단계 | 한 단어 | 슬라이드 설명 |
|---|---|---|
| 유입, COLLECTOR | 흘러든다 | Confluence, Jira, Slack, GitHub의 정보가 AKB로 자동 유입 |
| 정제, GARDENER | 다듬는다 | 원석을 보석으로. 중복과 낡은 건 솎아내고, 출처를 단다 |
| 활용, AKB | 쓰인다 | 에이전트와 사람이 여러 경로로 찾아 생산하고 소비한다 |
| 폐기, HITL | 보내준다 | 수명을 다한 지식은 사람 승인 후 정리(archive) |

가운데 문장은 "이 모든 흐름은 명확한 보안 경계 위에서 작동합니다"이고, 아래 띠에 보안 경계 4가지가 아이콘과 함께 놓인다.

| 경계 | 설명 |
|---|---|

## 4. 주요 결과와 벤치마크 (Key Results and Benchmarks)

### 4.1 21일 무인 자동 운영 실측

| 지표 | 값 | 슬라이드 부기 |
|---|---:|---|
| 무인 자동 운영 기간 | 21일 | 2026-05-15 ~ 06-05 |
| 정제 대상 Slack 채널 | 6개 | 누적 메시지 정제 |
| 누적 메시지 정제 | 2,500개 이상 | 6개 Slack 채널의 누적 메시지 |
| 분류 정확도 | 100% | 수동 검증 22건 |
| 민감정보 노출 | 0건 | redaction 누락 |
| 3주 전체 운영 비용 | 약 $10 | 사람 손이 거의 들지 않았다 |

유연성 항목이 비용 옆에 함께 놓인다. "정책 자체가 문서로 저장돼, 코드 재배포 없이 문장 한 줄 수정으로 동작을 바꿉니다." 정책을 코드가 아니라 문서로 두었다는 설계를 운영 이점으로 제시한 것이다.

### 4.2 운영 규모

- 1차 검증 기준 12명, vault 9개 (16쪽 각주)
- 사내 온프렘 환경에서 실제 운영 중이라고 14쪽과 15쪽에 명시

### 4.3 Slack 대화에서 정책 문서로

18쪽이 21일 실증의 결과물 하나를 구체 사례로 보여준다. 표제는 "어제의 슬랙 잡담이, 내일 검색되는 회사 규칙이 됩니다"이고, 도입 문장에 "21일간 6개 Slack 채널의 2,500개 이상 메시지를 자동 수집하고 정리해, 검색 가능한 지식으로 전환한 검증 결과입니다"가 붙는다.

왼쪽 원본은 사내 #개발 채널, 2026-05의 대화 3건이다.

- 김PM: "보험 PoC는 야탑 온프렘으로 가는 걸로 정리됐어요"
- 이엔지: "넵, 외부 반출은 전면 금지로 가이드에 박을게요"
- 박: "민감정보 가림(redaction) 규칙도 같이 정리 부탁요"

가운데는 수집(Collector)과 정제(Gardener) 두 상자다. 오른쪽 결과물은 제목이 "야탑 온프렘 배포, 데이터 반출 정책"인 문서이고, 문서 하단에 "출처: 사내 #개발 채널, 2026-05"가 자동으로 붙어 있다.

### 4.4 시장 근거로 인용한 수치

- 60%: Gartner는 "AI에 맞게 준비되지 않은 데이터" 위에 세운 AI 프로젝트의 60%가 2026년까지 폐기될 것으로 전망한다
- 출처 표기: Gartner "Lack of AI-Ready Data Puts AI Projects at Risk" (2025), GenAI PoC 30% 포기 예측 (Gartner, 2024)

이 수치는 자료가 직접 측정한 값이 아니라 포지셔닝 근거로 끌어온 외부 인용이다.

## 5. 한계와 향후 과제 (Limitations and Future Work)

### 5.1 자료 자체의 한계

- 제품 소개 자료다. 1차 자체 검증 외에 외부 비교나 공개 벤치마크가 없다
- 21일 실증의 외부 검증이 없다. 사내 환경에서 자체 수동 검증 22건만 공개되고, 분류 정확도 100%의 신뢰구간이나 n이 22라는 표본 크기의 통계적 한계는 언급하지 않는다
- 검증 규모가 12명, vault 9개다. 수백에서 수천 사용자 규모의 검증은 공개되지 않았다
- redaction 누락 0건의 측정 방식이 모호하다. 놓친 민감정보가 없다는 재현율 측정인지, 잡아낸 것 중 오탐이 없다는 정밀도 측정인지 자료에서 구분이 없다
- 3장 제목과 22쪽이 탐색 경로를 다섯 가지로 적지만 6쪽 도식은 네 가지만 나열한다. 다섯 번째가 무엇인지 자료 어디에도 나오지 않는다
- 오탈자가 여러 곳에 있다. 4쪽 "안 보변", 8쪽 "SGL", 12쪽 "구조회해", 15쪽 "관라하고", 17쪽 "Valut", 19쪽 "ABK"

### 5.2 공개되지 않은 구현 세부

| 영역 | 자료에 없는 것 |
|---|---|
| Collector | 6개 소스 connector의 구현 깊이, hash 비교 단위, redaction 엔진의 종류 |
| Gardener | LLM과 규칙의 비율, 4단계 요약에 쓰는 지시문과 모델 |
| Propose, Approve, Execute | 승인 화면 구성, 승인자 식별 방식, 충돌 해소 정책 |
| Kiwi | 형태소 분석기를 키워드 검색 단계에 붙였는지 질의 재작성 단계에 붙였는지 |
| XDR | 라이선스와 배포 모델, 가격 |
| 데이터베이스 격리 | 어떤 데이터베이스 기능으로 격리했는지. 자료는 "데이터베이스 자체에서 격리"라고만 적는다 |

### 5.3 추적할 지점

- Collector와 Gardener의 별도 제품화 시점과 라이선스
- 21일 자체 검증이 외부 고객 사례로 이어지는지
- XDR 적용 영역의 실제 도입 사례
- 9개 vault 패턴이 다른 규모의 조직에서 재현되는지

## 7. 용어집 (Glossary)

- AKB: Agent Knowledge Base. Dnotitia의 에이전트용 조직 지식베이스
- AKB Collector: 외부 소스 6종을 AKB로 자동 동기화하는 컴포넌트. hash 비교, 원본 링크 보존, 유입 단계 redaction 3원칙
- AKB Gardener: Bronze 상태의 수집물을 Gold로 정제하는 컴포넌트. 다듬기, 솎아내기, 출처 달기, 눈높이 요약 4가지 작업
- Bronze와 Gold: 자료가 원석과 보석으로 옮겨 쓰는 정제 단계 이름. Bronze는 Collector 직후, Gold는 Gardener 정제 후를 가리킨다
- HITL: Human In The Loop. Gardener의 파괴적 작업 앞에 사람 승인을 두는 안전장치
- Propose, Approve, Execute: Gardener의 3단계 작업 흐름. Gardener가 제안하고, 사람이 승인하고, Gardener가 승인분만 실행한다
- vault: 권한과 격리의 단위. 자료는 "금고"로 옮겨 부른다
- L0, L1, L2: 트리 탐색의 깊이. vault 목록, 컬렉션과 문서 요약, 문서 헤딩 순이다
- `akb_list_vaults`, `akb_browse`, `akb_drill_down`: L0, L1, L2 각 단계에 대응하는 MCP tool 이름
- `akb://`: 문서와 표, 파일을 하나로 묶는 주소 체계. 자료는 이를 "하나의 URI 코퍼스"로 부른다
- Kiwi: 국문 검색 정확도를 높이는 데 쓴다고 밝힌 형태소 분석기
- SOTA: 자료가 각주에서 "현재 시점의 최적 탐색 접근"으로 풀어 쓴 약어
- XDR: eXtended, Detection, Investigation, Response. 보안 로그를 통합해 탐지, 조사, 대응까지 잇는 운영 모델
- redaction: 민감정보 가림 처리. Collector의 유입 단계에서 적용한다
- 온프렘: 사내 자체 서버 환경. 자료는 한 바이트도 외부 반출이 없다고 명시한다
